## 3. 転移・持ち込み系の検証（H-03・H-05・H-30）

転移骨格・転移持ち込み可否・転移演出の 3 項目。ゴミ箱転移は「自分も棄てられるものだから国へ行ける」という理屈の物理実装（docs/23 §5.1）であり、往復路の実用性（荷物持ち込み可——docs/23 §5.1・§12 D2）と発見型片道入口（異物経由——docs/32 §4.2）の対比が正典の柱。全検証に横断する成立条件は **「帰れない状態を作らない」**（docs/32 §2.2・docs/23 §5.1③ の村共同箱フォールバック）である。

---

### H-03 転移骨格（デカいゴミ箱往復＋異物経由の片道入口——入口2系統）

- **実現性評価**：**高**。`Entity#changeDimension(DimensionTransition)` と `Portal`/`PortalProcessor` で転移時間・遷移先・発火条件（`canUsePortal`/`canChangeDimensions`）を制御できる（docs/56 §1.3——1.21 で刷新された転移 API の実在確認済み）。ブロック/アイテム起点の次元遷移は黄昏の森の儀式ポータル（花で囲んだ水窪にダイヤ投下→雷→転移）に先行実績がある（docs/02 §1——ただし本調査では物品投下の発火儀式の先例に留まり、実装細目は docs/56 §1 に未収録のため補助的根拠として扱う。API 実在性の主根拠は docs/56 §1.3）。
- **検証内容**：入口は **2 系統**（横断監査指摘への対応——棚卸しの先行ゲート項「異物経由の分岐」を本カードへ取り込む）：
  - **系統A デカいゴミ箱往復路**：デカいゴミ箱（L2——ゴミ箱 8 個のクラフト・レシピは招待状として届く——docs/23 §5.0・§8.1）に自分で入る→蓋閉→暗転→国へ転移し、国側にその箱の「こちら側の口」が着弾点に出現する往復路の骨格 PoC。正典の口運用定義 3 件（docs/23 §5.1）：①国側の口は回収・持ち運び可だが拾い上げ/破壊/持ち去りで閉じる（閉じても村の共同箱フォールバックが残る）②口は現実側の箱と 1 対 1 紐付き、自分の捨て場既生成時は着弾点＝捨て場（複数口が同場所に並びうる）③現実側の箱の消失・破壊でその口は不通→帰還は村の共同箱へ。
  - **系統B 異物経由の片道入口**：異物への欠損接触→「世界が壊れる」演出→次元へ落ちる→漂着浜着弾→**招待状不届フラグ＋ノミが漂着浜でレシピを直接渡す先行訪問分岐**（docs/32 §3.2・docs/11 §4・docs/40 §2.1/§2.7——蓋系列を持たない入口であり、転移演出は H-30・持ち込み不安定は H-05 T-U2-06e・生成/視認は H-02/H-06 と接続）。欠損接触→転移発火→着弾先選択→先行訪問分岐フラグの一連を作り・測る。
- **合格ライン**：往復 2 経路（自分の箱↔自分の捨て場/漂着浜・他人の箱→他人の捨て場）＋フォールバック（村共同箱）が全ケースで成立し「帰れない状態」の再現 0 件（docs/32 §2.2・docs/40 T-2 ラインと接続）。口の閉塞は一方向伝播（現実箱喪失→国側口「不通」化）で、どの閉塞経路でもフォールバックが残る。死亡リスポーンは下記 4 セルの期待値どおり。他者押し込みによる転移発火 0 件（否定確認）。
- **設計代替**：不要——成立しないと主題装置が潰れる（docs/40 §4.9 転移骨格行「設計代替：なし——最優先」）。
- **依存・前提**：docs/23 §5.0-5.1（招待状ゲート・両側口 3 運用定義）・§8.5/§9（デカいゴミ箱は「自分で入る」動作のみ・他者押し込み不可）・docs/32 §2.2（リスポーン優先順位 3 点＋帰れない原則）・§3.2（異物経由先行訪問の分岐：招待状不届＋ノミが漂着浜でレシピ直接渡し）・docs/40 §4.9 転移骨格行（先行ゲート）・H-15（個別層データ構造——所有者紐付・捨て場状態の保存先）。
- **Phase 1 タスク化**：
  - **T-U2-05a 初期遷移**：自分のデカいゴミ箱に入る→蓋閉→暗転→国の捨て場（未生成なら漂着浜）に出現＋国側の口の生成。
  - **T-U2-05b 国側の口**：出現位置（捨て場既生成時は捨て場着弾——§5.1②）・現実箱との 1 対 1 紐付・帰還で元の現実箱へ戻れる往復完結。
  - **T-U2-05c 複数口同居**：複数回転移で同一捨て場に複数の口が並ぶ状態の成立確認（§5.1② 後段）。
  - **T-U2-05d 他人の箱→他人の捨て場**：他人のゴミ箱に自分で入ると他人の捨て場へ落ちる（docs/23 §5.1「面白い事故」）。
  - **T-U2-05e 死亡×転移交差**：国での死亡→リスポーン優先順位どおりの出現。**4 セル（自分の捨て場生成有無×村成立有無）を全件試行し、期待出現先を下表のとおり明記する**（docs/32 §2.2 の厳格解釈）：

    | 自分の捨て場 | 村（拾い人の村）成立 | 期待出現先（厳格解釈） |
    |---|---|---|
    | 生成済み | 成立 | **自分の捨て場**（①） |
    | 生成済み | 未成立 | **自分の捨て場**（①） |
    | 未生成 | 成立 | **漂着浜の共同堆積**（②——③村は②が常時成立するため厳格適用では実質到達不能。docs/40 §4.2 も「自分の捨て場→漂着浜の共同堆積→村の3点を据える」と同順位を確認しており、設計意図が「村成立時は村優先」なら正典側の疑義として **57-U2-Q7** で承認を仰ぐ。承認次第で本セルの期待値は「村」に変わる） |
    | 未生成 | 未成立 | **漂着浜の共同堆積**（②） |
  - **T-U2-05f 他者押し込みの拒否**：他人をデカいゴミ箱へ押し込んでも転移しない（発火＝被転移者自身の「自分で入る」動作のみ——docs/23 §8.5・§9）。ピストン・水流・落下強制等の外部力による進入形態でも発火しないことを否定確認。
  - **T-U2-05g 口の閉塞ライフサイクル**：口の状態遷移＝**開通**（現実箱と 1 対 1 紐付・着弾点に出現・帰還口として機能）→**閉塞**（拾い上げ/破壊/持ち去りのいずれかでその口は閉じる——回収・持ち運びは可）→**不通**（現実側箱の消失・破壊で帰還口として不通）。3 経路それぞれで「閉じた/不通になった口でも村の共同箱フォールバックが必ず残る」ことを確認：(a) 現実側箱の破壊・消失→国側口「不通」化→村共同箱で帰還｜(b) 国側口の拾い上げ→閉塞→村共同箱フォールバック｜(c) 国側口の持ち去り（運搬中の帰還要求）→閉塞→同上。
  - **T-U2-05h 異物経由片道の端到端**（横断監査指摘への対応）：欠損接触（異物への接触/操作）→転移発火（DimensionTransition——`canUsePortal`/`canChangeDimensions` による条件付け）→国へ落ちる→**漂着浜着弾**（着弾先選択＝捨て場未生成・招待状未着ゆえ共同堆積/浜側の定着点）→**招待状不届フラグ**（経路B 利用者には招待状が届かない——docs/32 §3.2）→**ノミが漂着浜でレシピを直接渡す**先行訪問分岐の成立確認。異物は利用後も残存・再入可能（16-U1-Q14——個別層前提の条件化は 57-U2-Q11 連動）。
  - **スライス外**：国側の口の「回収した後の口の扱い」（回収済み口の残骸表示・修復可否——現行正典は単純に閉じる）等はスライス外メモとして Issue #16 側台帳へ。
- **想定リスク/工数**：**中**——口の紐付管理と閉塞伝播のエッジケースが細かい。実装パスは確立済みのため不確実性は低い。工数目安 3-4d。

### H-05 転移持ち込み可否（インベントリフィルタ）

- **実現性評価**：**高**。転移時のインベントリ走査と禁止品フィルタは `PostDimensionTransition` コールバックまたは専用フックに実装可能（docs/56 §1.3「持ち込み可否の制御＝転移時にインベントリ走査して禁止品を弾くフィルタ」）。`net.minecraft.core.component.DataComponents.CONTAINER`（mojmap 定数名——`ItemContainerContents` を保持するコンポーネント）を読めばシュルカー・梱包器の入れ子中身も判定できる。なお docs/56 §1.4 が確認済みなのは DataComponent 機構一般であり、CONTAINER の定数名は同節に未記載——**mojmap 上の定数名として独立に記す**（P-TV-03 準拠）。入れ子インベントリは再帰探索で網羅可能。
- **検証内容**：ゴミ箱転移（往復両方向）と異物経由片道の持ち込み可否の制御。正典：**往路＝全持ち込み可**（docs/23 §12 D2 確定値「実用往復路の差別化。喪失リスクは死亡/没腐側に残す」＋§5.1「荷物：持ち込み可」）。**復路＝持ち帰り分類どおり**（docs/32 §1.2——拾得物・携行品の収め物は可／汎用建材・大量資源・生き物・住人・没腐汚染物は不可／N-ITEM-027 例外＝拾い直し完了〔使用済み〕品のみ持ち出し可——U1 #5 承認）。
- **合格ライン**：往路＝全持ち物が届く・復路＝分類表どおりに不可区分が国側へ残る・死亡時喪失（未登録拾得物 25%・最大 8 個・没腐遺留物化）と回収可能性が docs/32 §2.1 どおり。正典未定義の 3 項目（死亡×転移交差の残置物行き先・緊急脱出ハッチ化の抑止要否・異物経由の不安定度値）は合格不能項として **57-U2-Q3/Q4/Q2 に分離**——承認値確定後に合否を確定する。
- **設計代替**：持ち込み制限そのものが実装不能な場合の正典代替＝「持ち込み制限を撤廃して設計側で調整」（docs/00 §3.1⑤ 拡張検証項目表）。往路の一部制限は D2 確定値を壊すため代替として扱わない。**復路拒否品（不可区分品を携行して復路に入った場合の残置物）の滞留形式と、持ち帰り分類（docs/32 §1.2）が適用例外にならない範囲は一体の決定点として 57-U2-Q5 に集約する**（選択肢：(i) 口内に残留し現実側箱へ戻る／(ii) 国側に取り残される）。
- **依存・前提**：docs/23 §5.0-5.1（招待状ゲート・荷物持ち込み可・口運用定義）・§8.4-8.5（クレーン処理での強制転移＝他人を捨てる唯一系・埋立て地行き）・§12 D2/E2・docs/32 §1.2-1.3（持ち帰り/持ち込み分類）・§2.1-2.2（死亡喪失・リスポーン）・§4.2（異物経由＝片道・持ち込み不安定）・docs/40 §4.9 転移持ち込み行（先行ゲート——「持ち込み可否・死亡時挙動・緊急脱出化の防止」）・H-03（転移骨格成立が前提）。
- **Phase 1 タスク化**：
  - **T-U2-06a 往路全許可**：装備品・バインド呪い付き装備を含め全持ち物が国へ届く（docs/23 §12 D2）＋二度棄て用ゴミ箱・梱包用器の持ち込み（docs/32 §1.3 注記——「入れると届く」ので実質「持ち込み＝捨てる準備」）。

  - **T-U2-06e 異物経由片道の持ち込み不安定**：ゴミ箱経路＝全許可（docs/32 §1.3・docs/23 §12 D2）に対し、異物経由は「片道・持ち込み不安定——装備の一部が届かない等の緊張感」（docs/32 §4.2・docs/23 §5.1 の対比設計）を成立させる。**不安定度の実装値（何がどの率で届かないか）は正典未定義 → 57-U2-Q2**。

  - **T-U2-06g 復路拒否品の残置**：不可区分品を携行して復路に入った場合、その品は転移先で受け取れない——残置形式（口内残留→現実箱へ戻る／国側取り残し）と適用範囲 → **57-U2-Q5**。
- **想定リスク/工数**：**中**——入れ子インベントリ・他 MOD 追加スロット・呪い装備など判定網羅の漏れリスク。工数目安 3-5d。
