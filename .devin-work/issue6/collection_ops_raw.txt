    section_md: ## 3. 回収設計

### 3.0 本節の範囲と原則の適用

本節は回収物3点セット（録画・イベントログ・聴取）の**運用形**を定める（H-05 の回収側・H-06・H-07・H-08）。実施形の選定（リモート観察／非同期録画回収／Discord 中継）自体は §1（H-01・H-05 前半）に委ね、本節は「どの実施形でも3点が揃い、揃ったものが判定に使える状態」を設計する。

docs/58 §3 の設計原則を本節へは以下の形で落とす：

| 原則 | 本節での適用 |
|---|---|
| P-PT-01（測れるものはログで測る） | §3.2 で記録イベント一覧を定義し、40-Q7 の定量ライン9件をすべてログに割当てる（§3.2-3）。聴取は「なぜ」の解明とログの裏付けに限定（§3.4） |
| P-PT-02（説明なし鉄則） | 観察者の介入は `observer.intervention` イベントとして記録し、介入時点以降の当該テスターの E 系観測値は母集団から除外して別集計（§3.1 介入の記録運用） |
| P-PT-03（失敗も情報） | 離脱・迷子・気づかなかったモーメントもログ・録画で欠かさず回収する充足条件を定める（§3.1 の充足条件表） |
| P-PT-04（定点聴取は4定点） | 転移直後・ボス撃破後・結末後・終了時の4定点＋自由記述（§3.3） |
| P-PT-05（分母明記） | 全検証項目の分母を §4 カードに明記。ログは分母判定用イベント（`invite.fired`・`discard.generated`・`moment.fired` 等）を必須とする（§3.2-2） |
| P-PT-06（判定を先に書く） | 合格ラインは docs/40 §5.2 を引用のみで据え、「何をもって測定と見なすか」の運用定義を本節・§4 で事前に固定する |
| P-PT-07（配信者は別分母） | 定点アンケート・終了後聴取は L2 専用。L3 には適用しない（§5 側で別設計） |
| P-PT-08（テスター負荷） | 聴取の合計負荷を設計値として見積もり §3.5 に記す（募集条件への反映は §2 側） |

加えて docs/58 §1 の調査基準を直接適用する点：行動法（ログ・録画）と経験法（聴取）の併用（§1.1）／「評価してから理由」＋7件法＋逆得点項目＋「やめたい点」検出（§1.4）／イベント駆動ロギングとテスターID・ビルド・シード紐付け（§1.3）／定点は瞬間の記憶が残るうちに置く（§1.4・P-PT-04）。

### 3.1 回収物3点セットの運用形（H-05 回収側）

全 L2 セッションで以下の3点を揃えて回収する。**3点のいずれかが欠けたセッションは「充足条件未達」として記録**し、判定には充足したデータのみを用いる（欠損時の再実施規則は要承認 41-U2-Q6 参照）。

| 回収物 | 内容 | 形態 | 命名・紐付け | 充足条件（これを満たさない記録は判定に使えない） |
|---|---|---|---|---|
| **録画** | ゲーム画面の通し録画。Discord 画面共有での観察時も観察者側で録画を残すか、テスター側ローカル録画を回収する。音声はテスターの独り言・環境音を含めて録る（思考の声出しは求めない——無言プレイの自然さを優先） | mp4 等、解像度・フォーマット不問（内容が判読できれば可） | `{tester_id}_{session_id}.mp4` | **現実側セッション開始（OP）〜帰還（または離脱点）まで切れ目なく**記録されていること。OP 区間（招待状受領→デカいゴミ箱作成→転移）は説明なし進行が最初に問われる検証区間であり（E-1 の正典チェーンは「OP→第1章クリア→村→帰還」——docs/40 §5.2.1）、M-OP1（返礼の気づき）・M-OP2（転移「壊れる」）の切り抜き素材根拠にもなるため欠かせない（docs/40 §1.3・S-1）。**非同期録画形で OP 開始が未録の場合も充足未達**とし、後続区間のみの録画を充足と見なさない。画面が読める画質。音声欠如は許容するがその場合は「音声なし」タグを付す |
| **イベントログ** | 計測ロガー（§3.2）が出力する JSONL。テスターはログファイルを Discord 投稿または共有フォルダで提出 | JSON Lines（1イベント1行） | `{tester_id}_{session_id}_{build}_{seed}.jsonl` | `session.meta`（ビルド・シード・コンフィグ）を先頭に持ち、`session.start` から `session.end`（または `player.quit`）まで連続したイベント列があること。**OP 区間（招待状受領〜転移前）で離脱したセッションは `session.start` 不発のまま `player.quit` で終わる列を充足とする**——OP で詰まる・離脱する証拠自体が E-1 判定と離脱リスク地図の入力になるため（docs/40 §5.2.1 E-1） |
| **聴取** | 定点アンケート回答（F1〜F4）＋終了後構造化インタビュー＋自由記述（§3.3〜§3.4） | フォーム回答データ＋インタビュー文字起こし/録音 | 回答は `tester_id` 入力で紐付け。文字起こしは `{tester_id}_{session_id}_interview.md` | F1〜F4 全定点の回答と、インタビューの主要項目（§3.4 の A〜D 群）への回答があること |

**紐付け規則**（§1.3・H-06）——3点セットを同一キーで束ねる：

- `tester_id`：T01〜T08 の匿名 ID（§2 のスクリーニング時に払い出し。ログ・録画・聴取の全媒体で本名・Discord アカウントを使わない）
- `session_id`：テスター×実施回の連番（`T03-S2` 形式。再実施・追跡セッションを区別する）
- `build`：検証ビルドの識別子（リリースタグまたは commit SHA。ログの `session.meta` に自動記入）
- `seed`：ワールドシード値（同じく `session.meta` に自動記入）
- 対応表（tester_id ↔ Discord アカウント ↔ 実施日時 ↔ 環境メモ）は §2 側が管理する。本節は「全回収物に tester_id・session_id・build・seed が刻まれていること」を充足条件として要求するに留める

**介入の記録運用**（P-PT-02）——観察者が口出し・ヒント・操作代行を行った時点で `observer.intervention` イベントを手動発火させる（非同期録画形では事後に録画タイムスタンプへ記録）。介入時点以降の当該テスターの E 系観測値（E-1・E-3・E-5・E-9 等「説明なし」を前提とする全項目、および E-2 所要時間）は**「介入あり」タグを付けて分母から除外し別集計**する。介入前のデータは有効。T/A 系（L1 内部実施）には本規則を適用しない。

**「やめたい点」の記録**——離脱・停止は `player.quit` で検出し、定点アンケートの「やめたい点」回答（§3.3）と突合して離脱リスク地図（場所×人数）の材料とする（集計規則は §7 側）。

### 3.2 イベントログ設計（H-06）

#### 3.2-1 前提：計測ロガー

ログ計測は 40-Q7②「イベントログ計測」を正典前提とするが、その**実装経路は未定のため要承認 41-U2-Q3** とする。推奨は「検証ビルド限定のサーバー側計測ロガー（JSONL 出力・config で本番無効化・本番配布ビルドから除外可能な分離構成）」を Phase 1 タスクとして設計対象に含めること。以下の設計は同ロガーの存在を前提とする。

**フォーマット**：JSON Lines。全イベントに共通フィールドを持つ：

| フィールド | 内容 |
|---|---|
| `ts` | 発火時刻。サーバー tick と実時間 ms の双方（T-7 の ±100ms 同期測定のため実時間 ms は必須） |
| `event` | イベント名（ドット区切り、3.2-2 の一覧どおり） |
| `tester_id` / `session_id` / `build` / `seed` | 紐付けキー（§3.1）。`session.meta` で宣言後は全行に `tester_id`・`session_id` を付す。L1 の計測セッションでも同形式で記録し、`tester_id` は L1 識別子（`L1-a` 等）を用いる |
| `dim` | 現実 / 国 |
| `pos` | 発火座標（区画判定用に丸め値でも可） |
| `layer` | 個別層 / 共有層（該当するイベントのみ） |
| `data` | イベント固有フィールド（3.2-2 の「主要フィールド」列） |

#### 3.2-2 記録イベント一覧

**A. セッション・進行系**

| イベント名 | 発火点 | 主要フィールド | 対応検証 |
|---|---|---|---|
| `session.meta` | セッション開始時（ヘッダ相当・1行目） | tester_id・session_id・build・seed・config 一式・shader 状態 | 全項目（環境紐付け） |
| `session.start` | 国側への初到達確定（着弾——経路不問：ゴミ箱転移・異物片道のいずれでも発火） | route | E-1・E-2 |
| `chapter.clear` | 第1章クリア（ボス撃破＋結末確定） | chapter | E-1・E-2 |

※**`survey.point` の発火主体と時点**：観察実施形（Discord 画面共有・同席観察）では**観察者が手動打刻**する——節目到達を検知して定型通知を送った時点を `start`、回答区間の終了を検知した時点を `end` とする（観察者の検知→通知送信までの遅延は mark=live_observer の打刻精度として許容し、補正時の系統誤差は一定方向＝回答区間を過大側に切る運用）。**非同期録画形ではセッション中に発火主体がいないため事後打刻**とし、録画上の回答区間（フォーム操作が見える区間）をログ時刻列へ転記する（mark=posthoc）。さらに**フォーム回答の送信タイムスタンプを常時併記**し、`survey.point` を打てなかったセッションではフォーム送信時刻をログ時刻列と照合して回答区間を代替推定する（mark=form_ts——E-2 の回答時間補正＝41-U2-Q5 の入力を欠損させないためのフォールバック）。

#### 3.2-3 40-Q7 定量ラインのカバレッジ確認

P-PT-01 に従い「40-Q7 の定量ラインを全部ログで賄えるか」を先に確かめ、残りを聴取へ振った結果——**全9ラインがログ主体で測定可能**（④⑤⑥のみ聴取/監査の補助を併用）。対応表：

| 40-Q7 定量ライン | ログでの賄い方 | 聴取・録画の役割 |
|---|---|---|
| ①完走時間（序+1章 1〜2h・離脱0） | `session.start`〜`chapter.clear`/`session.end` の差分・`player.quit` で離脱検出 | アンケート区間の補正（`survey.point`） |
| ②迷子（中央値≤3回/人・最終段0人・同一地点二度目＝不合格） | `navigation.lost.*` の回数・区画ID・via | 聴取で迷いの自覚と回帰手段の主観を補強 |
| ③撃破時間（中央値135〜145s±20%・試行1〜3回・予備床） | `boss.fight.*` の duration・試行回数・`boss.telegraph.shown` の発火 | 理不尽感の聴取（E-8 と共用） |
| ④発見密度（断片60〜70%/周回・欠片CP3全員・寄り道1個≥50%） | `item.pickup` の category・location_id で個人別集計。分母＝配置数（N-ECO-601/602 の設計値） | 寄り道の「意識的寄り道か」の聴取補助 |
| ⑤気づき率（各モーメント≥2/3・名付き品は由来物初投入限定） | `moment.fired`＋代理指標（`discard.first_view`/`inspect.lore`/`attack.in_window`/`choice.ending` dwell）。**分母＝各モーメントの発火点到達者**（「名付き品がここにない」のみ `invite.fired` route=named_first_insert のテスターに限定——正典注記どおり） | **主判定は終了後聴取**（§3.4 A 群）。ログは発火点通過と代理行動の裏付け |
| ⑥クリアシーケンス無欠落・導線SE全件字幕名 | `sequence.step` の全ステップ発火・`se.fired` の subtitle_shown | 録画で演出の視認確認（A-6 と連動） |
| ⑦a11y（最重要3系統・主要2系統・色のみ0件・OFF一次導線） | `config.state`（shader）＋監査用チャネル割当表（§4 A-1） | L1 監査が主体（A-1〜A-7） |
| ⑧技術（転移/環礁生成/ボスでティック落ちなし） | `perf.mspt`/`perf.gen` の局面別計測 | 閾値着地は判定運用（T-1/T-6・G-PT-11） |
| ⑨配信（配信1回=第1章クリア・切り抜き≥3） | L3 セッションの `session.start`〜`chapter.clear` 時間＋切り抜き候補モーメント（`moment.fired`） | §5 側（U3 担当）。切り抜き評価は配信観測で別設計 |

#### 3.2-4 セッション再現性（H-06）

全イベントに `build`・`seed`・`session_id` が刻まれるため、**問題発見時に L1 が同一ビルド＋同一シードでワールドを再生成して内部再生できる**ことを再現性の要件とする：

- 地形・配置（異物・断片・淀み地点）はシードで再現される。プレイヤー行動は再現されないため、内部再生は「同じ環境を観察者が検証する」用途に用いる（気づき不成立の原因が導線か個人差かを分離する等）
- 迷子・離脱の再発地点は `pos`＋区画ID で特定し、同シードで当該区画の導線設計を再検査する
- 同一シードを複数テスターで使い回す選択肢もある（環境要因と個人差を分離しやすい）が、異物生成はランダム配置のため E-9 の生成保証確認は L1 側の複数シード実施（41-U2-Q8）で担い、**L2 は各テスター新規シードを基本**とする（新規シードでの動作自体が検証対象——招待状→転移→配置の端到端がシード非依存で成立することを見る）

## 4. 検証項目の運用

### 4.0 共通規則

- **引用規則**：測定方法・合格ラインは docs/40 §5.2 を**引用のみ**——数値・文言を変えない。本節が定めるのは「誰が・いつ・どう記録し・どう判定するか」の運用形（G-PT-05・H-09〜H-11）
- **記録形の凡例**：`ログ`＝§3.2 のイベントログ／`聴取`＝§3.3〜3.4 の定点アンケート＋終了後インタビュー／`録画`＝§3.1 の通し録画／`監査`＝L1 の表照合・目視確認（L1 内部資料）
- **判定権の分離**（docs/40 §5.1）：E 系の合否は **L2 の初見データで判定**する——L1 は面白さの判定権を持たない。カードの「合格判定担当」は「合否を記録・確定する者」であり、E 系は L2 データに基づき L1 判定役が記録する。判定権者・再試行規則の確定は §7（H-13）側

### 4.1 体験検証 E-1〜E-9（H-09——L2 主・L1 補助）

  1. テスターに招待パッケージ（§2）を配布し、操作方法のみを記した説明書きで開始（目的・攻略は教えない）

#### E-3 定点の気づき

- **正典（引用——E-3）**
  - 測定方法：核心モーメント（「全部俺が捨てたものだ」「あの名付き品がここにない」MP反転・翁の正体・月齢ゲートの理解・結末の逡巡）ごとに「気づいた/気づかなかった」を記録
  - 合格ライン：各モーメントで気づき率 ≥ 2/3（※「名付き品がここにない」の気づきの分母は**由来物初投入経由で到達したテスター**に限定——累積64個フォールバック経由では構造上発火しない・34/00 §3 注記）。気づかなかった場合は発火条件・多重化を巻き戻し対象にする
- **実施手順**：
  1. モーメント別の観測チャネルを下表で定め、発火点通過を `moment.fired` で記録
  2. 「気づき」の判定基準は運用として定義する——**行動代理ログ OR 終了後聴取の複合判定**（要承認 41-U2-Q4）：①代理指標ログの観測 または ②聴取 A 群での気づきの言語化、のいずれかで「気づいた」。両方なければ「気づかなかった」

  | モーメント | 発火点（ログ） | 代理指標（ログ） | 聴取判定 |
  |---|---|---|---|
  | 全部俺が捨てたものだ（M-00-3） | `discard.first_view` | 自分区画の滞在・`inspect.lore`（owner=self） | A-1/A-2 |

- **実施主体／記録者**：ログ自動＋聴取担当 L1＋判定者 L1 2名
- **記録形**：ログ＋聴取＋録画（判定再確認用）
- **母集団・分母**：各モーメントについて発火点に到達した L2 全員。**「名付き品がここにない」のみ `invite.fired` route=named_first_insert のテスターに限定**（正典注記どおり——`invite.fired` が分母判定の必須イベントになる）
- **合格判定担当**：L1 判定役（気づき率の集計は L2 データに基づく）

#### E-4 読み合いの成立

- **正典（引用——E-4）**
  - 測定方法：窪地の小遭遇でテレグラフ（塊の膨張1.5s 予備動作）を体験し、月欠狼で「月齢→窓」の法則を自力で理解したか（死亡/試行回数と理解の経緯を聴取）
  - 合格ライン：撃破時点で窓の意味を言語化でき、撃破時間が標準帯（135–145秒ソロ・38/03 §4.2）から大きく外れない。大幅超過は読み合い不成立の徴候
- **実施手順**：
  1. `boss.fight.*`・`boss.window.*`・`boss.telegraph.shown`・`player.death` で試行回数・撃破時間・死亡経緯を記録
  2. 言語化は F2-4（自由記述）と聴取 A-4 で確認——「月齢→窓」の法則を自分の言葉で説明できたかを判定
  3. 撃破時間が標準帯±20%（40-Q7③）から大きく外れた個人は「読み合い不成立の徴候」として別記録し原因を聴取
- **実施主体／記録者**：ログ自動＋聴取担当 L1
- **記録形**：ログ＋聴取＋録画
- **母集団・分母**：ボスを撃破した L2 全員（正典の「撃破時点で」に基づく）。撃破未到達の者は本項目では測定不能として記録し、未完走なら E-1/E-5 側の記録と突合する
- **合格判定担当**：L1 判定役

#### E-5 迷子・停滞

- **正典（引用——E-5）**

  - 合格ライン：迷子判定の発火そのものは想定内（45/02 §4.2）。強制誘導なしで全員が主線へ復帰できること。同一地点での二度目の迷子は導線の不合格

- **実施主体／記録者**：ログ自動＋聴取担当 L1
- **記録形**：ログ＋聴取
- **母集団・分母**：L2 全員
- **合格判定担当**：L1 判定役——40-Q7②「中央値≤3回/人・最終段到達0人・同一地点二度目＝不合格」で判定

#### E-7 拾い直しの動作

#### E-9 異物の発見性

- **正典（引用——E-9）**
  - 測定方法：新規ワールドの複数シードでスポーン圏内1箇所の生成保証を確認（docs/32 §4.1）＋遠望・近接での視認強度が「気配〜示唆」段階に収まりランドマーク級の明示になっていないかをスクリーンショット/録画で確認（U1-Q5）。縁の羅針盤の二次案内が機能するか（対象種別は「針の色＋針の形」または「音色＋字幕名」の複合で識別——U1-Q4）

- **実施手順**：
  1. L1 が新規ワールドを複数シードで生成しスポーン圏内1箇所の生成保証を確認——**複数の運用最小値は3シード以上**とする（要承認 41-U2-Q8）
  2. 視認強度の判定＝遠望・近接でスクリーンショット/録画を撮り、「気配〜示唆」段階（45/01 §3.1-3.5 の3段階のうち下位2段）に収まりランドマーク級の明示でないことを L1 が目視判定

- **母集団・分母**：生成保証・視認強度＝L1 実施シード群／発見性＝L2 全員（発見せずともゴミ箱経路到達で合格）
- **合格判定担当**：L1 判定役

### 4.2 技術検証 T-1〜T-9（H-10——L1 主・L3 補助）

#### T-1 環礁生成

- **正典（引用——T-1）**
