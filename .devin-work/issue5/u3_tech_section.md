### 4.0 位置づけ——スライスが立つ土台

垂直スライスは Phase 1（Walking Skeleton、docs/00 §3.1）と Issue #13（次元生成・異物チャンクの技術検証）の成果の上に立つ。本節は、スライスに必要な技術基盤を「依存構成・次元生成・構造物・ボス状態遷移・語り/フォント・音響演出・データ構造・パフォーマンス」の領域別に要件化し、最後に Issue #13 との検証の住み分けを定める。

土台の原則——スライスの基盤は**本番設計で作る**（P-VS-04「拡張構造は作り捨てない」）。試作用の一時実装・写し替え前提の骨組みは、第2章以降の量産コストを誤測定させるため禁止とする。「スライス専用の仮装置」は置かず、実装しない機能は §2 の範囲外として明示的に切る。

| 前提（引用のみ・変更しない） | 値 | 根拠 |
|---|---|---|
| ローダー / MC / Java | NeoForge / 1.21.1 / Java 21 | ADR-0002・G-VS-02 |
| ワールド生成方式 | データ駆動ワールドジェン（JSON/Datapack 主軸） | ADR-0002 |
| セーブ・同期モデル | 共有層＋個別層のハイブリッド | ADR-0004・docs/32 §6 |

### 4.1 依存MOD構成

| MOD | 依存形態 | スライスでの役割 | 根拠 |
|---|---|---|---|
| JEI | **必須** | レシピ可視化——拾得鍛錬・ゴミ箱8連クラフト・名づけ系の閲覧。隠しレシピは既定非表示＋発見後解禁（`IRecipeManager` 制御）。modpack組込条件（D-4）の前提でもある | docs/46 §7 D-1・docs/32 §9・18-U4-Q6 |
| Patchouli | **ソフト依存**（必須ではない） | 拾得図鑑・村報の実装器（器割当＝目録系書物のみ——拾得図鑑・村報）。非導入でも本編は遊べ、未導入時は自前書物器の別冊（同一書物スキン族）で機能を代替する | docs/46 §7 D-2・docs/48/02 §4.4-4.5・docs/18 §3.1・§4.0（U2-N6・U4-7） |
| GeckoLib＋Blockbench | **配備形態は要決定（40-U3-Q9）** | ボス・特殊モブのアニメーション基盤（月欠狼の相変化・見得・満月窓の静止演出、没腐の塊の蠢き）。docs/00 §3.1⑦「GeckoLib＋Blockbench が定石」を採用するが、D-4②「hard dependency は NeoForge＋JEI のみ」（docs/32 §9）により外部必須依存にはできない——**推奨＝ jarJar 同梱**（mod jar 内埋め込みのため必須依存を増やさず定石を維持）。代替＝soft 依存＋未導入時はバニラ式状態遷移に簡略化（docs/00 §3.1⑦の設計代替） | docs/00 §3.1・G-VS-03・docs/32 §9 D-4②・docs/38/03 |

| 字幕・音響拡張 | 自前実装 | 環境音ベッドの擬似ループ制御・共有層イベントのサーバー権威発火 | docs/19 §2.4-2.5 |

**スライスに入れない依存**（範囲の境界）：正典が確定した依存構成は上表に尽きる——**modpack 追加依存・外部 MOD 連携はリリース後の拡張枠とし、現時点で個別の計画はない**。スライス外のコンテンツ（響界・仮の姿/上位鍛錬・原案の座など）は外部依存ではなく自前実装の後続章要素であり、§2 範囲表と §7 台帳で管理する。**必須依存は NeoForge＋JEI のみの上限に固定する**（modpack 収録5条件の一つ＝依存最小——docs/46 §7 D-4・docs/32 §9）。追加の必須依存・外部連携が必要になった場合は本計画の open_questions へ回してユーザー承認を取る（未承認の依存計画を本文で確定事実として記述しない）。

**依存でないが共存必須の検証環境**：Iris＋主要シェーダー3系統（Complementary Shaders - Reimagined・BSL Shaders・Sildur's Vibrant Shaders——18-U4-Q14 承認済みの確定値）＋ Distant Horizons（望遠）。配信者はほぼ全員シェーダー使用のため「シェーダー ON/OFF 両方で演出が崩れない」は公式対応要件（docs/20 §4）。導線・演出はすべて OFF＝素のバニラ表現で一次チャネルが成立する設計（U1-Q1 承認・G6 相当）。DH の遠距離描画が未踏環礁の内容を見せすぎないかは §5.2.3 A-7 で検証する。

### 4.2 次元・環礁生成方式

**国＝1つのカスタムディメンション**（ADR-0002 のデータ駆動ワールドジェンで定義）。スライスが生成を要求する領域：

| 領域 | 内容 | 生成方式の要求 | 根拠 |
|---|---|---|---|
| 漂着浜（序） | 着弾点〜帰還の場所系列8地点（淀みの窪地＝場所6・共同堆積の丘＝場所4——自分の区画の器を含む） | 埋没型環礁全体を1構造群として生成。場所系列はアンカー固定 | docs/16 §3.2・34/00 §3 |
| 満ちなかった月の林（01） | 場所系列＝正典のクリティカルパス6地点（①手紙の径口→②もうすぐ参道→③熟すことを書かれなかった果樹園→④月見の小屋→⑤月読みの丘→⑥摘み取りの丘）＋寄り道・補助3箇所（二度棄ての物置・前任の露営・月下の小島） | 同上。常夜の環境表現（昼でも薄暮＋欠けた月）が必要 | docs/34/01 §3・docs/16 §4.1・§4.1.1 |
| 拾い人の村 | 集落構造＋共同ゴミ箱＋灯り（浜の奥の道から視認） | 集落型生成——中核棟＝①固定テンプレ＋発展区画＝②jigsaw の住人棟プールで、救出後に農園プロットが増える**成長可能な構造** | docs/16 §3.4・34/01 §7・docs/11 §7 |
| 環礁間の接続 | 浜→林の土手・橋めいた流れ（徒歩で辿り着ける） | 環礁間の海/淀み空間を含む次元地形 | docs/34/01 §2.1・docs/13 §4 |
| 月下の小島 | 01沖の補助環礁（S規模・没腐濃度の高い小試練） | ③地形依存埋没＋①固定テンプレ（ロア部品）——補助環礁の標準形。配置は Structure Set の探索型（spacing/concentric）を沖ゾーンに限定し、主線のアンカー定点とは分離 | docs/16 §3.8（補助環礁⑨）・§4.1.1・45/02 §8 |
| 自分の捨て場 | 所有者別の区画（投棄量で増築）＋国側の口 | **個別層の動的生成**——所有者ごとに内容が変わる唯一の地形区画 | docs/16 §3.5・docs/23 §5.1・docs/32 §6 |
| 未訪問環礁（02〜終） | 見晴らしの岬から一望できる「気配」——最遠の白い座（終章・原案の座）と常夜の林・欠けた月を含む | **遠望表現のみ**——実環礁の生成は各章制作時。スライスでは遠景レイヤー/疑似表現で「遠望は存在のみ・形は見せるが内容は見せない」（G11）を満たす | docs/16 §3.2 詳細カード⑤・§3.8・45/01 §3.2-3.3・45/02 §3.4 |

**配置方針（推奨——40-U3-Q8 で承認を取る）**：環礁アンカーと場所系列の相対配置は**ワールド固定**とする。場所系列はクリティカルパスとして脚本化され（34 各章 §3）、序破急の時間配分（48/03 §4.2）・月中継点の方位基盤（45/01 §3.3「共有の月＝中継点の本家」・docs/16 §2.6-3）・見晴らしの岬からの環礁群一望（docs/16 §3.2 詳細カード⑤・§3.8）がすべて固定地理を前提にするため、プロシージャルな島配置では脚本どおりの劇を上演できない。地形の肌はシード依存ノイズでよいが、主線の骨格（場所の並び・距離・見通し）は固定レイアウトで生成する——黄昏の森型の「構造はアンカー配置、地表はノイズ」に相当する方式。

**共有の月と時間表現**：国の空の月は全環礁で共有（34 README 規則6・docs/11 §5）。01環礁は「月が欠けたまま止まる常夜」、浜は「かすれた朝靄」と環礁ごとに時間帯表現が異なるため、ディメンション共通の時刻進行ではなく**環礁（バイオーム）ごとの環境光・空演出の個別制御**を要件とする。ボス戦の月齢満ち欠けは演出レイヤーとして同期描画し、マルチでも全員に同一の月相が見える（共有層＝サーバー権威——docs/19 §2.5）。結末後の月の状態変化（A選択＝満ち欠け再開／B選択＝新月と星）はワールド状態として持続し、全環礁の空に反映される（34/01 §6.3）。

**入退次元の機構**：デカいゴミ箱の両側口（23 §5.1 確定値——現実側の箱と1対1紐付き・国側の口は着弾点に出現・拾い上げで閉じる・村共同箱が必ずフォールバック）と異物チャンク（個別層・片道・持ち込み不安定・視認は気配〜示唆段階に固定＝U1-Q5）の2系統。**「帰れない状態を作らない」（docs/32 §2.2）を転移機構の成立条件**として実装し、リスポーン優先順位＝自分の捨て場→漂着浜の共同堆積→村の3点を据える。

### 4.3 構造物生成

生成方式の語彙は docs/16 §2.4 の4型に固定：**①固定テンプレ（.nbt）②jigsaw モジュラー③地形依存埋没④手組み領域**＋ハイブリッド標準。スライスで実証すべき生成基盤：

| 基盤 | スライス内の使いどころ | 検証の要点 | 根拠 |
|---|---|---|---|
| ①固定テンプレ | 月見の小屋・二度棄ての物置（小屋同一パッケージ）・村の中核棟・月下の小島のロア部品・月中継点の開口部・**章クリア後に開く橋/流れの接続部品** | .nbt 配置＋向き/オフセット規則（月中継点は01＝空の月自体が担うため構造物対象外）。橋/流れは「序・1章・5章・終章はクリアで繋がる」地理ゲートの開放演出を担保する部品として含める（01クリア後の遠望更新と連動） | docs/16 §4.1.1・§3.4・§3.8-3.9・docs/13 §4・45/02 §3.4 |
| ②jigsaw モジュラー | 01は4構造——手紙の径口（浅層：径口モジュール＋手紙の木）・もうすぐ参道（径パーツ＋立て札点＋根の遮光節）・熟すことを書かれなかった果樹園（区画迷路組み）・前任の露営（露営モジュール）。加えて村の発展区画（住人棟プール）と自分の捨て場（増築モジュール）が同型 | jigsaw pool/depth の JSON 定義 | docs/16 §4.1.1・§3.4-3.5・Issue #13 手渡し |
| ③地形依存埋没 | 淀みの窪地・堆積系・月読みの丘（丘の起伏に追従）・摘み取りの丘（丘体＋アリーナ盤＝L規模・直径60〜70m）・月下の小島・縁の地・異物チャンク | 地形追従の埋没配置（探索ランダム性は主線に使わない） | docs/16 §2.4・§4.1.1・§3.6-3.7 |
| 劣化置換 processor | 全埋没・廃墟系構造 | 「かすれた」審美の自動置換（色・損傷・反復痕跡）。適用外カテゴリ＝物証系・ボスアリーナ・安全拠点・境界の機能物 | docs/16 §2.4 |
| 個別層生成 | 自分の捨て場区画（②jigsaw増築＋没腐度歪みprocessor）・異物チャンク（スポーン圏内1箇所保証＋発見者のみ視認） | 所有者別の内容分岐・増築（ADR-0004） | docs/16 §3.5・§3.7・docs/32 §6 |
| Structure Set | 補助環礁（月下の小島）のみ | 主線場所系列は探索型でなく**アンカー定点生成**とし、spacing/concentric の探索配置は補助環礁に限定 | docs/16 §2.4・§3.8・§4.1.1 |

構造物の数値（規模・個数・配置数の実数）は **Issue #15**（数値全表）へ、生成技術一式（構造生成 JSON・jigsaw pool/depth・processor・個別層生成・L3 同一構造判定・灯台−座礁船連動生成）は **Issue #13** へ手渡し済み（docs/16 §7.5 の振り分けどおり）——本計画では要件として触れるのみ。

### 4.7 データ構造＝拡張前提（P-VS-04）

量産フェーズで「章を足す＝データを足す」にするため、スライスの全コンテンツは本番スキーマで定義する：

- **章定義**：章ID・場所系列・主線/寄り道区分・一次チャネル・救出者・結末選択肢・予告頁接続をデータ駆動で記述（第2章以降は定義の追加のみで成立する構造）。
- **断片・頁・ロア**：拾得物ID・由来フラグ・頁データ・綴じ先の登録を JSON/レジストリ管理。図鑑・手記・結末記録は同じ頁データ層を参照する。
- **ボス・モブ数値**：HP・係数・フェーズ閾値・報酬をデータ表として定義（docs/38 数値表がそのままデータソースになる構造）。
- **導線チャネル**：各場面の一次/二次チャネル（C1〜C8の割当）を宣言的に持ち、a11y 監査とシェーダーOFF検証の対象表をデータから生成する（docs/45/04 §3.1-3.2 の必須チャネル表・算入制約を機械検査可能にする）。
- **個別層/共有層の状態分離**（ADR-0004）：ワールド状態（村の成長・結末確定・月の状態・環礁の救出済みフラグ）とプレイヤー状態（ノミの名・拾得履歴・手記頁・自分の捨て場・先着結末の帰属）を別ストレージで実装。スライスでこの分離を作る＝全章共通の基盤。
- **登録の規約**：全IDは `understory:` 名前空間、バニラ上書きなし、レシピ/データ競合を避ける（modpack 5条件 D-4）。
- **コンフィグ**：a11y 10項目（45/04 §6——コンフィグ化一覧の権威）のうちスライスに効くものは初期からコンフィグ駆動で実装し、Issue #34 の設計へそのまま渡せる形にする。

## 5. 検証計画

### 5.0 目的

スライスの検証は「作ったものが動くか」ではなく、docs/00 Phase 2 の定義どおり**「第1章を遊ばせて感動する品質か——実プレイで証明できるか」**を判定するために行う。合格したときだけ量産フェーズへ進む（P-VS-06「検証は3層」・G-VS-01）。検証の対象はスライス全体（OP〜序章〜第1章〜村〜帰還の端到端）であり、単体機能の通電確認は検証計画ではなく工程（§6）の各ステージで済ませる。

### 5.1 検証者3層

| 層 | 検証者 | 担う判定 | 実施形態 |
|---|---|---|---|
| **L1・自分たち** | 制作者（本計画の実施者） | 仕様適合・仕上げ基準の充足・技術計測値の取得・a11y規則の監査 | 全工程で常時。マイルストーンごとに仕上げ基準チェックリストを適用 |
| **L2・テストプレイヤー** | クローズドの少人数プレイヤー（推奨 3〜8名、募集方法は 40-U3-Q5） | **初見体験の成立**——説明なしで気づき・迷い・選び・感動できるか。制作者には見えない盲点の発見 | 録画または同席観察。感想は定点アンケート＋自由記述 |
| **L3・配信実環境** | 配信者または配信相当環境（推奨 1名・サーバーイベント相当——40-U3-Q5） | **視聴者への伝達**——クリップ瞬間が切れるか・説明なしに画面が語るか・同時性が演出を壊さないか | サーバー上での実配信または収録。観客反応（コメント/クリップ作成）を可能なら取得 |

L1 は「作り手の確認」であり面白さの判定権を持たない——体験の合否は L2 の初見データで判定し、配信映えは L3 で判定する。判定の混同（自分で面白いと思う＝合格）は検証失敗の主原因（docs/55 §1.4 速度の錯覚と同型）として禁止する。

### 5.4 失敗時の巻き戻し方針

docs/00 の「面白くなければ仕様を巻き戻す」を、本計画では**巻き戻しの階層**として運用する。失敗した検証項目ごとに、まず浅い層から修正し、浅い層で治らなければ一段深い層へ降りる。各段階は必ず再検証してから次へ進む。

| 層 | 巻き戻し対象 | 例 | 判定に必要な再検証 |
|---|---|---|---|
| ①表現層 | 演出の見せ方・強度（チャネル強度・見え方・間合い） | 気づき率不足 → 一次チャネルの強度を上げる/多重化を1系統追加 | 失敗項目のみ L1→L2 部分再検証 |
| ②数値層 | 時間・難度・閾値・配置数 | 所要時間超過 → 場所間距離・断片数・ボス帯域の調整 | 時間系は L1 計測＋L2 部分再検証 |
| ③仕組み層 | 導線装置・教え方・場面の構成 | 窓の意味が伝わらない → 月齢 teach の場面追加/狼の構えの段階化 | 失敗項目を中心に L2 再検証 |
| ④範囲層 | §2 範囲表の含む/含まないの再裁定 | 寄り道・補助環礁が体験密度を下げる → スライスから切る（台帳に記録） | 範囲変更は計画の改版として記録 |
| ⑤正典層 | 主題装置・仕様の根本の見直し | 「待つ/満ち欠け」が面白くない → **ユーザー決裁のみ**。G-VS-07 の識別子（あなたが捨てたもの・拾得図鑑・ノミ・結末綴じ）と P-VS-02 の主題装置（没の掴み・拾得・語り・綴じ・選択の記憶）は巻き戻しでも削らない | ユーザー承認＋正典の改版 |

- **巻き戻しの順序**：①→⑤の順でしか深くならない。いきなり範囲や正典に触れない（浅い修正で治るものを深い層で壊さないため）。
- **切る判断は台帳に残す**（P-VS-07）：④範囲層で切った項目は「切った理由・再候補条件・受け渡し先」を必ず記録し、量産で拾えるようにする。
- **判定不能時**：修正方針が層をまたがる、または効果が読めない場合は、追加の小規模検証（対象場面のみの再テスト）を実施してから次段階へ進む。迷ったまま深い層へ進まない。

## 6. 工程・工数測定

### 6.0 目的

本章は2つの目的を持つ：(1) スライス自体を作る順序と段階的マイルストーンを定める、(2) スライスで得た実測工数から**章量産フェーズの可否と規模を外挿する**方法を定める（P-VS-08「量産可否は工数で判る」——量産判断は勘ではなく測定値で行う）。

### 6.1 順序の原則——先に終わりまで走らせる

P-VS-01「完走優先」に従い、スライスは**まず端到端を骨格品質で通し、その後にモーメント単位で仕上げる**。序盤から一点だけを完成品質まで磨くと、後半が検証前に崩れたとき発見が遅れる（docs/55 §1.4「速度の錯覚」——早く見える＝完成していない、の典型）。各ステージの完了条件は「先に進める状態」であり、仕上げ基準の判定は最終段で行う。

### 6.4 工数測定の方法

量産への外挿が目的のため、スライスの工数は**章当たりの変動コスト**と**一回限りの基盤コスト**に分けて記録する。混ぜると外挿が壊れる。

- **記録の粒度**：作業単位を「資産種別×フェーズ」でタグ付けして記録する（日報/チケットの実績メモで足りる——ここでは測定の型だけを定義する）。
  - 資産種別：構造物/モブ・ボス/アイテム・レシピ/テキスト・頁/UI・音/フォント・字形/FX・転調/導線実装/a11y 対応/検証・修正。
  - フェーズ：S0〜S5。
- **分類の規則**：
  - **一回限り**：次元骨格・転移機構・個別層/共有層基盤・フォントパイプライン・ボス基盤・書物器・字幕規格・検証の型（§5 自体）。
  - **章当たり**：環礁地形・場所系列・断片配置・ボス実装・結末差分・章固有音/フォント運用・その章の検証周回。
  - **未分類は後で外挿できない**ため、記録時に必ずどちらかに振る。
- **巻き戻しの計上**：§5.4 で修正に費やした工数は「検証・修正」として別立てで記録する——初見での制作時間だけ測ると量産時の試行錯誤コストを過小評価する。

### 6.5 章量産への外挿方法（P-VS-08）

**外挿モデル（推奨式）**：

```
章コスト(概算) ≈ スライス実測の「章当たり変動コスト」 × 章規模係数 + 章固有の新規基盤分
```

- **章規模係数**：第1章は想定 50〜80分、第2〜3章は 120〜180分、第4章・第5章・終章は 180〜240分（48/03 §4.2・docs/13 §2）。時間比を第一近似の係数とし、場所系列の場所数・断片数・ボス規格（T0〜T3）で補正する。
- **新規基盤分**：スライスに入らない機構（第5章の響界・終章の座と綴じ機構・第4章の仮の姿/鍛錬上位）は「章当たり変動」に含まれないため、個別に基盤コストとして見積もり直して加える。**外挿が効かない機構を隠さない**。
- **割引（haircut）の適用**：スライス実測には初回特有の熱意・集中・仕様詰めの速度が含まれるため、そのまま残5章＋終章に掛けると楽観になる（docs/55 §1.4 速度の錯覚——スライスの速さは量産の速さではない）。外挿値には安全側の係数を掛け、根拠とともに報告する（係数値はスライス計測後に確定——40-U3-Q7）。
- **量産可否の判定基準**：以下の3点が揃ったときのみ量産へ進む。
  1. **実測外挿が許容期間内**：外挿総量（変動分×係数＋新規基盤分＋巻き戻し余裕）が定めた開発期間に収まる（期間の上限はユーザー決定——40-U3-Q7）。
  2. **パイプラインが文書化済み**：章を足す＝§4.7 のデータスキーマに定義を足す作業として記述できる（属人化していない）。
  3. **検証が合格済み**：§5.3 の基準をクリアしている（面白くないものを速く作れるだけでは量産しない）。

外挿の結果が期間を超える場合の選択肢（どれも open_questions で判断）：章規模の削減（範囲層の巻き戻し）・分割リリース・制作期間の見直し。

### 6.6 注記——この測定が外挿を誤らせないために

- スライスは「最も骨太の一章」ではなく「代表章」——月の林は標準的な場所系列と演出密度を持つが、響界（第5章）や座（終章）のような特殊基盤を含まない。**外挿は「代表章の単価」としてのみ使い、特殊基盤は別見積もり**とする。
- S0〜S1 にかかる基盤コストは第1章固有ではないため、第1章単体の実績は「基盤込みの最悪値」と「変動分のみ」の2値で記録しておく（量産モデルの上下限に使う）。
