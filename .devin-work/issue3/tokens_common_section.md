## §1 デザイントークン完全定義

> docs/20 §8 残件「デザインシステムのトークン（色・形・動き）の完全定義」の着地節。docs/20 §2 の方針行を、実装が引ける値・規格へ翻訳する。実数値は推奨案——承認で正典化（要承認 ID＝`18-U1-Q{n}`・§2.7 に集約）。

### 1.1 色トークン

**原則**：色は「語りの深度」を運ぶ。基調パレットは器の骨格（全器共通）、アクセントの朱・琥珀は意味を持つため予約（docs/20 §2 色予約）、かすれは淀みの語彙（彩度↓＋灰化）。**色のみに依存する表示は禁止**（G-UI-06——必ず形・位置・動き・音と併記する）。

#### 1.1.1 基調トークン（器の骨格——全 UI 共通）

| トークン | 用途 | 推奨値（hex） | 根拠 |
|---|---|---|---|
| `ui_ink`（墨） | 本文・罫線・枠線・確定した記述 | #2B2E33 | docs/20 §2 基調「墨」。読む層の主文字色 |
| `ui_paper`（月白） | 頁の地・主面・ハイライト背景 | #E6E1D3 | 基調「月白」。温かみのある白（国の紙） |
| `ui_ground`（灰青） | 背景地・器の外縁・暗い下地 | #3E4A52 | 基調「灰青」。頁を囲む世界の色 |
| `ui_gilt`（古金） | 見出し・装飾線・綴じ糸・重要項目の強調枠 | #8F7B4F | 基調「古金」。意味を帯びた飾り（使いすぎない） |

#### 1.1.2 アクセントトークン（予約色——使い途を限定）

| トークン | 許される用途 | 禁止用途 | 推奨値 | 根拠 |
|---|---|---|---|---|
| `ui_vermilion`（拾得の朱） | 拾える物の標識・拾得系動作の選択表示（綴じ画面の「拾う」項等——**拾得に帰属する選択に限定**）・新規拾得の通知差し・「届いた」の一点 | 装飾全般・章差し色・危険表示・**拾得に帰属しない汎用カーソル/選択色** | #B5442C | docs/20 §2・45/01 §4.4「拾得の朱一本」（器内適用の裁定は下行注記） |
| `ui_amber`（灯りの琥珀） | **「読める物を兼ねる拾得物」のみ**（届いた手紙・読める物を兼ねる由来物）・灯火の UI 反映 | 上記以外の全て（**読めない由来物・汎用の気配表示には使わない**） | #B98A44 | docs/20 §2 琥珀例外・45/01 §4.4 |

> **予約色の器内適用の裁定（本書の明記）**：朱の選択表示への適用は「拾う」等の**拾得に帰属する動作の選択に限定**し、汎用のカーソル色・選択色には用いない。琥珀の由来物への適用は**「読める物」を兼ねる由来物**（届いた手紙等）に限定し、読めない由来物の気配には用いない。いずれも 45/01 §4.4 の予約域（拾得標識＝朱一本／琥珀＝読める物・静止した手紙・灯りの安全・静止系）の内側に収める器内適用として明記する——予約色の乱用禁止（45/01 §5.1 K-10「アクセント予約色の乱用」）に触れない範囲の限定である。

#### 1.1.3 かすれ階調（淀み・読めない項・未確定の語彙）

| トークン | 用途 | 推奨値・規則 | 根拠 |
|---|---|---|---|
| `ui_faded`（かすれ） | 「かすれた項」・封印済み・まだ読めない頁の表示 | 基調色を彩度 −60%・輝度 ±10% へ灰化（頁上では墨 #6A6E70 相当・輪郭だけ残す）。**存在の可視は枠・位置・形が担い、文字の可読は奪う**（コントラスト規則 C-4 の対象外＝正典設計） | 45/04 §4 C-4・docs/20 §5 彩度規則・K3 |
| `ui_blank`（余白） | 「まだ綴じられていない頁」・欠頁の余白・詩の行間 | `ui_paper` より一段明るい #EFE9DC。余白は情報の欠如でなく「これから綴じられる場所」の語彙 | docs/20 §5 余白・48/02 §4.1 |

#### 1.1.4 章パレットの UI 適用

- **器は共通・断片頁の皮だけが変わる**：UI の基調色・器クローム（拾得図鑑・手記・綴じ画面等の枠・綴じ目——1.1.1・1.2.1）は章・形式で変えない——「拾得図鑑は形式に関わらず同じ器に収まる・共通の装丁に住み分け」（48/04 §5.2 綴じの皮）が確定済みの線引き。章・形式ごとに変わるのは**断片頁の装丁の皮**（枠意匠・綴じ糸色・頁面モチーフ・挿絵比率——48/04 §5.1 装丁マトリクスの「装丁の皮／頁の構え／乱れの演出」列の範囲）のみ（P-UI-01・法典の結び）。
- 章サブパレット（褪せた祭り色・錆・鉱石の輝き等）は**断片頁の装丁と頁面挿絵の内部**に閉じる。HUD・通知・字幕・器クロームには章色を流用しない（色が情報を担う系譜を乱さない——G-UI-06 予防）。

#### 1.1.5 コントラスト規則（45/04 C-4 の UI 側履行）

- 読む層の本文は「`ui_ink` × `ui_paper`」の高対比を既定。装飾背景の上に本文を直置きしない（挿絵頁の文字は余白面または下地紙の上に置く）。
- かすれた項・封印項は読めない設計（K3）ゆえ対象外——**「ある」ことを枠・折れ目・綴じ目の空きで示す**（色の灰化は補助）。
- 字幕・由来札・照準ヒントは背景不透明度の確保で担保（バニラ字幕の表示規則に倣う）。

### 1.2 形トークン

**原則**：全 UI は「書物・頁・綴じ目」のモチーフで造る（P-UI-01）。「かすれた・欠けた・継がれた」の審美は形の言語で表す（docs/20 §2 形状言語）——**形の差は色に依存しない識別系**としても機能する（G-UI-06 の裏取り）。

#### 1.2.1 器の部品語彙

| 部品 | 意味 | 形の規格 |
|---|---|---|
| 表紙 | 器の入口・所蔵状態の顔 | 外縁に継ぎ目（異素材の接ぎ）・角の欠け。「新頁あり」の気配は表紙の微細な隆起＋薄い光の滲みで表す（U2-N2——拾得の朱の予約域に触れない、気配級の形＋光の差で示す） |
| 頁 | 内容の最小単位 | 右/左頁で綴じ目側の影が逆。端のかすれ（水濡れ系）は装丁差の一部 |
| 綴じ目（糸綴じ） | 頁の帰属・欠頁の可視 | 綴じ糸は古金。欠頁は糸の残る空き孔＋余白頁で「ここにあった/来る」ことを示す（枚数のみ可視・内容は示さない——U2-N2） |
| 折れ目（頁端折り） | 未読の印 | 頁の外角を折る。読了で消える（状態遷移＝読了フラグ） |
| 栞・帯 | 再開地点 | 綴じ画面・手記で「前回ここまで読んだ」を帯で示す（再開可能原則の視覚化） |

#### 1.2.2 枠意匠（境界の装飾）

| 意匠 | 用法 |
|---|---|
| 欠けた矩形 | 基本フレーム。角の1〜2箇所を欠かす——完全な矩形は「現実側・新品」の語彙として温存 |
| 破れた頁縁 | 断片・欠片由来の頁（拾得した断片の綴じ頁は縁が破れている） |
| 継ぎ目 | 異形式・異出典の境界（書簡と設計書が同じ器に綴じられる境、等） |
| 不完全な円 | 選択肢・未確定の項の囲み（綴じ画面の三択枠——完成しない円＝結末の未確定） |
| 「没」の印 | 設計書・棄却項の捺印型意匠（朱肉の掠れ印——48/02 §4.1） |

#### 1.2.3 アイコン体系

| 規格 | 値 |
|---|---|
| 基準グリッド | 16×16（バニラ GUI 基準）。内側 1px 余白 |
| 統一線幅 | 外郭 1px・主形 1px（アイコン内の太さ差は 2 段まで） |
| 欠け表現 | 全アイコンに「欠け変種」を用意——角の欠け・輪郭の断ち・内部の抜けを形で入れる（完全な形は使わない） |
| 色規則 | アイコンは墨＋古金で描き、意味の差し色は朱（拾得）・琥珀（読める物兼ねる）の予約に限る |
| 一覧 | 拾得（欠けた菱形＋糸屑）・没腐（歪んだ輪郭）・結末（不完全な円＋綴じ目）・図鑑（綴じ目付き冊子）・未読（折れ目）・由来（名札形）・頁追加（頁＋折れ目）・幕（開いた幕形）——各器での使用は §3〜§5 が明記 |
| 配信要件 | 16px 基準でも部品が識別できる形（輪郭の内切りを広めに——P-UI-08・30 秒基準） |

#### 1.2.4 「読めない形」の語彙（幻想文字・かすれ文字の形側）

- 幻想文字：58 字形・「骨格（子音行）×継ぎ目（母音列）」の行列構造（48/04 §2.2〜2.3 確定）。**ガラ（読めない字）の識別基準＝行列構造に収まらない形**——UI 側はこの形状規則を崩さない字形でレンダリングする。
- かすれ文字：日本語のまま形が崩れる書体——「読めるが乱れた」状態はフォントが担い（§1.4）、読めない状態（幻想文字）と峻別する（48/04 §5.2：読めなくするために幻想文字は使わない）。
- 祭囃子没腐姿（Issue #2 手渡し分——H23）の**形側メモ**：半融合三段構成（下半身＝指揮台機構接合・両腕＝操り糸機構・頭部上半身＝人の姿——16-U3-Q1 承認値）において、UI/観る層で「機構が演目を演じる」ことが読める部位の見え方（拍子歯車の露出・糸巻きの回転・鈴と扇の腕のみが拍子を刻む動き）は §6 演出要件の入力とする——デザイン側造形詳細（衣装・表情）は本節のトークン範囲外、§6.5 の造形メモへ集約する。

### 1.3 動きトークン

**原則**：モーションは「時間の経過」を語る——速い・弾む動きは使わない（世界は止まっている）。動きは全て「かすれて現れる・綴じられる・めくれる・幕が降りる」の語彙に閉じる（docs/20 §2 モーション）。数値は UI 時間値として本書が確定する（P-UI-10——承認で確定：18-U1-Q3/Q2）。

#### 1.3.1 モーションプリミティブ（推奨確定値）

| モーション | 用法 | 時間・緩急（推奨値） |
|---|---|---|
| かすれて現れる | テキスト・項・頁の出現。低彩度・低輪郭から知覚できる形へ | 0.45s・ease-out（彩度 0→規定値・不透明度 0→100% を同時変調） |
| 欠片が綴じられる | 拾得片・頁・欠片が器に収まる | 0.9s：対象が収束点（綴じ目）へ吸い込み＋綴じ音で締まる |
| 頁めくり | 書物器の頁送り/戻り | 0.30s/頁・ホールドによる連続めくり時は最短 0.18s/頁（**同一操作部位の長押し＝同一入力の反復**——§1.3.2 の裁定・採否は 18-U1-Q2 の確定対象）——§2.6 と連動 |
| 幕遷移 | 大幕/中幕/小幕の暗転 | **時間規格は docs/38 03 §4.3 が権威**（暗転約10秒・応答窓±0.40秒・キュー3.0秒——引用のみ・G-UI-18）。画面側のフェード形状＝暗転の立ち上がり 0.8s・保持・降り 1.2s（演出時間の内側に収まる形状のみ定義） |
| 巻き戻る | キャンセル・戻る操作のフィードバック | 0.25s 逆方向フェード＋巻き戻る音 |
| 沈む/淀む | 通知の消去（Toast が視界から沈む） | 0.4s 下方へ 4px 移動しながらフェード |

#### 1.3.2 モーション規則

- **イージングは ease-out のみ**（現れ→静まる）。bounce・elastic・over-shoot は使わない（「かすれた・古い」の審美と矛盾）。
- **明滅は一拍限定**——連続閃光・速いパルスは禁止（45/04 §4.3 規則 C-6＝点滅は注意喚起の一拍限定・幕の暗転等の演出は対象外。抑制強度のコンフィグ化は 45/04 §6 #3）。
- **UI 上の動きは情報の一次チャネルを担わず増幅側に留める**——**これは本書の UI モーショントークンに限定した規則**。世界側の動き（C4）は一次チャネルを担う（規則 A-2「動くものは敵・止まったものは読める」の運動 2 値判別・ボス攻撃の見得テレグラフ——45/04 §2.2（規則 A-2）・§5.1（規則 H-2））。UI のモーションは、形・位置・文字が担う一次情報の差分の可視性を上げる補助として設計する（G-UI-06・45/01 §1.4 と同じ発想）。
- **頁送り連続入力の裁定**：頁めくり部位の長押しによる連続めくり（§1.3.1・最短 0.18s/頁）は**同一操作部位への同一入力の反復**であり新規操作体系の追加ではない——法典 §4.2 可表「書物 UI 装丁：頁めくりの操作はバニラどおり」「頁めくり演出：速度・入力は不変」（48/04 §4.2）の内側と裁定する。ただしバニラ書物に長押し連続めくりは存在せず「速度・入力は不変」との解釈余地が残るため、**採否を 18-U1-Q2 の確定対象として明示**する——不採用なら連続めくりはクリック反復のみとし、0.18s/頁の値は破棄する。

### 1.4 フォントトークン

**原則**：フォント差は「読めるか」でなく「どの時代・誰の手の字か」を運ぶ（48/04 §5.2）。3 系統は font プロバイダで実装（U4-8 承認済み・G-UI-12）。

#### 1.4.1 系統表

| 系統 | font id（仮） | 役割 | 実装方式 | 使用箇所 |
|---|---|---|---|---|

#### 1.4.2 実装規則

- **プロバイダ構成**：`font/understory.json` に `ttf`（本文）・`bitmap`/`ttf`（かすれ・幻想）を登録し、テキストコンポーネントの `font` フィールドで切替（53 §2.1）。本文・かすれ系のプロバイダ種別（`ttf`/`bitmap`）の確定は 18-U1-Q5 の対象。**幻想文字の実装方式細目（プロバイダ種別の確定・換字対象の専用コードポイント割当・登録構成）は U4 担当節が確定する**（H17 棲み分け——§0.4・docs/53 §1 U4「幻想文字フォント実装方式」）。幻想文字はゲーム内に翻訳 UI を置かない方針は不変（48/04 §2.4「ゲーム機構は翻訳しない」・§4.3 不可表）。
- **和文要件**：本文・かすれ文字はゲーム内日本語全量をカバーするグリフ数が前提——約 2,000〜7,000 字形級の和文対応書体を選定する（docs/20 §3/§8 の留意条件）。サイズは描画スケールで 9〜12px 可読（読む層の可読性はコンフィグ拡大段階と併用——45/04 §6 #2）。
- **手書き三系統との境界**：案内人筆・先達筆・王筆の「字癖」は実文（Issue #10）と装丁側が担い、フォント器は時代・書き手の差を運ぶ器に留める（48/04 §2.6）。
- **ライセンス**：同梱書体は SIL OFL 相当の再配布許可を必須条件とする。**本文・かすれ系の書体選定確定は要承認（18-U1-Q5・docs/20 §8 残件）**——幻想文字書体の実装・ライセンス細目は U4 担当節の確定事項（§0.4）。

### 1.5 UI音トークン

**原則**：UI 音も「かすれた・古い」質感で全編統一（docs/20 §7）。音は通知の一チャネルであり、字幕名は「〈主体〉：〈動作〉」二項型で登録する（G-UI-15）。

#### 1.5.1 UI 音パレット（docs/20 §7 の UI 範囲）

| 音素材 | 質感 | 用途 |
|---|---|---|
| 紙 | 擦れ・めくれ・閉じる | 頁めくり・書物の開閉・断片の綴じ込み・予告頁の提示 |
| 木の軋み | 箱・台・器の軋み | 名付けの台・掲示板・コンテナの開閉 |
| かすれた鐘 | 遠くて掠れた鳴り | 通知・解放・章の印（音量小・残響短め） |
| 綴じ音（糸を締める音） | 締まる・縛る | ノミ綴じ・結末確定・頁追加の締め |
| 巻き戻る音 | 逆巻きの軋み | 戻る・取り消し・綴じ画面からの離脱 |
| 封切り | 封蝋の剥がれ | 届いた手紙・密書の開封 |
| 静けさ/紙音のみ | 音の不在 | 設計書・05 章区間（無音区間は字幕も出さない——H-4） |

#### 1.5.2 字幕名登録規則（H15 の登録面）

- **命名型**：`〈主体〉：〈動作〉` の二項型——例「紙：擦れる」「頁：めくれる」「封：切れる」「頁：綴じる」「箱：軋む」「鐘：遠くで鳴る」「幕：落ちる」。
- **方向・距離語は許容**（「遠くで」「足下で」）、**内容言明は禁止**（正体を名付けない——「打鍵：遠くで響く」型。45/04 §5.2）。
- **無音区間は字幕も出さない**——05 章の「音がないこと」は演出であり字幕で埋めない（45/04 §5.2 聞き手規則との関係・48/02 §6 無音区間行・48/04 §5.1 詩行）。
- **登録範囲**：導線上意味を持つ SE に限定を既定（45/04 §6 #1）——言語ファイルの字幕キーに登録し、UI 音は `understory.ui.*` 命名系で管理。

## §2 共通規格

> 全画面・全表示に共通する構造規則。各器の規格表（§3〜§5）は本節の規則を前提とし、繰り返さない。

### 2.1 画面階層

**原則**：UI の所在層を固定し、層の秩序を乱さない（P-UI-05・P-UI-06）。層は「演出層＞画面層＞世界層＞HUD 補助層＞通知層」の序列で管理する——**この序列は抑止優先度であり描画の上下関係ではない**（通知は描画上は画面の上に出るが、演出中は抑止される。描画上のオーバーラップ可否は §2.1.3-2 が規定する）。同時に開く画面は常に 1 つ（バニラと同型）。

#### 2.1.3 層の優先度と抑止

1. **演出層が最上位**——幕・綴じ画面・エンドロールの表示中は通知層の一過性通知（Title・Toast・HUD 小通知）を抑制し、キューイングして演出後に出す（幕の中に Toast は出さない——幕自体が通知であるため）。**字幕は抑止・キューの対象外**——字幕は一過性通知ではなく SE の同時表示名（45/04 §5.2 H-4：導線上意味を持つ SE は全て字幕表示名を持つ）であり、演出中に発生した音（柝・綴じ音・頁送り音等）の表示名を遅延・欠落させると、聴覚特性のプレイヤーの「音がある」検知チャネルが演出中だけ消失する（H-1）。演出内の SE は発生と同時に字幕が出る。
2. **画面層は 1 画面**——書物器を開いている最中に別器は開かない（バニラの画面排他と同型）。通知層（Toast・字幕）は描画上は画面層の上に重なってよいが（序列は抑止優先度であり描画順ではない——§2.1.1）、読み物を隠さない位置に置く（右下・上部端）。
3. **世界層は視線依存**——対象が視野外・照準外になれば消える（常時表示は由来札のコンフィグのみが例外＝U4-#9）。没腐コンパスの指しは同行者（ノミ）の身体動作として実現されるため、ノミが視界にいる間に機能する世界側の表現である（45/01 §2.2-9）。
4. **HUD 補助層は最小化**——常時の HUD 追加は行わない（没腐コンパスの指しは世界層のノミ動作が担い、HUD の針・マーカーは新設しない——45/01 §2.2-9・48/04 §4.3 不可表「HUD 矢印・浮遊マーカー」）。拍子キュー・照準ヒントは局面限定の二次補助（G-UI-22・G-UI-23）。

### 2.2 国スキン適用境界

**原則**：国スキンは「国にいる間だけ」適用、現実側の UI はバニラのまま（G-UI-02）。実装は次元判定によるリソースパック GUI 差替（48/04 §6）。

#### 2.2.1 適用判定規則

| 対象 | 判定 | 適用内容 |
|---|---|---|
| 世界クローム（コンテナ枠・HUD 枠・ボスバー枠等の GUI 装飾） | **所在次元**で判定 | 国次元にいる間＝国スキン（欠けた矩形・継ぎ目・基調パレット）。現実次元＝バニラのまま |
| 書物器の装丁（手記・図鑑・村報・予告頁・綴じ画面） | **器固有**——所在次元に依らない | これらは「物の見た目」でありアイテム固有の装丁を持つ（バニラの記入済み書物が現実でも本の見た目を保つのと同型）。現実で手記を開いても国の装丁——器は次元スキンではなく物の顔 |
| フォント（系統の登録） | 系統ごと固定・**登録は全次元で有効** | 「フォント系統は所在次元に依らない」＝**フォント ID（`understory:*`）の登録が全次元で有効**の意——登録の有効範囲の話であり、各表示がどのフォントを**選ぶ**かは下行（情報チャネル）の次元判定に従う。幻想文字は国の物にのみ出る（器側の選択——48/04 §2） |
| 字幕・由来札・照準ヒント（情報チャネル） | 機能は次元非依存・**スキンは次元判定に追従** | 表示機能はどの次元でも働く。**フォント選択も次元判定に従う——現実側＝バニラ既定フォント・国側＝本文フォント `understory:body`**（G-UI-02「現実側はバニラのまま」との整合）。枠・背景のスキンも所在次元に追従。書物器内部（手記・図鑑等の頁面）の表示は器固有の装丁として次元に依らず各系統フォントを適用する（上行「書物器の装丁」） |
| 通知音 | 質感は全編統一 | 「かすれた・古い」質感は現実側でも変えない（国の物が届く時の音は国の音——20 §7） |

#### 2.2.2 境界の白黒

- **可**：国次元での全 UI 装丁・フォント・遷移・色味の変更（法典 §4.2）。
- **不可**：現実側への国スキン漏出（クローム類——法典 §4.3「現実側での国 UI スキン適用」）。
- **裁定の明記**：書物器の装丁は器固有として次元非依存と裁定——世界クロームの次元判定とは分離して扱う（本節 2.2.1 表の二分法。要承認＝18-U1-Q4 へ記録）。
- 死亡・帰還・転移の瞬間は次元切替に追従——クロームスキンは次元変化イベントで切り替わる。

### 2.3 遷移言語

**原則**：開く・閉じる・戻るは全器で同一（P-UI-02・P-UI-06）。閉じる操作は常に有効——読み損ねを構造で潰す。

#### 2.3.1 基本遷移（全器共通）

| 操作 | 入力 | 挙動 |
|---|---|---|
| 開く | 右クリック（使用）／対象ブロックへ照準＋使用キー | 書物アイテム＝手に持って使用。掲示板・台・箱＝ブロック操作。バニラ書物・容器と同型 |
| 閉じる | ESC／インベントリキー | **全器で常時有効・例外なし**。アニメーション中（頁めくり・かすれて現れる途中）でも即座に閉じる |
| 戻る | 頁戻しボタン／右クリック領域 | 書物器内の階層戻り。最深は一覧（目次）まで——戻る操作のスタックは器の階層と一致 |

#### 2.3.2 閉じて再開可能原則（K3 の拡張——P-UI-02）

- **全ての読み物・演出画面は閉じて再開可能**：結末綴じ画面（K3 確定）・予告頁（U1-#1）・エンドロール（48/01「いつでも閉じられる・再演可」）・手記・図鑑・村報——閉じても内容は失われず、同じ状態から再開する。
- **再開時の状態保存**：綴じ画面＝選択途中の状態を保持し再度開ける（頁の帰還＝座の境へ——K3）。書物器＝前回の頁で開く（栞・帯が再開点を示す——§1.2.1）。
- **強制表示・自動進行の禁止**：プレイヤー操作なく内容が消える読み物を置かない。表示時間が問題になるのは一過性通知のみであり、その数値は §2.6 が確定する。
- **頁めくり中・語り再生中の閉じる**：アニメーションを中断して閉じる。再生済み部分は記録され、再開時は同じ頁から。
- **マルチ**：綴じ画面の開閉は個人単位——他者の画面を開閉しない（32 §6）。

#### 2.3.3 遷移の例外（幕・暗転）

幕転換（暗転＋間）は**UI の開閉操作の対象外**——演出時間規格（38/03 §4.3）に従って自動で進行し、閉じる・スキップの UI 操作を受け付けない。**ただし身体入力（移動・回避）は奪わない**——幕は演出層でありプレイヤーの身体は制限しない（§4.3.2-2 と同規定。攻撃等の動詞が進行に寄与しない局面は正典規範どおり）。ただしエンドロール/PC は「いつでも閉じられる」（48/01）——演出画面でも閉じる権利は残る。幕の暗転とエンドロールの違い：暗転は世界側の転換（全員に同期）であり、エンドロールは個人の画面再生（閉じてよい）として分ける。

### 2.4 入力規則

**原則**：前提操作は七つの身体動詞＋既存バニラ入力のみ（45/04 A-0・P-UI-09）。新規キー・新規操作体系の追加は不可（G-UI-01）。

#### 2.4.1 動詞 → 入力写像（確定）

| 身体動詞 | バニラ入力 | UI 側の受け口 |
|---|---|---|
| 近づく | 移動（WASD） | 接近時の由来札・気配表示の発火条件 |
| 拾う | 接触／使用 | 拾得物の獲得・拾得通知の発火 |
| 置く | 設置／ドロップ | 台座・箱・ゴミ箱への投入（容器操作） |
| 撞く（鳴らす） | 使用／攻撃 | 鐘・音符ブロック（A-0 の正典写像——45/04 §2.1。名付けの台は含まない） |
| 乗る | 使用 | 座れる構造物 |
| 坐る | 使用（照準時ヒントが補助） | 「観客になる」等の局面動詞——環境誘導一次・照準時最小表示は二次フォールバック（G-UI-23・H12） |
| 開ける | 使用 | 書物・箱・扉・蓋・**名付けの台**——全器の開操作。名付けの台は「命名器を開く→名を書き込む→確定」の書き込み系手続（48/04 §4.2・23 §3.3・38/02 §3.6.4②・34/06 §3.2——台は平時の手続。戦闘中のその場命名は台を用いない別手続③として §4.2.1 が扱う） |

※「名付けの台の起動＝撞く」は正典に存在しない写像（A-0 の撞く＝鐘・音符ブロックのみ——45/04 §2.1）のため確定表から除外する。「撞く」で儀式を開始する案は身体動詞語彙の拡張（正典変更）にあたるため、確定表には置かず 18-U1-Q6 として記録（推奨＝不採用・現行の「開ける/使用」写像で確定）。名付けの台の器規格（アンビル型命名器の国スキン器）は H19＝U3 §4.2 が担当。

#### 2.4.2 UI 内操作

- 書物器内の操作は**「読み・選び」の範囲**：クリックによる頁送り/戻り・選択肢のクリック——バニラ書物の操作体系を超えない（法典 §4.1-1）。頁送り部位の長押しによる連続めくりは同一入力の反復として扱う（§1.3.2 裁定——採否は 18-U1-Q2 の確定対象）。
- 名付け入力はバニラ命名器（看板/アンビル型）の入力——台への起動は「開ける（使用）」、器内はキーボード文字入力のみで、操作は不変（48/04 §4.2・23 §3.3・38/02 §3.6.4）。器の規格表自体は U3 §4.2（H19）が定義する。
- マルチで他者の画面操作・画面強制は行わない。

#### 2.4.3 ヒントの位置づけ

操作ヒント（「坐る」等）は**環境誘導が成立しない場合の二次フォールバック**としてのみ設計する——照準を合わせた時だけ出る最小表示。常時ヒント・チュートリアル画面・操作説明テキストは置かない（P-UI-09・45/04 P-1・U4-#1）。

#### 2.5.2 通知の優先度とキュー

1. **幕（演出層）＞綴じ画面＞Title＞Toast＞HUD 小通知**。演出中のこれら一過性通知は演出後にキューから出す（§2.1.3-1）。**字幕は本キューの対象外**——SE の同時表示名として発生と同時に表示し、演出中・画面閉じ中を問わず遅延・欠落させない（§2.1.3-1・45/04 §5.2 H-4/H-1）。ただし 05 章の無音区間は「音がないこと」自体が演出であり字幕も出さない確定規則（§1.5.2）が上位に立つ。
2. **同型通知は集約**——連続拾得は 1 件に集約（「○○ ×3」）して表示を溢れさせない。
3. **持続型気配は時間で消えない**——「新頁あり」「折れ目」は読了まで残る（状態表示であり通知ではない——時間切れを起こさない）。

### 2.6 テキスト表示規則（読み上げの間の確定値——H11 着地）

**原則**：全年齢で読み切れる時間を担保する（P-UI-02・53 §2.4）。数値の委譲を受けて本書が確定値を持つ（P-UI-10——以下は推奨案、承認で確定＝18-U1-Q1・Q2）。

#### 2.6.1 適用範囲の二分

- **読み手が速度を制御する器**（書物器・図鑑・村報・綴じ画面の本文）：**最低表示時間は設けない**——閉じて再開可能（§2.3.2）が構造の担保であり、読み上げの間は「頁が開いている間ずっと読める」形で実現される。
- **一過性・自動で消える表示**（字幕・Toast・Title・HUD 小通知・語り再生・自動フェード）：**式で最低表示時間を強制する**。これらは消えたら読み損ねになるため、時間で担保する。

#### 2.6.2 読み上げの間の式（一過性表示——推奨確定値）

**`T_min = T_base + N × τ`**（N＝表示文字数、上限 T_max あり）。全年齢向けに遅めの係数を取る：

| 係数 | 推奨値 | 意味・根拠 |
|---|---|---|
| `T_base`（基本時間） | 1.2 秒 | 出現を認知する最低時間 |
| `τ`（1 文字あたり） | **0.12 秒/字** | ≒8.3 字/秒——全年齢の余裕側（大人の快適読了 10〜20 字/秒の 8 割程度・BBC/Netflix 系の子供基準の系譜——53 §2.4） |
| `T_max`（上限） | 10 秒 | それを超える文は頁区切りで分割する設計側の義務（U2-R-6「朗読に耐える分量」と両立） |

#### 2.6.3 媒体別の適用値（推奨確定値）

| 媒体 | 保持時間 | 備考 |
|---|---|---|
| 字幕（独自 SE 行） | バニラ準拠（各行 ≒3 秒）。長い表示名は `T_min` 式に適合させる | 45/04 §6 #2——サイズ拡大はコンフィグ。**抑止・キューの対象外——演出中も常時表示（§2.1.3-1）** |
| Toast（拾得・解放・頁追加・気配着弾・綴じ片入手） | `3.0 秒 + 0.12 秒×文字数`、上限 6 秒 | FromSoft 型の短い通知側 |
| Actionbar/HUD 小通知（死亡遺留物・最小 1 行通知） | 2.5〜3.0 秒固定（短文のみ） | 連続拾得は集約（§2.5.2-2） |
| Title（章名・重要告知） | フェードイン 0.5s＋保持 `1.2s + 0.12s×文字数`＋フェードアウト 0.5s | 配信視点の視認要件（P-UI-08）に適合する大きさ |
| 照準時表示の消滅フェード | 約 0.3 秒 | 照準を外した時の消え方（§5.3 の器に適用） |
| 語り再生（ノミ語り・予告頁の語り） | 読み上げ音声の長さに同期＋終了後頁は残る | 音声なし時は `T_min` 式を頁単位で適用後、自動では送らない（手でめくる） |
| エンドロール「残した者たちの頁」 | 1 頁あたり **5〜6 秒**（10〜15 頁 × 5〜6 秒＝60〜90 秒——48/01 U1-#3 の確定値を確認値として引用） | いつでも閉じられる・再演可・**自動頁送りは演出画面の器規格どおり（§2.6.4 参照——読み物器の自動送り禁止とは別系統）** |
| 頁めくりアニメーション | 0.30 秒/頁・連続 0.18 秒/頁 | §1.3.1 と同値。連続めくりは同一入力の反復（§1.3.2 裁定——採否は 18-U1-Q2 の確定対象） |

#### 2.6.4 自動送り・特殊ケース

- **読み物に自動送り・強制送りのテキストは置かない**——書物・手記・語り頁等の読み物器は読み手がめくる（「読み損ね」を構造で潰す原則の裏面＝強制もしない）。**演出画面の自動頁送りは本項の適用外**——エンドロール「残した者たちの頁」の自動頁送り（頁10〜15枚×約5〜6秒＝48/01 §4.4 U1-R-5・§7-#3 承認済みの確定値）等は演出画面群の器規格（§4.4＝U3 担当節）に従い、停止・送り/戻し・閉じるは常時有効（48/01 §4.3 U1-R-4・本書 §2.3.2）。両者の分岐基準：読み物器は「頁が開いている間ずっと読める」器、演出画面は「記録の再生」器——いずれも閉じて再開可能であり、読み損ねは構造的に潰れる（P-UI-02）。
- **かすれた項・封印項は常時表示**——時間で消えない（存在の可視が仕様——K3・45/04 P-2）。
- **マルチの個別層**：表示時間は各プレイヤーの端末で独立に計算（他者の読み速度に引っ張られない）。
- **読み上げの間の最低保証**：一過性表示を読み損ねても、全ての内容は書物器・図鑑・記録頁へ着地する（読み返せる＝P-UI-02）——通知は「あることを知らせる」までの役割であり、本文の唯一の置き場にしない（G-UI-04 とも整合）。
