### 0.2 対象範囲

- **実装の各論**——計測ロガー・パック製造・掲載 CI 等の実装は Issue #13 系・実装フェーズへ手渡す。

## 1. 公開段階設計

### 1.1 段構成の全体図

公開工程は以下の直列＋循環で構成する（先行慣行「内部テスト → 限定招待 → 公開アルファ → ベータ → リリース」——docs/60 §1.2——に本作の検証3層〔L2/L3——docs/41〕と章構造〔P-RL-01〕を重ねた形）：

```
（Phase 2 スライス工程：S0〜S5／M0〜M5——docs/40 §6.2-6.3）
   │
   ▼
段 A  L2 限定招待 ──────→ 段 B  L3 限定公開配信 ──→ 段 C 公開アルファ ──→ 段 D ベータ ──→ 段 E 正式リリース
（非公開・検証層）        （限定公開・検証層）         （alpha チャネル）     （beta チャネル）   （release チャネル）
   │                        │                        │                    │                │
   └──────── 判定入力を供給 ──┴─ docs/41 §10.2 ─→ G-3 可否判定        章追加リリースが    段 F 章追加リリース
                                                    → G-4 解禁判定        本段の駆動単位      （循環：正式後も継続）
```

- **段 A・B は公開ではなく検証の段**——しかし公開工程の列に含める理由は二つ：① L2/L3 の成果が公開アルファ可否判定の入力そのもの（docs/41 §10.2）であり、② L3 の限定公開運用が D-7 サーバーイベント主経路の雛形（docs/40 §9「限定招待運用＝D-7 の雛形」——P-RL-09）。段 A・B の実施運用の正本は docs/41 に留め、本書は段の位置づけと成果の消費のみを設計する。
- **段 C（公開アルファ）が公開の起点**——解禁判定（§2 G-4）を兼ね、以降は不特定多数が到達し得る領域になる。
- **段 F（章追加リリース）は循環段**——段 D（β期）の駆動単位として各章の公開を担い、正式リリース後もポストゲーム等の追加単位として継続する（P-RL-01）。

### 1.3 収録範囲の境界

各段の収録範囲は**スライス端到端（OP〜序〜第1章〜村〜帰還——40-Q1）を基準線**として定義する：

- **段 A・B・C＝スライス範囲そのもの**：アルファがスライス範囲を超える要素（スライス外台帳 docs/40 §7 の項目——第2〜5章・終章・響界・ポストゲーム・ボス再戦・名づけ派生等）を含まないことを境界とする。スライス内で実装済みの全要素（月下の小島・マルチ機構・配信モード config 等）はアルファに含む——「検証済みのものだけが出る」が境界規則（40-Q2 承認済みのマルチ実装は専用サーバー動作＝D-4⑤ の実演でもある）。
- **段 D＝スライス＋追加済み章の逐次拡大**：追加は 1 完成塊ずつ（§2.5 の公開判定を通ったもののみ）。
- **段 E＝全章収録**：収録下限は要承約 43-U1-Q6 の決裁に従う。
- **言語の境界**：スライス期の検証言語は日本語のみ（42-U2-Q1——英語版は Phase 4 で範囲確定）。公開アルファ時点の言語対応は正典未確定のため要承認 43-U1-Q2 とする。正式リリース時の言語範囲は Phase 4 の確定値に従う。

### 2.0 ゲートの記法と共通規則

- 各ゲートは「発火条件 → 判定者（誰が）→ 判定入力（何を見て）→ 記録先（どこへ記録）→ 判定出力と経路」の5要素で定義する（P-RL-04/06）。「時期が来たら考える」型の記述は作らない。

- **参照ゲート**：G-1・G-2 の判定手順の正本は docs/41——本書は段列の連続性のために位置と条件を引用のみで記す（G-RL-11）。

### 2.9 判定保留・不可時の経路

- **保留**（入力欠測・前提未着地）：欠測・未着地の内容を判定票に明記し、揃った時点で同一ゲートを再判定。待機中も他工程の進行を止めない（docs/41 §8.4「判定保留中の工程」のモデルに準拠）。
- **不可**（公開形の見直しが必要な判定）：ユーザーへ選択肢を提示する。選択肢の枠組みは docs/40 §6.5 の外挿超過時選択肢（章規模削減・分割リリース・制作期間見直し）を公開工程側へ適用したもの——①章規模の削減（公開単位を小さく）②分割リリース（段を増やす・刻みを変える）③制作期間の見直し（公開時点の再設定）。正典・面白さの方向性に関わる見直しはユーザーのみが裁定する（docs/40 §5.4 ⑤正典層と同型——G-RL-12）。
