## 1. 音設計の骨格

### 1.1 層モデル

本作の音は**三層モデル**で設計する。

| 層 | 内容 | 代表例 |
|---|---|---|
| **世界音層** | 環境に実在する音。減衰・遮蔽・響界の対象 | 環境床（波・林の静まり・拍子）・世界内 SE（鐘・門・クレーン・モブ音） |
| **器音層** | プレイヤーが持つ器・UI が返す音。個別層・本人のみ | 書物器の頁・封切り・拾得通知・羅針盤・掌サイズの鐘・鳴る楽器 |
| **楽曲層** | 非定位の楽曲・歌 | 次元環境楽曲・章テーマ・ボス曲・歌姫の歌・読み上げ BGM・レコード |

加えて**演出音**（幕切れ・転移・救出復帰・結末の一音）はイベントとして世界音層に発火するが、共有層で全員に同期して届く。

**層の機械的判定**：登録表 §3 の「層」列が各行の層帰属を一意に定める（カテゴリ→層の写像は §2.2）。これにより 05 環礁の消音規則・響界内フィルタを行単位で適用できる。

### 1.1.1 汀・無音区画での層別扱い（05 環礁）

05 環礁（歌姫の汀）では、響界外では世界の音は「実在しない」。統一機構は**発火抑制**——音が発火しない＝再生も字幕も出さない（G-AU-03「無音区間は字幕も出さない」）。バスミュート（音だけ消して字幕を残す）や空間減衰は要件を満たさない。

| 対象 | 汀・無音区画での扱い |
|---|---|
| 環境床 | バス即時消音（汀侵入＝床が止まる演出そのもの） |
| 世界 SE（定位・非定位） | **発火抑制**——再生・字幕とも出さない |
| 楽曲 | バス即時ミュート（05 章は楽曲なし特例——§6.2） |
| 器音層（UI 操作音） | **残る**——書物器・器の操作はプレイヤーの手元の音であり、消音の対象外（ただし器音のうち世界に発するもの＝鐘・楽器・拾得トークン環境鳴動は世界音層として抑制される。器 UI だけが残るか、響界内の器音まで抑制するかは **19-U1-Q2** の係留） |
| 字幕 | SE が発火しない以上、字幕も出ない（無音演出の一部） |

### 1.2 質感規範

全ての独自音は「**かすれた・古い・捨てられた**」質感で統一する（docs/20 §7・G-AU-06）。

| 領域 | 帯域 | 残響 | ノイズ | 根拠 |
|---|---|---|---|---|
| **第一領域（器音・UI）** | 中域主体・高域は擦れ成分のみ | 短い（0.3〜1.0s） | 紙擦れ・木軋み・接触ノイズ | 18 §1.5.1 パレット |
| **第二領域（世界音・環境）** | 低〜中域・章固有の音色 | 環境依存（汀では吸収） | 風・水・機械・拍子の環境ノイズ | docs/34 各章・§4 章別表 |
| **第三領域（原案・座の気配）** | 高域の澄んだ残響 | 長い（4s 超可） | ノイズを排す——**泛音・純音系** | **19-U1-Q4**（推奨＝泛音純音系の「第三の質感」） |

第三領域は「座・原案・名の残る部位」など世界の深部に属する気配のための音色帯で、かすれの一般則に対する唯一の例外候補（採否は 19-U1-Q4 決裁）。

### 1.2.1 「無い音」の設計

音がないこと自体が演出である局面は**登録しない**（SE 行を持たない）：

- **音無しの靄**（N-MOB-006）：接近音を登録しない——音がないこと自体が正体（19-U2-Q6 推奨＝無音維持）
- **揺れて鳴らない鐘**（05）：発火しない
- **無音の頁**（06）：頁自体に音はなく、鐘・楽器・拾得物の応答が問いへの返答となる
- **05 の汀・響界外**：全消音（§1.1.1）

例外として「**無音への遷移**」（沈黙の域への侵入の一拍）は機構の可読性のため C6+C7 ペアが必要であり、`understory.event.silence.dome`「音：消える」として登録する（§3.2）——無音区間そのものではなく境界の一拍のみが対象。

### 1.3 多重化算入規則（C6+C7 ペア）

45/04 §5.2 の算入規則どおり、**C6（音）＋C7（字幕）はペアでのみ算入**。音声メディアのない SE は C6+C7 で 1 系統を構成し、視覚系（C1/C2/C4/C5）と合わせて最重要動作は 3 系統・主要は 2 系統を満たす。

- 字幕登録対象＝**意味を持つ SE**（45/04 §5.2 列挙：遠い汽笛・打鍵音・紙擦れ・拍子・鐘・没腐の歪み音・異物の気配音・頁めくり・ゴミ箱投入音等）
- 意味を持たない装飾音・楽曲は字幕対象外
- 字幕名は §3.6 の台帳が唯一の権威（新規名は「新規」印つき）

## 2. 実装規格（sounds.json・カテゴリ・減衰・定位・発火）

### 2.1 sounds.json

- 配置：`assets/understory/sounds.json`
- 形式：SoundEvent 登録（`"category"`, `"subtitle"`, `"sounds": [...]` 各項目に `stream`, `volume`, `pitch`, `attenuation_distance`）

#### 2.1.1 SoundEvent ID 命名規格

```
understory.<領域>.<主体>.<動作>
```

| 領域 | 値 | 対象 |
|---|---|---|
| `ui` | UI 層の器音（書物器・通知・語り） | §3.1 前段 |
| `world` | 世界内定位 SE（装置・器機・箱・鐘・手持ち品） | §3.1 後段・§3.3 |
| `event` | 演出イベント（幕・転移・救出・門・結末） | §3.2 |
| `mob` | モブ・ボスの音 | §3.4 |
| `ambient` | 環境床（疑似ループ） | §3.3 各章床行 |
| `music` | 楽曲・歌・読み上げ BGM | §6 |

字幕キー：`subtitles.understory.<領域>.<主体>.<動作>`（ID から `understory.` プレフィックスを除いたもの——18 §5.6 規格）。

> **ID 一元化注記**：本書の `understory.*` が唯一の SoundEvent ID。素材表（§7）の `SE-*`/`MU-*` は発注用素材 ID であり、§3 の対応列で SoundEvent ID と突合する（実装上は `sounds.json` の ID のみが存在する）。

#### 2.1.2 stream 規格（19-U2-Q1 の推奨案として本文はこれで統一）

**採用推奨（19-U2-Q1）**：疑似ループ方式——`stream:true` は**楽曲（music 領域）と 4 秒を超える単発イベント音のみ**に限定し、環境床・周期音・ループ演出は全て `stream:false` の疑似ループ（短〜中尺素材の間隔再発火または連続ループ再生）とする。

| 種別 | stream | 方式 |
|---|---|---|
| 楽曲・歌（music 領域） | true | 全尺ストリーム |
| 単発イベント音 >4s（終幕一打ち・結末鐘・幕間大鐘等） | true | 1 回再生のストリーム |
| 環境床（ambient 領域） | false | 10〜30 秒素材を環境床コントローラがフェード重なり再発火（§2.4） |
| 周期音（拍子 3s・打鍵 ~7s・鐘楼等） | false | 短素材の間隔再発火（ジッタ ±0.2〜0.4s） |

理由：バニラのストリーム同時本数は限られるため、複数環礁の床を stream で常時占有すると楽曲・長尺イベントと競合する。疑似ループはバニラ自身の環境音方式に倣う（docs/54 §3 H-12）。

### 2.2 カテゴリ割当

| カテゴリ | 割当対象 | 層写像 |
|---|---|---|
| `UI` | UI 操作返答・通知器音（個別層のみ） | 器音層 |
| `PLAYERS` | プレイヤーの動作音（手持ち器・クラフト・演奏・足音） | 器音層（個別）／世界音層（定位・共有のもの） |
| `BLOCKS` | 世界定位音（箱・鐘・門・クレーン・座・部位） | 世界音層 |
| `AMBIENT` | 環境床・非定位の世界広域イベント | 世界音層 |
| `HOSTILE` | 敵性モブ・ボスの音（戦闘聞き手対象） | 世界音層 |
| `NEUTRAL` | 中立モブ・ノミ・住人（非敵性時） | 世界音層 |
| `RECORD` | **レコード盤相当の楽曲のみ**（§6.5 の 3 枚） | 楽曲層 |
| `MUSIC` | 次元環境楽曲・章テーマ・ボス曲・読み上げ BGM・歌姫の歌 | 楽曲層 |
| `WEATHER` | 天候系（現在使用予定なし） | 世界音層 |
| `VOICE` | **保留カテゴリ**——歌姫声部・ノミ語り気配の帰属先として定義のみ（実使用は 19-U1-Q1 VO 方針の決裁に連動。VO 不採用なら該当行は NEUTRAL/UI に再割当） | 器音層または楽曲層 |

> RECORD を拍子キュー・幕転換・環境拍子に割り当てない——バニラでは RECORD は Music Discs 音量スライダに紐付くため、必須聴取音がスライダでミュートされる実害がある（P-AU-06）。

### 2.3 減衰と定位

#### 2.3.1 減衰帯域（目安・実装時の上限値）

| 帯域 | 対象 |
|---|---|
| 8〜16B | 器の細音・モブ接近音・拾得トークン気配 |
| 16B | 標準定位 SE（箱・門・名付け台等） |
| 32〜64B | 鐘・楽器・拍子・環境イベント（聞き手規則の対象音） |
| 96B 超・非定位 | 章ワイド演出（救出復帰・結末の一音・幕切れ）——減衰なしの共有層イベント |

#### 2.3.2 定位必須一覧（mono 収録必須）

定位を担う音＝**mono 収録必須**（stereo は定位情報を潰す）。以下は定位必須の正典要求音：

- 祭りの鈴（N-GEAR-3-01）・座共鳴・クレーン腕（警告・掴み）・迷子再提示・名の残る部位・羅針盤 3 音色・掌サイズの鐘・ゴミ箱（投入/着弾）・拾得トークン気配・招待状ポップ・歌姫の連（攻撃・フレーズ）・鐘類（径の鐘・大鐘・結末の一音）・門・楽器・モブ・打鍵環境・拍子床・ノミ気配・死亡遺留物気配

非定位（stereo 許容）は UI フィードバック・楽曲・共有層の幕演出のみ。

### 2.4 環境床コントローラ（自己完結・サーバー権威）

- **外部 mod 不使用**（P-AU-03）：環境床は自作の環境床コントローラで管理。バイオーム ambient 機構・外部ライブラリに依存しない
- **サーバー権威**（19-U1-Q3 推奨）：発火・停止・同期はサーバーが権威を持つ。クライアントは受信再生のみ
- 床は 10〜30 秒素材をフェード重なりでループ。複数環礁では主環礁の床のみ鳴動＋遠方環礁は定位の個別音のみ（混濁防止）
- 迷子再提示（一次チャネル）・救出復帰時の床復帰は §5.5 の順序に従う

### 2.5 発火・同期規格（19-U1-Q3 推奨案として本文はこれで統一）

- **サーバー権威発火**：全ての共有層イベント（幕・転移・鐘・救出・結末）はサーバーが発火点を定め、参加プレイヤーへ同時配信
- **聞き手判定**：鐘・楽器の発火者は半径 12B・±8 高低の響界内の者（正典値・§5.1）。響界内発の音の到達は**響界半径で頭打ち**（響界外へは届かない＝音の実在域が響界に一致）
- **共有/個別**：各行の層属性は §3 登録表の「共有/個別」列に従う
