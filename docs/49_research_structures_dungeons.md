## 2. 先行研究

### 2.1 黄昏の森（Twilight Forest）——次元MODの構造物体系の原型

「第二の黄昏の森」を目指す本作の直接の比較対象。構造物13系統の設計作法：

- **ランドマーク制**：全構造物はマジックマップに載る規模を持つ——「遠くから見えて、行ってみたくなる」ことが前提設計。構造物は探索の単位そのもの
- **型の使い分け**：迷路型（Labyrinth・Hedge Maze）／塔型（Lich Tower・Dark Tower・Aurora Palace）／広場・庭型（Naga Courtyard・Quest Grove）／洞窟・地下型（Hollow Hill・Yeti Cave・Troll Caves）／城郭型（Final Castle）。**型＝内部体験の約束**：塔なら登る、迷路なら迷う、広場なら対峙する
- **プログレッションロック**：Lich Tower は緑黄色の障壁でブロック破壊・攻撃を封じ、前段ボス撃破で開放——構造物自体が「進行の鍵」になる設計（本作は第2〜4章順不同のため採用不可——G4。代わりに「没腐の境界」「縁の民のいる場」が内側の進行制御を担う）
- **内部構成の実際**（Lich Tower）：中央尖塔＋周辺小塔が橋・直接接続で不規則に連結、二重螺旋階段で上下動線、破損した階段＝落下リスク、頂上にボス——「主軸＋枝部屋」の構造文法
- **報酬の置き方**：構造物ごとに固有の宝（エンチャント部屋・保管庫）＝構造訪問の動機を物語でなく実利でも支える

### 2.2 バニラ Minecraft の構造物型

| 型 | 代表例 | 設計の要点 |
|---|---|---|
| 直線階層型 | エンドシティ（塔＋枝）・砦の遺跡 | 主軸１本＋副室。導線が自明で迷わない |
| 網状型 | 要塞・廃坑・古代都市 | 部屋と廊下の非決定的連結。探す緊張＝報酬探索 |
| 単一宝箱型 | 寺院・沈没船 | 小型・構造より中身。玄関の仕掛け（TNT・罠）が全て |
| 集落型 | 村・前哨基地 | 構造物群の「系統配置」——個々でなく集合が意味を持つ。拾い人の村の直接の原型 |
| 試行場型 | Trial Chambers | jigsaw 構成の部屋群＋試練装置。構造とギミックの一体化 |
| 埋没型 | 砂漠の井戸・トレイル遺跡 | 「掘り当てる」構造——地形との境目が曖昧。本作の異物チャンク・埋まった坑道の参照 |

### 2.3 生成方式の技術実態（NeoForge / MC 1.21.1 想定）

構造物生成はデータ駆動（worldgen JSON＋.nbt テンプレ）が標準：

- **Structure Template（.nbt）**：構造ブロックで保存した建築単位。jigsaw 構造物の部品になる
- **Jigsaw 構造**：テンプレプール＋ジグソーブロックで部品を接続して成長させる方式。`start_pool`＋`max_depth`＋`template_pool`で構成（バニラ例：村・Ttrail Ruins・Trial Chambers）。**部屋の組み合わせに可変性を持たせられる**——本作の構造物（棄て物の集合）は jigsaw が実装上も世界観上も適合する
- **Structure Set**：構造物の配置規則（間隔・分離・バイオーム指定・確率）。構造物密度＝探索体験の骨格
- **Processor List**：生成時のブロック置換（石レンガ→ひび割れレンガ等の劣化処理）。「かすれた・欠けた」審美（G5）を構造生成段で出す技術的器
- **単一テンプレ型**：大規模固定構造（ボスアリーナ等）は jigsaw 化せず1個の .nbt でもよい——**可変性が要る部分だけモジュラー化**するハイブリッドが実務形

本書では全構造物に「生成方式」の欄を設け、①固定テンプレ（.nbt 単発）②jigsaw モジュラー（プール＋深度）③地形依存型（地形に食い込む埋没構造）④手組み領域（L3処理場＝プレイヤーが組む構造、docs/23 §8.3）の4型から選択・明記する。

### 2.4 ダンジョン設計原則（探索体験側）

- **遠望→遮蔽→開示**：構造物はまず遠くに見える（遠望）、近づくと全貌が隠れる（遮蔽）、核心に近づくと開示される——docs/45/01 の導線文法と同型を内部空間にも適用
- **分岐と回収**：深部へ進む本線＋引き返せる枝（見逃しへの寛容）——「取り残された場所」として本線を外れた枝部屋にこそ物語断片を置く
- **劇場化した中間**：最深部の手前に「中間の劇場」（ボス直前の静寂・準備空間）を置く——見得・幕（docs/48/03）の前室として機能。**各章で必置（16-U2-Q07 承認・Issue #2）**：01＝月読みの丘から摘み取りの丘の開示・02＝灯台灯室から座礁船の開示（docs/16 §2.2 の劇場規格と整合）
- **キーと文法ロック**：本作では「アイテムの鍵」でなく**文法の鍵**——拾う・捨てる・届けるの行為自体が進行を開く（ドアに鍵ではなく「届けられたものが開く」）
- **縦の劇場性**：塔は登る（垂直の緊張）、坑道は降りる（深さの不安）、広場は開く（水平の解放）——型と感情の一致
- **環境物語の密度**：構造内の断片配置は docs/45/03（環境物語）に従う——「誰が・なぜ・どう使っていたか」を空間の状態で語る

### 2.5 アクセシビリティ・導線の適用（docs/45 からの引用）

- 構造物の**発見**は非言語導線で完結（遠望のシルエット・光・音・匂いパーティクル）——文字・看板に依存しない（G2・G8）
- 構造物内部の導線は「片側開放」「向かい風」「最頻出の回収物」等の環境文法（docs/45/01 §2）で構成
- 迷子規則：構造内で迷ったときの回帰路（最後に見えた主軸への接続）を各構造物に1つ定義する（docs/13 迷子規則と整合）
- ボス戦構造物は見得の視認距離・逃げ場・リスポーン近接を確保（docs/38/03・docs/45/04）

### 2.6 「没になった場所」の構造美学

先行作における「廃墟の説得力」の条件：
- **用途の読み取れさ**：何の場所だったかが構造から分かる（灯台なら光の間がある、坑道なら搬出口がある）。本作の「没になった理由」は構造の**不完全さ**（書きかけ・壊れ・埋まり）で示す
- **住人の痕跡**：道具立て・生活の残骸が「誰かいた」を語る（03 の祭具・04 の検品票）
- **時層**：崩れ・埋まり・侵食が「あとから流れ着いた」時間差を出す——Processor による劣化置換の物語的運用

## 4. 設計原則（P-01〜P-09）

| ID | 原則 |
|---|---|
| P-01 | **構造物＝読む場所**：構造の状態（不完全さ・配置・道具立て）が没になった理由を語る。説明せず、見せる |
| P-02 | **遠望→遮蔽→開示**：全主要構造物は「遠くから見える→近づくと全貌が消える→核心で開示」の劇場性を設計する |
| P-03 | **器の明記**：全構造物に生成方式（固定/jigsaw/地形依存/手組み）と実装上の器（worldgen JSON・.nbt・processor）を記す。抽象論で終わらせない |
| P-04 | **順不同耐性**（第2〜4章）：構造物の前提関係を作らない。個別構造内のギミックは章内で完結させる |
| P-05 | **二状態設計**：全主要構造物に救済前/救済後（または結末後の殻）の状態を定義する |
| P-06 | **拾い人の村＝規格見本**：村の構造物群は本作の構造物設計の模範形（小規模・機能棲み分け・拡張余地）として最初に固める |
| P-07 | **命名の文法**：構造物名は正典の造語（「〜なかった〜」型・「没になった〜」型）に従い、呼ばれたくなる固有名詞化を狙う |
| P-08 | **配信の舞台**：各章に最低1つ「クリップになる構造」（外見の印象・内部の劇場）を必ず確保する |
| P-09 | **ギミック＝文法の具現**：構造物のギミックは新機構でなく、捨てる・拾う・届ける等の既存文法（docs/23）の空間的具現に寄せる |

## 5. 組版テンプレ（docs/16 の必須節構成）

成果物は `docs/16_structures_dungeons.md` 単一ファイル。以下の構成を厳守：

```markdown
# 16_構造物・ダンジョン設計書
## 0. 本書の位置づけと使い方
## 1. 構造物総覧表（全章） —— 必須列：名称｜所属章・領域｜型（迷路/塔/広場/洞窟/集落/試行場/埋没/特殊）｜規模（S/M/L）｜役割（主線/寄り道/報酬/拠点/補助）｜ボス・主関係者｜生成方式｜出典
## 2. 構造物設計の共通規格（§3 共通規格編の要約形）
   2.1 型体系と使い分け ／ 2.2 遠望→遮蔽→開示の劇場規格 ／ 2.3 二状態（救済前後・結末後の殻）規格 ／
   2.4 生成方式の選択基準（固定/jigsaw/地形依存/手組み） ／ 2.5 命名文法 ／ 2.6 導線・迷子回帰・ノミ収まりの共通規格
## 3. 序章・拠点・環礁共通構造物（U1）
## 4. 第1・2章の構造物（U2）
## 5. 第3・4章の構造物（U3）
## 6. 第5・終章・補助領域の構造物（U4）
## 7. 未決・要ユーザー承認
```

各**章別節**（§3〜§6）の内部は：①構造物一覧表（総覧表と同じ必須列）→ ②主要構造物の詳細カード。詳細カードは1構造物＝以下の10節テンプレ厳守：

1. 概要と役割（章内での位置・クリティカルパス上の位）
2. 由来と「没になった」理由（世界観的素性——G20）
3. 外観と規模（遠望での見え方・大きさの目安・シルエットの印象）
4. 内部構成（部屋・区域の割り振り——主軸＋枝部屋。平面の概念を言語化）
5. ギミックと仕掛け（文法の具現——P-09。構造固有の遊び）
6. 導線（発見→侵入→最深部への経路。遠望→遮蔽→開示の具体。迷子回帰路）
7. 演出・状態遷移（救済前/救済後の差・結末後の殻の状態・幻想文字の有無）
8. 収容物（拾得物・断片・ロア配置——中身の割り当て。数値詳細は Issue #15 へ手渡し可）
9. 生成方式（①固定テンプレ ②jigsaw（プール構成案・深度）③地形依存 ④手組み領域——§2.3 の4型から明記＋processor 劣化方針）
10. ボス・モブとの結合（戦場としての視認性・逃げ場・リスポーン近接——該当する場合）
