## 2. 先行研究

### 2.1 次回予告（アニメ/ドラマ型）の慣習

- **次回予告の発明意義**：視聴者に「次回も観る」動機を作る装置。内容は**声（セリフの断片）・色（印象色）・一場面（謎めいた断片）**の3要素で構成されるのが定石——「全部見せない・気になるだけ」が原理
- **慣習**：アニメでは15〜30秒。タイトル提示＋語り手がひとこと＋断片映像。答えやシーン全体は見せず、**好奇心の欠損**だけ残す
- **本作への転写**：ノミが語る「予告頁」＝声（次章の誰かの言葉の断片）＋色（次章の基調色）＋一場面（挿絵的一コマ）。実シーンを見せず挿絵と語りで構成する方式は Issue #31 で確定済み（U2-D/U4-#2）
- **考察機能**：予告に次章の手がかり（新キャラの影・キーワード）を混入させると考察班の材料になる——「答えは言わないが辻褄は合う」密度が条件

### 2.2 語り形式と「どう読ませるか」の先例

| 形式 | ゲーム内実現の先例・作法 |
|---|---|
| 絵本 | 挿絵主体＋短文の見開き。Minecraft では書物UI＋挿絵アイテムの組み合わせで再現（頁を絵に近い比率で使う） |
| 書簡 | 宛名・差出人・日付の形式美。封蝋・便箋の素材感が「届かなかった手紙」の悲哀を運ぶ（2章未読港との一致） |
| 戯曲 | ト書き＋台詞の構造。観客も「演じ手」にされる演出と相性（3章広場） |
| 日誌 | 日付の経過がそのまま時間の経過を運ぶ。乱れの演出（Biohazard 型、docs/24 §18 で確定の基本形） |
| 詩 | 行の短さ・余白が「欠け」を体現する形式 |
| 設計書 | 章の形式から外れる「異質文体」として配置済み（docs/36 §4.2・F-entries——落慮王・原案の座の系統） |

- **読ませ方の基本系**：世界に散った書き物を拾い読む文書回収型（docs/24 で採用済み）＋鑑賞層で「後から読み返す」器（U2 の主題）

### 2.3 歌舞伎の演出語彙（幕・見得・柝）＋ボス読み合い

- **見得（みえ）**：物語の重要な場面・気持ちの盛り上がった時に一旦演技を止めてポーズを取る。観客の注目を集める効果。種類は定型化されている：元禄見得（右手水平・左足踏み出しの力強い型）・石投げの見得・不動の見得（巻物＋数珠の不動明王型）・柱巻きの見得・天地の見得（高低2人同時）
- **幕**：開幕・幕切（幕が閉まる瞬間）。フェーズ転換＝「幕」として一瞬暗転＋間
- **柝/拍子木**：幕の開閉・「知らせ」（開幕・俳優到着）・「キッカケ」（セリや廻り舞台の合図）・「ツナギ」（幕が閉まった後、次の幕までの緊張感を持続させる連打）に使う。本作でも見得時の「ツケ」（打上げ＝幕切の見得に合わせてバタバタと打つ）が視覚合図として docs/38 で承認済み（U4-#8：拍子の視覚合図＝見得と同型）
- **ボス読み合いの先例**：予備動作を「読む」設計は Sekiro の危（危険漢字＋姿勢）・MH の溜め・Zelda の構えが定型——「予備動作を見得の定型ポーズにする」ことで、読み合いのフェア性と演劇の形式美を両立させる方針は docs/09 §2 で確定済み
- **幕間（まくあい）**：幕と幕の間の暗転。本作では docs/38/03 §4.3 で承認済み（幕間暗転＝各約10秒・間＝応答窓±0.40秒・キュー3.0秒）

### 2.4 序破急（じょはきゅう）のペーシング

- **出典**：雅楽→能楽の三段構成。序＝導入（静・遅）、破＝展開（動・転）、急＝結び（早・急）
- **本作への適用**：docs/09 §3 で確定——序＝漂着・探索、破＝没腐との対峙、急＝ボス＋結末。docs/34 各章に既に組み込み済み（例：01章「序＝1〜4の静かな探索、破＝5〜6前半、急＝ボス〜結末」）
- **詳細化の余地**：各場面の**時間配分比率**・章間での緩急の違い（章ごとの呼吸を変えると退屈しない）・序破急が壊れる境界（ボス戦中は探索に戻れない等）を定量化するのが U3 の仕事

### 2.5 エンドロール・ポストクレジットのゲーム先例

- **映画の慣習**：ポストクレジット＝「帰り道の余韻」＋次作/続きへの橋
- **ゲーム先例**：Mario Odyssey（スタッフロール自体がミニゲーム）・NieR:Automata（結末別の別視点ロール）・Undertale（登場人物の「その後」断片を順に流す）・ゼルダ BotW（後日談カット）
- **本作に決定済み**：結末別演出——拾う＝宛名のない届け物／書き換える＝新しい捨て場の影／見届ける＝終わりの後に届く最後の手紙（docs/36 T-PC・K9-K11 で承認済み）。「まだ拾われていない物語がある」示唆＝リプレイ導線（docs/09 §9）。docs/28 §145：救われた者たちが村にいる／灯台守が手紙を書いている／祭囃子の準備の一場面
- **詳細化の余地**：名の流し方（残した者たち・協力者名の体裁）・エンドロール中の操作可否・スキップ規則・一場面の長さ

### 2.6 ゲーム内暗号の先例（考察班向け）

| 作品 | 暗号の形 | 鍵の渡し方 | 学び |
|---|---|---|---|
| **Tunic（Trunic）** | 音素対応の独自ルーン（英語音素1:1対応） | 説明書の頁21・54が解読キー——頁を集める過程で鍵が揃う | 「読めない言葉に囲まれる違和感」自体が面白さ。鍵はゲーム内で配る |
| **ゼルダ BotW/TotK（シーカー文字）** | 英字アルファベットの換字表 | ゲーム内ヒントなし——ファンが総当たりで解読 | 形の美しさだけでも考察班は勝手に解く。文字は「雰囲気」として先に機能する |
| **ポケモン アンノーン** | ラテン文字の図形換字 | 文字自体が生き物——図鑑が対応表の役割 | 存在自体が謎の部品化 |
| **FEZ** | アルファベット換字＋空間パズル | 特定の部屋が「ロゼッタ石」 | 解読の達成感は「自分で気づく」こと |
| **原神（複数文字）** | 地域別の換字表 | 石碑に対応表が埋め込まれている | 「世界に対応表がある」作法——読む人だけが読める |

- **共通パターン**：①単純換字（monoalphabetic substitution）が標準——解読可能だが手間がかかる ②鍵はゲーム内に埋め込む（外部ツール必須にしない）③内容は**必読情報を置かない**（docs/36 §742 で確定済み——「辿り着いた者への握手」）
- **本作の条件**：環境文字＝「状態と数量のみ・固有名詞禁止（新規のみ適用・例外列挙）」（docs/26 §3.4・U3-Q2 承認済み）——幻想文字は環境文字とは別系統（装飾・刻印・最深部の書き入れ）として扱い、内容方針は承認済み（「没になった世界設計の断片」U1-新5/30-D/U4-Q1）
- **日本語か英語か**：観客は日本語話者中心——**ひらがな/カタカナ音節への換字**が自然（約50音＋記号）。字形数が多い分、デザインは「音節の形に体系性」を持たせる（母音列・子音行で部品を共有）

### 2.7 鑑賞層（読む・観る・聞く）の先例

- **収集型書物**：Hollow Knight の Hunter's Journal（倒した敵が図鑑に埋まる）・Animal Crossing の博物館・Patchouli 型の書物（Issue #22 D-2 で採用提案中——無くても遊べる soft dependency）
- **Tunic の説明書**：頁を集めることが進行と読解の両方に効く——「集める＝読めるものが増える」＝収集動機
- **教訓**：Destiny のグリモア（ゲーム外サイトに物語を置いた）の失敗——**鑑賞層はゲーム内に置く**。読み返し器はゲーム内書物で、外部 ARG は「ヒント」までに留める（docs/09 §5：宣伝サイトに解読ヒントを散りばめる構想は維持）
- **本作への適用**：「拾い人の手記」（読む物語）＋「拾得図鑑」（集める図鑑）＋語り形式別の視覚差（絵本は挿絵・書簡は便箋・戯曲はト書き——読むだけでなく「見る」差）

### 2.8 演出UIの線引き（ユーザー指針の法典化）

- **ユーザー指針（docs/09 §6 で確定）**：「語り形式が変わる際の演出UIはこっちでいじれると良い、ただしマイクラらしさは保つ。ちょっと見た目を変えるくらいはOK（例：国にいる間だけ枠の見た目が変わる）が、大きな変更は既存ユーザーのUXを損なう」→ **見た目のスキン的変更は可・操作体系の変更は不可**
- **先例**：ゲームが章・地域・文脈で UI の「皮」を変える作法は珍しくない（枠の意匠・フォント・色味の切替）が、操作体系（ボタン配置・入力方法・必須操作）を変えると学習が壊れる
- **線引きの仕事**：U4 は「可」の範囲を明示（枠・書物UI・頁めくり演出・幕間・結末綴じ・エンドロール・国の中だけの UI スキン）と「不可」の範囲（ホットバー/インベントリ/必須操作の体系変更）を白黒つけ、語り形式別に「どこまで皮が変わるか」の見本を作る

## 4. 設計原則（P-01〜P-08）

- **P-01 欠損の設計**：予告・語りも「全部見せない」——好奇心の欠損が次章/考察/リプレイの動機
- **P-02 形式美＝読み合い**：見得・幕・予告頁は定型化することで「読める記号」になる（形式が分かるほど読み合いが成立する）
- **P-03 器はマイクラ**：演出は「書物・頁・幕」のメタファーで統一し、バニラの器（書物UI・アイテム・暗転・音・パーティクル・挿絵）で実現。独自画面は最小限（docs/09 §11）
- **P-04 三層の視覚差**：読む（書物の内容）・観る（装丁・挿絵・形式の見た目）・聞く（BGM・効果音・読み上げの間）を別層として設計し、語り形式ごとに差を作る
- **P-05 集める＝読める**：鑑賞層は「拾うと増える」構造（拾得の楽しみと一致）。実績/進行連動の開放
- **P-06 線引きの明文化**：演出UIの可/不可は例外なく白黒つける。「場合による」は設計の失敗
- **P-07 暗号は贈り物**：必読情報を置かず、「辿り着いた者への握手」。解読できなくても欠落しない層
- **P-08 配信で成立**：予告・幕・ポストクレジットは「配信の締め/切り抜き」として機能すること（視聴者が一緒に読める）

## 6. レビュー基準

- **blocker**：正典（§3 G1〜G18）と直接矛盾（例：予告頁を実シーンに変える／操作体系を変える／必読情報を暗号に置く）
- **major**：章間の不整合・伏線受け渡しの欠落・規則未定義（例：ある章の語り形式だけ仕様がない・結末別演出の一つだけ詳細がない）
- **minor**：表記揺れ・参照ずれ・語彙の不統一
- レビューアは「正典の該当節を必ず開いて突き合わせる」こと（記憶で判定しない）
- 指摘には「根拠箇所の引用」と「修正案」を必須化。棄却する指摘にも理由を求める
- 「指摘0件で受理」も正当な結果
