# 調査報告書 02：成功MODの分析・市場・技術選定

## 1. 黄昏の森（The Twilight Forest）分析 — なぜ伝説になったか

2011年登場、現在も現役。**「新しい次元をまるごと追加する」という野心**と、その中身の密度で伝説となった。

### 成功要因の分解

| 要因 | 具体 | 学び |
|---|---|---|
| **世界のアイデンティティ** | 永遠の夕暮れ、巨大樹、蛍、霧。「異界に来た」が一瞬で伝わる | 次元は「見た目の約束」で勝負。色・光・時間の固定は強力な記号になる |
| **儀式的ポータル** | 花で囲んだ水窪にダイヤを投げ込む→雷が落ちる | 導入そのものが「儀式」。口コミ・配信で「やってみて」と言わせる瞬間 |
| **ボスゲート進行** | ナーガ→リッチ→モスラ系→…と、撃破で次のエリアの呪いが解ける | 探索自由度と進行秩序の両立。メトロイドヴァニア型ゲーティングの教科書 |
| **手作りダンジョン** | リッチタワー、迷宮、中空の丘。構造自体が冒険 | プロシージャルな地形＋手作りの「意味のある構造物」|
| **固有報酬** | 各ボスが固有ドロップ（テレポート杖、不死のトーテム等） | 報酬は「次の遊び方を変える」もの。数値の強化版ではなく新動詞を渡す |
| **物語めいた静けさ** | 明示的な物語はないが、荒廃した城・氷の城塞が「ここで何かがあった」と語る | 環境ストーリーテリング＝説明せず残す |

### 黄昏の森の弱み＝後継の隙

- 明示的な「ストーリー」がほぼない（含意に留まる）
- キャラクター性のあるNPCがいない（語りかける存在がいない）
- クラフト要素は薄め（主に探索・戦闘MOD）
- 章立て・結末といった「完結する物語体験」ではない

→ **「黄昏の森の世界構造」＋「物語・キャラ・クラフトの強化」が本企画の差分になる。**

## 2. 現代のヒットMODの共通項

| MOD | 規模 | 成功の本質 |
|---|---|---|
| **L_Ender's Cataclysm** | 約1億DL | ボスの「スペクタクル」。多段変形・画面埋める攻撃・読み合い可能なフェアな難しさ。ボス戦は「見せ物」として設計されている |
| **Create** | 2億DL超 | 「possibility space」。単純部品の組合せ爆発＋失敗が視覚で分かる物理＋Ponder(ゲーム内説明書)。解法ではなく道具を渡す設計 |
| **Alex's Mobs** | 1億DL超 | 90超の「個性ある生き物」。いるだけで楽しいマスコット性。実在動物+空想のバランス |
| **Aether** | 伝説級 | 「ネザーの反対側」という一目で分かるコンセプト。対になる世界設計 |
| **Botania** | 長期人気 | 「見た目と仕組み」が美学として一貫。花と魔力の独自文法 |

**共通項**: ①一目で分かる世界の約束、②学習可能な挑戦、③固有の新動詞を渡す報酬、④説明より発見、⑤単体で完成度が高い。

## 3. 市場：次元MODの隙

- 「新次元＋進行＋ボス＋物語」を現代水準で全部やるMODは実質空席。TFは現役だが設計は2011年の延長。
- 1.21.xでは新次元系の大型新作が少なく、**「物語駆動の次元MOD」は未占有のニッチ**。
- MCreator製の次元量産MOD（Elemental Dimensions等）は量はあるが「雑多な世界の束」で、一貫した世界観・物語を持たない。差別化余地が明確。

## 4. 配信者（YouTuber/VTuber）向け設計要件

調査で確認した実態：

- **イベント化されている**: 「ぶいきゃすマイクラ ドラゴンサバイバル」(35名のVTuber、MOD入りサバイバル、期間限定サーバー)、トーナメント型マルチ鯖企画など、MOD入りマルチサーバー＋期限＋目標の形式が実績ある。
- **耐久配信文化**: 長時間の攻略配信に耐える構造（章ごとの区切り＝配信1回のゴール）が求められる。
- **切り抜き文化**: 数十秒で「何が起きたか」分かる瞬間が二次拡散を生む。
- **名付け・愛着文化**: マスコット/同行NPCに名前を付けて愛でる文化（ホロライブのマスコット、にじさんじ等）。
- **マルチでの役割分担**: 探索班・素材班・戦闘班に分かれる構造が配信を豊かにする。

**設計要件としての結論**:
1. 章（エリア）ごとに「配信のゴール」を宣言できる進行構造
2. 名付けて愛せる同行NPC/マスコットを必須実装
3. ポータル儀式・儀式クラフト等「真似したくなる作法」
4. ソロ完結可能だがマルチで自然に役割分担が生まれるギミック
5. 観客が「次何が起きるか」を一緒に予想できる、読みやすいストーリー提示

## 5. 技術選定（案）

| 項目 | 推奨案 | 理由 |
|---|---|---|
| **MCバージョン** | 1.21.1（後に最新安定版追従） | MODエコシステムが最も成熟している現行系。TF/Cataclysm/Createの主要ターゲット |
| **ローダー** | **NeoForge** | 大型コンテンツMOD（次元・ボス・構造物）はほぼNeoForge系。TFもCataclysmもNeoForge。Fabricはクライアント/軽量系が中心。将来マルチローダー化は可能だが初手はNeoForge集中 |
| **言語** | Java 21 | MC1.21の標準 |
| **ワールド生成** | データ駆動（biome/dimension JSON + 構造物NBT） | 現代の標準。調整・拡張が容易 |
| **ボス/モブ** | 独自AI（goal selector + カスタムステート） | Cataclysm的なフェーズ制御 |
| **ドキュメント** | 設計書＋ADR 方式（kakeibo工程踏襲） | 本プロジェクトの大方針である「徹底設計」を制度化 |
| **配布** | Modrinth + CurseForge、英語/日本語対応 | 配信者が見つける主要経路 |

## 6. 規模感の現実

- TF/Cataclysm級は**数年規模のプロジェクト**。「第2の」を目指すならスコープを段階化する：
  - **MVP（垂直スライス）**: 次元＋第1章＋ボス1体＋儀式導入 — ここで「面白い」を証明
  - **その後章を追加**: 計5〜7章構造を想定し、章は独立追加可能なアーキテクチャに
- 1章を「最高品質」で作り切る方が、7章を薄く作るより第2のTFに近い。
