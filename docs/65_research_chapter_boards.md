# 65_Issue #11 調査基準：章ボード（絵コンテ）の制作規範（docs/51_chapter_boards/ の物差し）

> **目的**：Issue #11「各章ストーリーボード（docs/51_chapter_boards/）」に先立つ調査基準。docs/51 は**「物語の内容を書く」のでなく「画面・音・行動・感情を時系列で固定する演出設計書」**——docs/50 のビート形式を各章へ展開し、実装者・演出者・配信者が同じ絵を見られる一次入力を作る。本書は全制作・レビューエージェントが共有する**書式・正典制約・棚卸し・組版テンプレ**を一元化する。
> **先例フォーマット**：docs/62（a11y）・docs/64（ロア断片）と同型——先行研究・正典制約（G-CB-xx）・原則（P-CB-xx）・棚卸し（H-xx）・組版テンプレ。
> **承認ID規約**：本書系の要承認は `51-U{n}-Q{m}`（成果物 docs/51 の番号を取る——43-U・52-U・63-U と同じ文書番号系）。
> **範囲（docs/40 §9 承認済みの手渡しどおり）**：Phase 0 で作るのは**スライス範囲**——序・第1章・村・月下の小島のボード＋横断規格。**スライス外章（02〜05・終章）のボードは Phase 3 へ回す旨確定済み**。Issue 完了条件「全章のボード作成」はフェーズ跨ぎの総量として読む。

## 1. 先行研究（絵コンテ・演出設計の到達例）

正典が名指ししている参照系と、絵コンテ実務が教える作法：

| 先行 | 学ぶ作法 | 本設計での適用先 |
|---|---|---|
| **映像の絵コンテ（実写/アニメ）** | 1コマ＝1絵。「画面に何が・どこに・どの大きさで見えるか」＋音・間（秒数）・台詞を1枚に集約。読む人が頭に同じ絵を描ける粒度 | ボードのビート書式（画面・音・行動・感情・配信の見せ場の固定欄）。時間（間）を明記する——docs/50 運用メモ継承 |
| **BotW / 環境主導設計** | 演出は「見える場所からの逆算」——視線誘導・開示の順序を地形と光源で設計する | 各ビートの「最初に見えるもの」欄（視線誘導の設計順——34/00 §2.2 の型を全ボードへ） |
| **Half-Life 2 系** | プレイヤーの操作権を奪わない演出（カットシーンにしない——身体は動かせるまま世界が動く） | G-CB-03（バニラの器・操作体系不変）。ボードは「プレイヤーの行動」欄を必須にして主体性を保つ |
| **Journey / 感情曲線設計** | 章を1本の感情曲線（序破急＝静→動→急）として設計し、山場と静けさの呼吸を先に決める | 各ボード冒頭の「序列の目的」とビートの「狙う感情」欄。感情の勾配を横断で揃える |
| **歌舞伎・能（正典内）** | 幕・見得・柝・序破急——演目の形式美をゲーム転用 | docs/48/03 の幕三階層・見得4型・拍子キューをボードの演出欄へ引用（docs/16 §7.5 手渡しの幕間/転換/対峙シークエンス） |
| **Tunic / 実物資料** | ページ・挿絵・装丁を「作中の物」として設計する——器の規格と一体 | 予告頁・村報・手記の頁面をボードの「器」欄で docs/18 §3 の器規格へ接続 |
| **実況配信（本作のターゲット）** | 「切り抜き瞬間」を作る＝視聴者が声を上げるフレームを設計段階で固定 | 各ビートの「配信での見せ場」欄（docs/17 §3・各章 §10 の切り抜き瞬間を引き継ぐ） |

## 3. 制作原則（P-CB——ボードを「面白くする」作法）

| # | 原則 | 出典 |
|---|---|---|
| P-CB-01 | **説明しないで発見させる**——ボードは「プレイヤーが自分で気づく瞬間」の設計。演出は気づきの直前に配置し、答えは置かない | docs/50 序列の目的 |
| P-CB-02 | **狙う感情を先に宣言してから絵を決める**——各ビートの「狙う感情」欄を空にしない。感情が弱いビートは統合する | docs/50 運用メモ |
| P-CB-03 | **プレイヤーの身体を止めない**——操作権を奪う演出は禁止。暗転・幕は「呼吸の一拍」として短く（頁めくり0.3s・幕切れ≈2s の体感） | docs/48/03・HL2 先例 |
| P-CB-04 | **音と画面を同じ発火点に置く**——SE/楽曲/字幕はビートの「音」欄で画面の変化と同期させる。音先行（聞こえる→見える）で気配を作る | docs/19 §4〜§5 |
| P-CB-05 | **1配信1章のエピソード構造**——各章ボードに「配信の切り抜き瞬間」を最低1つ（できれば序盤・中盤・山場に分散）配置する | docs/17 §3・docs/40 §9 Issue #17 行 |
| P-CB-06 | **欠損を設計する**——全部見せない。気配・淀み・朧な光で「ある何か」を匂わせるだけに留める（明答度管理） | docs/48/01 §2.1・F-U4-P02 |
| P-CB-07 | **読みやすさはボード自身の品質**——1ビートあたりの文字量を絞る（実文は引用せず参照IDのみ）。絵の意図が3行で読める粒度 | docs/50 の簡潔さ |
| P-CB-08 | **マルチで破綻しない**——ボードの発火・同期は個別層/共有層の区分（G-CB-16）で書き分ける | docs/32 §6 |
| P-CB-09 | **救出後の差分は「色・音・気配」の三層で書く**——結末が「殻として再入可能」になる差分をボードの末尾に固定（G13） | docs/16 §4.1.2⑦・34 各章 §7 |
| P-CB-10 | **遠望は物語の装置**——見晴らしの岬・浜からの遠望・月下の小島からの視線を「世界の目次」として設計する（隠すのでなく見せて絞る） | docs/45/03 §3.1・P-02 |

## 7. レビュー観点（別エージェントへの指示仕様）

1. **正典整合**：ボードの場所・構造物・断片・音の引用が各正典の該当節と一致するか（記憶でなく開いて突合）。正典値の再定義・無断変更がないか（G-CB-01/10/12/22）
2. **書式適合**：§5 テンプレの必須節が全て埋まっているか。ビートに「画面・音・行動・狙う感情・配信の見せ場」が揃っているか（G-CB-02）
3. **演出の実現性**：バニラの器で実現できるか（G-CB-03）。操作を奪う演出・カットシーン化していないか（P-CB-03）
4. **層構造**：共有層/個別層の区分が発火対象に明記されているか（G-CB-16）。OP側に配置設計を書いていないか（G-CB-17）
5. **発火点の完全性**：docs/19 の章別 SE・docs/18 の通知型が全てビートへ着地しているか（H-09/H-07——欠落 SE の洗い出し）
6. **順不同耐性**：他章の未訪問情報・結末をボードに含んでいないか（G-CB-09）
7. **面白さ**：「狙う感情」が宣言され、配信の切り抜き瞬間が章に最低1つあるか（P-CB-02/05）。説明し切っていないか（P-CB-01/06）
8. **表示時間**：断片の頁区切り・間が docs/18 §2.6 の式で検算されているか（G-CB-11）
9. **マッチカット**：切り替わりの形式が「絵の連続性・音の反転・間の長さ」で定義されているか（H-06——曖昧な「かっこよく切り替わる」で終わっていないか）
