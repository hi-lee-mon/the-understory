# ADR（Architecture / Design Decision Records）

「なぜそう決めたか」を残す決定記録。コード・設計の「何を」は設計書が担い、「なぜ」はここに置く。

## ルール
- ファイル名：`NNNN_タイトル.md`（連番4桁）
- ADRは**immutable**：書いた後は本文を修正しない。決定を覆すときは新しいADRを作り、旧ADRのStatusを `Superseded by ADR-XXXX` に更新する
- 1ADR = 1決定。複数の決定を混ぜない
- **暫定値の実測着地時の ADR 運用（12-U4-Q1 承認・2026-11-03）**：暫定値を改版しない——着地記録は Issue #13 コメント＋各正典書（docs/40 §4.8/§5.2.2・docs/19 §6.1・docs/63 §4.5）へ書き戻し、ADR は「暫定値と着地規則の決定記録」として残す。閾値自体を変更する場合のみユーザー承認＋新 ADR（supersedes）
- **ADR 化トリガ（docs/42 §5.2→Issue #12 手渡し——12-U4-Q6 参照）**：緩和・対処の重要決定（例：収益化設計の方針決定時）・前提行の恒久確定時は ADR として記録する。新規 ADR は Status=Proposed で作成し、Accepted への昇格はユーザー承認を経る（ADR-0002 の前例——42-U4-Q6）

## テンプレート
```markdown
# ADR-NNNN: タイトル

- Status: Proposed / Accepted / Deprecated / Superseded by ADR-XXXX
- Date: YYYY-MM-DD
- Deciders: 65banseki + Devin
- Related: docs/XX（関連設計書）

## Context
この決定が必要になった背景・制約・論点。

## Decision
採用した選択肢と、その理由。

## Alternatives Considered
検討して却下した選択肢と、却下理由。

## Consequences
この決定による影響（良い面・悪い面・今後の制約）。

## Open Questions
未決・要承認事項の参照表（ID＋推奨案＋書き戻し先）。ない場合は「なし」と明記する。
```
