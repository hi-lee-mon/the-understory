# ADR-0008: マルチプレイ仕様 — 共有層の同時配信と個別層の見え方差分

- Status: Proposed
- Date: 2026-10-25
- Deciders: 65banseki + Devin
- Related: ADR-0004（上位決定——共有/個別のハイブリッド状態モデル）・ADR-0003（ゴミ箱主機構）・ADR-0005（入口2系統）・ADR-0006（次元生成方式——異物の個別層生成と連動）・ADR-0007（セーブ・状態同期——個別層の永続化側）・ADR-0009（パフォーマンス方針——D-2 合格ラインの T-7/T-8 測定基盤）・docs/32_system_specs.md §3.3/§4/§5/§6・docs/19_audio_direction.md §2.4/§2.5・docs/57_tech_verification_plan.md §4 H-06/H-15・§6 H-16〜H-19・§8（57-U2-Q11/Q12）・docs/40_vertical_slice_plan.md §4.4/§4.9/§5.2.2（T-5/T-7）・docs/23_discard_grammar.md §8.4〜8.6/§9/§11・docs/46_distribution_research.md §4.2/§6（D-7）・docs/17_streaming_design.md §3/§5

## Context

「1つの世界をみんなで歩く」本作では、物語の結末・村の発展を全員に同じ歴史として刻みつつ、「あなたが捨てたもの」だけを見る人で変える——ADR-0004 が確定したハイブリッド状態モデルの**配信側の仕様**が複数の正典に散在していた。「誰に何が見えるか」の細目は docs/32 §6、音のサーバー権威と ±100ms 目標は docs/19 §2.5、異物の可視性モデルは docs/57 §4 H-06、「他人を捨てる」儀式は docs/23 §8.5、サーバーイベントを配信の主経路とする流通要件は docs/46 §4.2/§6——これらが1つの決定として束ねられていなかった。

さらに配信者到達の主経路はサーバーイベント運用（D-7・docs/46 §6）であり、「専用サーバーで動くこと」は modpack 収録条件の必須項（docs/46 §4.2・docs/32 §9 条件⑦）である。マルチで動かなければ配信経路自体が断たれるため、単なる「マルチ対応可」では足りず、**サーバー前提の協力プレイを設計要件として固定する**決定記録が必要だった。

本 ADR は新規の設計判断を行わない。承認済みのマルチプレイ関連決定（ADR-0004・docs/32 §6・Issue #13 要承認28件のマルチ領域分・Issue #22 D-7）を「なぜそう決めたか」の記録として束ね、「誰に何が見えるか」を**判定可能な言語**で定義する（docs/68 §3 P-ADR-04）。

## Decision

マルチプレイは**サーバー前提の協力プレイ**とする——物語・村・結末は共有層で1つの歴史を刻み、個人差分は個別層で観測者別の見え方とする（ADR-0004）。以下の6件を採用決定として束ねる。

### D-1 協力プレイの状態モデル（出典：ADR-0004・docs/32 §6・docs/00 §3.1）

- 物語の結末・没腐の浄化・拾い人の村の発展・「書き換えた/見届けた」の記録は**共有層（ワールド）**——マルチで1つの歴史を刻む群像劇の蓄積（ADR-0004）
- **結末の決裁＝先着**——最初に「綴じる」動作をした者の結末が記録される。他者は「見届けた/書き換えようとした」として並記可能（docs/32 §6・J7 承認・K3/K7）。戦闘転換点は個人単位の戦闘離脱、頁全収集による勝利は世界の状態として全員の戦闘を終わらせる。「◯◯が綴じた結末」は共有層で全員に表示し、個人の図鑑にも「私が関わった」記録が残る。ボス再戦記録は共有層に「◯◯の記録」として残し、明細は個別層（拾得図鑑の再戦頁節）
- 村の発展は共有——誰かが救った住人は全員の村に現れる。後発加入者は済んだ章を「◯◯の手記の写し」書物で追体験する（死亡ロスト対象外——docs/32 §6・U2-N4・18-U2-Q6）
- ノミ＝一人一ノミとして全章・戦闘中を含め常時同行し、名付け帰属は名を付けた本人のノミ（docs/32 §6・K16）
- 宝箱・モブドロップ＝個別層で全員分（開ける者ごとに独立抽選。欠片等の世界一意品を除く——docs/32 §6・U4-9）
- マルチ係数：ボス HP×(1+0.5n)・月充填は1窓＝1段で人数非依存（docs/40 §4.4・docs/38/03 §4.2/§5）
- 月齢周期＝45秒（共有層の世界周期——空の月の充填を含め全員に同一の状態として進行する。マルチ係数ではない——docs/40 §4.4・docs/38/03 §4.2/§5）
- 環境一次導線（定点・勾配・ランドマーク）は共有層で全員同一の見え方とし、個別層の差分は表示のみ——迷った者は「先に進んだ者が物理的に導く」構造（docs/32 §6・U2-G）
- 頁所持者の可視化は共有層で「気配のみ」表示——綴じ画面の項の縁に「◯◯が頁を持っている」旨を添える程度（docs/32 §6・18-U4-Q11）

### D-2 個別層の見え方モデル（誰に何が見えるかの判定言語）

正典の個別層の定式は**2系統**——アイテム/表示は「実体共有・表示のみ個別化」（ワールド状態分岐は不可）、生成物は「個別層生成＝所有者別の内容分岐」（docs/57 §4 H-12/H-15・docs/16 §7.5・docs/32 §6・ADR-0004）。本 ADR は「誰に何が見えるか」を判定可能な言語で定義するため、個別層生成を視認軸（発見者のみ／全員に視認）で再区分した**3系統**として整理する（P-ADR-04——新規の分類体系ではなく、正典2系統の視認別再編としての判定言語化）。

1. **実体共有・表示のみ個別化**——由来札・拾得図鑑の個人収集・初回リアクション・招待状。実体はワールドに1つ存在し全員が見えるが、表示名・ツールチップ・届きものは観測者で分岐する：自分の物＝「あんたの物」、他者の物＝「◯◯の物」、未鑑定（由来不明の由来物——由来札の適用範囲は docs/18 §5.4 の列挙に従い、非由来物に由来札が出ないことはその列挙からの推論）＝「誰かの物」かすれ行（`understory:faded`）、鑑定済は接尾「——◯◯で捨てられた」が加わる4分岐（docs/32 §6・docs/18 §5.4/§5.9・18-U4-Q4・57-U2-Q9 承認）。招待状は所有者の箱にのみ届き1人1通——他人が先に開けても所有者にのみ見える（docs/32 §3.3・docs/18 §5.4）
2. **個別層生成・発見者のみ視認**——異物チャンク。「発見した人にしか見えない」を体験目標として採用（docs/32 §4.1-4.2・docs/57 §4 H-06）。**実現方式は暫定**——パケット偽装／エンティティ化＋描画差分の最小実装を Phase 1 スパイク T-U2-03a〜c で比較・計測して確定する（着地先＝Issue #13 検証記録・docs/40 §4.9 先行ゲート判定）。この前提が変わる場合の連鎖は Consequences の条件付き項（57-U2-Q11）を参照
3. **個別層生成・全員に視認（所有者帰属）**——「自分の区画」（共同堆積内）・「自分の捨て場」。所有者ごとの内容分岐を実体として生成するが、生成物はワールドに実在し全員に見える。区画の割当・生成は集約漂着統計からの決定論的生成（同じ統計なら同じ区画——57-U2-Q6 承認）。他人の捨て場は見学可。自由に拾えるのは無主の漂着物のみ——他人の物も「◯◯の捨て物」として由来を保持したまま取れるが、拾うと「届ける/返す」行為が発生する（取れるが、その物の物語が変わる——docs/23 §9・docs/14 宝物ルール）

**宝箱・モブドロップ（個別層で全員分——docs/32 §6・U4-9・docs/38/04 §4.3 N-ECO-803）**：箱の実体は共有で全員に同一として存在し、開ける者ごとに中身は独立抽選、モブドロップは近接者全員に別層で付与（全員分で先着争いを作らない——欠片等の世界一意品を除く）。他者の抽選結果・ドロップ品が観測者にどう見えるか（他人のドロップは見えるか）は正典未規定 → `12-U3-Q3`

**「個別層が動いた」とは**、以下の全項目が成立すること：(a) 共有層が全員に一致する（結末・村・環境導線・着弾の実体が全員同一）。(b) 系統1の表示が観測者別に正しく分岐し、他者の物が本人の物として現れない。(c) 系統2で非発見者には異物が見えず、当たり判定・音・採掘結果が破綻しない。(d) 系統3で所有者別の内容が正しく割り当たり、他者の区画に自分の物が混ざらない。(e) 全項目がセーブ/再ログインで永続化する。スライスの合格ライン＝T-4（永続化）＋T-5（個別層が他者に漏れず、共有層が全員に一致）（docs/40 §5.2.2・57-H-15）

### D-3 共有層イベントの配信精度＝±100ms 目標

共有層イベント（幕・鐘・祭囃子・結末・月の変化）は**サーバー権威で発火点を定め、参加プレイヤーへ同時配信**する（19-U1-Q3 承認・docs/19 §2.5）。クライアント間の再生開始差の目標＝**±100ms**（19-U4-Q4 承認・docs/19 §5.2）。超過時はローカル再生を優先し、遅延分はフェード扱いとする。**測定対象は共有層イベントの発火点配信のみ**で、個別層 SE は jitter 計測の対象外とする（57-U2-Q12・docs/57 §7.2——±15ms は暫定診断目標であり正典値ではない：docs/57 §7.4）

### D-4 配信層割当＝発火点は共有層・演出実体は個別層

イベントの「いつ・どこで」は共有層で配信し、「音・演出の実体」は個別層でローカル再生する（57-U2-Q12 承認——docs/19 §2.5 を揃正した正典改訂）。転移 SE 4件（`event.transit.*`）は転移者のみに再生され、共有層へ届くのは発火点の同期のみ（docs/19 §3.2）。個別層の音（器操作・個人通知）は各自ローカルで他者には届かない。環境床・共有層イベントの発火は外部 mod 不使用のサーバー権威コントローラが担う（19-U1-Q3・docs/19 §2.4——複数環礁では主環礁の床のみ鳴動＋遠方環礁は定位の個別音で混濁防止。PoC 最小構成は 57-U4-Q4 承認）。響界（鐘・楽器）の発火者は半径12B・±8高低の響界内の聞き手のみで、響界内発の音の到達は響界半径で頭打ち（docs/19 §2.5/§5.1・docs/38/03 §4.5——PoC の検証集合はプレイヤー・ノミ・救出済み住人の部分集合：57-U4-Q3）

### D-5 「捨てる→届く」の配信モデル

1人が捨てた物は**全員の世界（共有層）に届く**——これが「あなたが捨てたもの」機構の配信形。イベント系列＝投入（物は捨てた人に由来紐付——個別層）→国側への着弾（対象格に応じた着弾——docs/23 §11）→配置（物の実体は共有層として存在し、由来札は個別層表示——45/04 M-2。音の層割当は docs/19 §3.1 の登録に従う）→図鑑・住人記憶への記録（docs/23 §11 イベント体系・§9 帰属原則・docs/32 §6）。他人のゴミ箱に入れた物は入れた人の捨て場へ届く（箱は回線、荷物は送り主のもの——docs/23 §9）。スライスの実装形＝実データ駆動（現実側ゴミ箱投入→章アフィニティ→配置→由来札表示の端到端——40-Q19 承認）。処理場経由（L3 マルチブロック構造物）は「◯◯の処理場から来た」由来を保持して灼熱の埋立て地へ届く（docs/23 §8.4）。

**他人を捨てる**＝ごみ処理場のクレーンで掴んで投入口へ落とすことでのみ成立し、処理場という構造コスト全体が合意の閾値となる（逃走余地＝掴みの予備動作・音・警告）。落とされた側は死ではなく灼熱の埋立て地への転移＝特別エリアへの特権で、「◯◯に捨てられた」が記録される——記録の層帰属は正典未規定（共有層＝群像劇蓄積との整合は推論として `12-U3-Q4` へ起票。永続化構造は ADR-0007 の所掌へ接続）（docs/23 §8.5・docs/32 §5・docs/17 §3）。帰還は処理口（焼却炉の逆流口）から焦げ跡つきの片道（docs/32 §5）。対してデカいゴミ箱は「自分で入る」動作のみ——他者の押し込みでは転移しない（docs/23 §9）

### D-6 動作保証環境＝専用サーバー必須

「専用サーバーで動くこと」を必須要件とする（modpack 収録条件⑦・D-7 サーバーイベント経路の前提——docs/46 §4.2/§6・docs/32 §9）。マルチ機構は全実装する（40-Q2/Q19 承認）。検証＝第1層で2人同時接続の疎通＋個別層分離・係数確認（T-5/T-7）＋第2層でマルチ完走1ケースを観測項目とし、第3層（配信環境）の合格条件にはしない（docs/40 §2.9/§5.2.2・docs/32 §6 注記——第1〜3層は検証者層であり、docs/57 §7.1/§7.2 の「LAN 2人→専用サーバー」系列は検証環境層の別系列：docs/42 R-08）。LAN/ホスト開放を公式対応範囲に含めるかは正典で未規定 → `12-U3-Q1`

## Alternatives Considered

- **全員同一視認モデル（個別層なし）**：ADR-0004 で棄却済み——「誰の結末か」問題が残り、「あなたが捨てたもの」の個別化ができない（ADR-0004 Alternatives A）
- **全てプレイヤー個別**：同じく ADR-0004 で棄却——全員が別世界を見る設計は群像劇・共有村・協力構造と衝突し、表示分岐の実装も重い（ADR-0004 Alternatives B）
- **異物の可視性＝案C「全員視認＋初接触消滅」**：正典の代替案（docs/00 §3.1①・docs/57 §4 H-06）。一期一会を物理成立させるが「他者の異物を目撃した際の語りの方向性」を失い、承認済みの16-U1-Q14「使用後も残存・再入可能」と正面衝突する。採用時のみ改訂連鎖（57-U2-Q11）が発動する条件付き案として保留中（現時点は未採用——Phase 1 スパイク T-U2-03a〜c の判定待ち）
- **案B' クライアント側インジケータ差分**：サーバー配信の実体は同一で表示側だけ個別化する中間案——H-06 の比較記録に残す（docs/57 §4 H-06 設計代替）
- **イベント発火をクライアント側に委ねる方式**：各クライアントの時計で演出を再生する対案。発火点の一意性と多重再生防止のためサーバー権威が採用され（19-U1-Q3・docs/19 §2.4/§2.5）、以後の全共有層イベントに適用する
- **配信モードで演出の多重化・同時性を削る案**：40-Q20 により「暗転長のみを短縮し多重化は維持」と確定（係数0.6程度＝暫定・実測で微調整——57-U2-Q10）。同時性要求自体を緩める代替は正典変更に当たり採用しない

## Consequences

**良い面**

- 共有層で1つの歴史を刻むことで「◯◯が綴じた」「◯◯に捨てられた」の群像劇が蓄積され、個別層の見え方差分が「推しには何が見えたか」を各視点で追う配信文化に適合する（docs/17 §5・ADR-0004）
- ±100ms のサーバー権威同時配信で結末・月変化・幕の「同時に見せ場」が成立し、配信検証 S-4 の体感ずれを防ぐ（docs/40 §5.2.4）
- 専用サーバー必須の固定でサーバーイベント運用（D-7）の実装前提が明確になり、modpack 収録条件⑦を満たす（docs/46 §4.2・docs/32 §9）

**悪い面・今後の制約**

- **個別層同期はスライス最大の技術リスク**——先行スパイクで最初に潰す（40-Q15 承認）。個別層の漏洩不具合は主題装置を壊すため、永続化（T-4）と非漏洩・共有層一致（T-5）をゲート化（docs/40 §5.2.2・docs/42 §2.1 R-05）
- **マルチ検証＝2人構成**：第1層で2人同時接続の疎通＋個別層分離・係数の数値確認（T-5/T-7）、第2層でマルチ完走1ケースを観測項目（40-Q2・docs/32 §6 注記）。T-5＝複数アカウントで捨て場・拾得・由来札・先着結末の振る舞いを確認し「個別層が他者に漏れず、共有層が全員に一致する」。T-7＝専用サーバー2名で共有層イベントの同時性・ボス係数・先着結末を検証し、合格ライン＝共有イベント見え方差 ±100ms 目標の達成＋結末先着の一意性確認（docs/40 §5.2.2）。測定はサーバー送出 tick/時刻と各クライアント再生開始時刻の jitter 集計（docs/57 §7.2）
- **±100ms jitter 超過時の代替（発動条件つき）**：(a) 予告時刻つきイベントパケットの時刻同期型へ切替、(b) 視覚合図（字幕・波紋）の先行発火で聴感同時性を担保。同時性要求の緩和自体は正典変更＝要承認へ上げ直す（57-H-16・docs/42 §2.1 R-08）
- **条件付き発動項（57-U2-Q11）**：H-06 で案C（初接触消滅）または生成側案A退避（全共有＋初接触消滅）を採用した場合に限り、16-U1-Q14「使用後も残存・再入可能」→「初接触で消滅」の正典改訂＋57-H-02 合格ライン・57-H-12 T-U2-04d の「個別層前提の条件付き基準」化＋「消え方が曖昧の演出形」の確定が発動する。書き戻し先4箇所（docs/16 §3.7・docs/32 §4.1・docs/11 §4・docs/00 §3.1①）は**一括反映のみ許可**（部分反映＝R-17 発火）。案A/B（発見者のみ視認）採用時は発動しない（docs/57 §8・docs/42 §2.1 R-04/R-17）
- **マルチ検証での設計変更は上位決定へ波及する**：T-5/T-7・個別層同期・先着結末・係数整合の限定検証で設計変更が必要になれば ADR-0004 の前提（docs/32 §6 全行）に波及し、個別層・村・結末・音同期の複数正典改訂が連鎖する（docs/42 §2.1 R-12・40-Q2——発生条件は承認済み）
- **暫定値の扱い**：±15ms はログ計測の診断目標（正典値ではなく合格判定に使わない——docs/57 §7.4）。配信モードの暗転短縮係数0.6程度は暫定で実測微調整（着地先＝docs/18 §6.1 #7・docs/40 §3.7・Issue #34——57-U2-Q10）。異物可視性の実現方式は Phase 1 スパイクで確定（着地先＝Issue #13 検証記録・docs/40 §4.9）
- **他 ADR との接続**：ADR-0004 が上位決定（本 ADR はその配信側の記録）。異物の個別層生成トリガ（案C 3区分——可視性モデルが「発見者のみ」以外なら案A退避で連動）は ADR-0006、発見者集合・先着綴じ・由来帰属の永続化構造（共有層＝ワールドデータ・個別層＝プレイヤーデータ）は ADR-0007、計測規格（T-1〜T-7）と負荷予算は ADR-0009 の所掌
