## Context

ADR-0004 で「物語/村はワールド共有・個人差分はプレイヤー個別」のハイブリッド状態モデルが確定したが、それをセーブとしてどう分離し、何をどこへ永続化するかは技術レベルでは未規定だった。「あなたが捨てたもの」（個別層）の実現には2つの異なる要求が混在する——アイテム由来の**表示分岐**と、所有者ごとに内容が変わる**地形区画の生成**——であり、保存構造はこの両方を支えなければならない。個別層はスライス最大の技術リスクと位置づけられ（40-Q15 承認）、状態モデルの実現性を最初に潰すため先行スパイク対象になっている。本 ADR は、承認済みの分離方針・永続化対象・生成方式を、ADR-0004 の技術実装側の記録として束ねる。

## Decision

**D-1 保存の物理分離**：共有層はワールド単位の保存（ワールドデータ）・個別層はプレイヤー単位の保存（プレイヤーデータ）として分離する（ADR-0004 Consequences「セーブは共有層＝ワールドデータ・個別層＝プレイヤーデータで分離でき単純」の技術化——docs/57 §4 H-15・docs/40 §4.7）。実装方式は「プレイヤー毎の attachment＋ワールド側の差分レコード」として設計する（57 §4 H-15——AttachmentType＋SavedData の API 実在確認済み・実現性評価＝高。最終的な実装形は Phase 1 スパイクで確定）。

**D-2 個別層は2系統の実装責務を持つ**（57 §4 序文・docs/32 §6）：

- **系統A＝表示のみ個別化（実体共有）**：アイテム由来情報・由来札・ツールチップ・招待状の所有者限定表示は、ワールド実体を分岐させず、由来情報を保持して表示時に観測者別に差し替える（docs/18 §5.4/§5.9・57 §4 H-04・G-TV-05——ワールド状態分岐は不可）。判定可能な言語化——実体は全員に同一で存在し、「同じ物に違う由来札がつく」形に限定される（45/04 M-2・docs/18 §5.10）。「個別化が動いた」とは、由来札の4分岐（自分＝「あんたの物」/他者＝「◯◯の物」/未鑑定＝「誰かの物」かすれ表記/接尾「——◯◯で捨てられた」——docs/18 §5.4・18-U4-Q4・57-U2-Q9）がプレイヤー別に正しく切り替わり、他者の物を見ても実体共有が破綻しないこと（57 §4 H-04 合格ライン）。
- **系統B＝個別層生成（所有者別の内容分岐）**：異物チャンク（現実側——プレイヤー毎にスポーン圏内1箇所保証・発見者のみ視認）、共同堆積内「自分の区画」、自分の捨て場区画（②jigsaw 増築＋没腐度歪み processor）は、所有者ごとに内容が分岐する実体生成として扱う（docs/16 §3.5/§3.7・§7.5・docs/40 §4.3・57 §4 H-12）。系統B は視認側でさらに2型に分かれる（再区分は ADR-0008 D-2 を参照）：(i) **異物チャンク＝発見者のみ視認・非干渉**（他者に視認されず干渉しない——docs/32 §4.1 逐語。非発見者には当たり判定・音・採掘結果も破綻しない）。(ii) **自分の区画・自分の捨て場＝実体はワールドに実在し全員に視認（位置は共有）、内容のみ所有者別に分岐**——他人の捨て場は見学可（docs/16 §3.5-5・docs/23 §9）で、拾えるのは無主の漂着物のみ・他人の物を拾うと由来保持で「届ける/返す」行為が発生する。判定可能な言語化——「個別層生成が動いた」とは、(i) では非発見者に異物が視認・干渉されないこと、(ii) では全員に視認される実体の内容が所有者別に正しく分岐し、見学・無主物拾得・「届ける/返す」が正典どおり機能すること。環礁レイアウト自体はワールド固定（40-Q24）のため、固定地理への所有者別差分生成として設計する（57 §4 H-12）。

**D-3 永続化する状態の台帳**（docs/40 §4.7/§9 の入力一覧＋docs/32 §6 確定表の束ね——正典値は引用）：

*共有層（ワールドデータ——全員で1つの歴史）*

- 章の結末・結末綴じ記録——先着決裁（綴じ動作の先着のみ）＋「◯◯が綴じた」の共有表示＋他者の「見届けた」並記（docs/32 §6・J7）
- 没腐の浄化・拾い人の村の発展・環礁の救出済みフラグ・結末後の月の状態変化（ADR-0004・docs/32 §6・docs/40 §4.7）
- 「誰が綴じたか」・ボス再戦「◯◯の記録」の共有表示（記録明細は個別層——docs/32 §6・18-U2-Q4）・頁全収集勝利（世界の状態——docs/32 §6・K3）
- 死亡地点の没腐遺留物——期限なく残置し拾い直しで回収可（57-U2-Q3・docs/32 §2.1）。喪失判定の権威＝個別層の拾得登録（失われるのは携行中の未登録拾得物のみ——docs/32 §2.1）
- 残置物2箇所——復路拒否品は国側の口の足下に（57-U2-Q5）、転移で届かなかった品は現実側異物内に（57-U2-Q2）、いずれも由来を保持して期限なく残置（再訪で回収可）。※異物内残置物の層帰属＝**個別層レコードに確定**（12-U2-Q4 承認・2026-11-03——置き場の異物が個別層生成・発見者のみ視認のため、発見者集合・所有者紐付と同じくプレイヤーデータ側の状態レコードとして扱い、実体は異物の個別層生成に同梱して再発現）
- 環境一次導線・定点（共有層で全員同一の見え方——docs/32 §6・U2-G）

*個別層（プレイヤーデータ——各人の私的記録）*

- 「あなたが捨てたもの」の所有者紐付けと由来情報（誰が・どこで・何を捨てたか——57 §4 H-04）。個別記憶の対象範囲は docs/23 §12 D1 の確定区分（名付き・記入済み・エンチャ品・拾得物・梱包物・ゴミ箱・自分。ガラクタは集約漂着のみ——非個別実体）
- ガラクタ集約漂着統計（種類×量——docs/23 §2 追跡2層。D-4 の生成入力）
- 拾得登録・拾得図鑑の個人収集・拾い人の手記頁（ADR-0004）
- 個人没腐度カウンタ（docs/32 §2.3 の確定定数を適用——引用のみ）・自分の捨て場増築状態（16-U1-Q11 の段階——57 §4 H-15）
- 宝箱構成の開ける者ごとの独立抽選・モブドロップ全員分（個別層——docs/32 §6。欠片等の世界一意品を除く）
- ノミの名付け帰属（名付けた本人に帰属——docs/32 §6・K16）・先着結末の帰属（個人図鑑の「私が関わった」記録——docs/32 §6）
- 招待状発火状態（1人1通・所有者の箱にのみ返礼——docs/32 §3.3・J4）
- 異物発見者集合（誰が発見済みかの視認判定データ——57 §4 H-15。H-06 の可視性モデルが前提とする永続化）
- 解禁実績の付与状態——解禁＝進行実績の付与で JEI unhide・Patchouli lock・通知を同時駆動（57-U3-Q5・docs/32 §9）
- 転移機構のプレイヤー側状態——ゴミ箱両側口の紐付け・拾い上げ閉塞（docs/23 §5.1）

*転移機構の束ね項（前提機構）*：転移はバニラ転移機構を利用する（DimensionTransition/PortalProcessor——バニラ差し替えなし）。持ち込み可否は PostDimensionTransition のインベントリフィルタで制御する（docs/56 §1.3 が権威・57 §3 H-03/H-05）。本項は先行ゲート「転移骨格」「転移持ち込み」の中核方式であり、D-3 の各残置物・持ち込み不安定項の前提として全 ADR で共有する

*死亡・リスポーン3点（両層を跨ぐ参照）*：リスポーン優先順位＝①自分の捨て場→②拾い人の村（村成立時）→③漂着浜の共同堆積（常時フォールバック）（57-U2-Q7 正典改訂確定・docs/32 §2.2）。「帰れない状態を作らない」——村の共同ゴミ箱から必ず現実へ帰還できる（docs/32 §2.2）。前提となる永続化＝自分の捨て場が生成済みか（個別層）・村が成立したか（共有層）。死亡脱出ハッチへの追加抑止機構は設けない（既存ペナルティが抑止として機能——57-U2-Q4）。

**D-4 自分の区画は集約漂着統計からの決定論的生成**：割当・内容は投入統計から決定論的に生成し、同じ統計なら同じ区画になる（再生成・ログ照合可能——57-U2-Q6・docs/16 §3.2 詳細カード②）。区画の実体スナップショットは保存せず、統計レコードのみを永続化する（最小投棄履歴でも最小区画として生成——51-U1-Q5）。

**D-5 データ構造は拡張前提**：本番スキーマで作り捨てない（P-VS-04——docs/40 §4.7）——「章を足す＝データを足す」構造とし、全IDは `understory:` 名前空間・バニラ上書きなし（docs/40 §4.7 登録規約）。章進行レジストリ（予告頁の動的選択——淀み指標 N-ECO-901 の参照入力を含む——docs/40 §4.5）はレジストリ項目の追加で章に追従する。

## Alternatives Considered

- **個別層縮退（表示のみ個別化への全退避）**：docs/00 §3.1②・docs/40 §4.9 が設計代替として残す案——実体共有のまま表示だけを個別化すれば技術リスクは激減する。却下：57 §4 H-15 で「データ分離自体が不能な場合は主題装置の根幹に関わるため正典側の再設計（ADR 改訂）としてエスカレート——本計画内の代替では処理しない」と確定済み。表示層への縮退では系統B（自分の区画・自分の捨て場・発見者のみの異物）が成立せず、主題装置を削る。
- **全共有保存（個人差分なしモデル）**：ADR-0004 の代替案Aとして棄却済み——「誰の結末か」問題が残り、「あなたが捨てたもの」の個別化ができない。
- **自分の区画＝発見時スナップショット保存（案ii）**：57 §4 H-12 の設計代替——区画内容を生成時に固定して永続化する案。却下：投棄ごとに区画が育つ差分を見せる設計（51-U1-Q5）と衝突し、スナップショットの肥大・照合不能を招く。決定論的生成は「同じ統計なら同じ区画」で再生成・ログ照合が効き、保存対象を統計レコードに限定できる。

## Consequences

- **良い面**：共有層/個別層の物理分離で、共有の群像劇（結末・村・月）と個人の「捨てたもの」体験が1つのセーブモデルで両立する。自分の区画を決定論的生成としたことで個別層の保存量は実体でなく状態・統計レコードに留まり、プレイヤー数・投棄量へのスケールを見込める。解禁を実績一本化したことで、進行連動の永続化チャネル（JEI・Patchouli・通知）が1系統に閉じ、チャネル間の不整合余地を排した。
- **悪い面**：個別層はスライス最大の技術リスク（40-Q15——先行スパイク対象）。バニラにプレイヤー別ブロック差分の API は存在せずパケット加工系は重量級（57 §4 H-06）、個別層生成はバニラ生成系に直乗りしない自前実装（57 §4 H-12）。個別層の漏洩不具合は主題装置を壊すため最優先の検証対象（57 §4 H-15）。死亡・リスポーンは個別層（捨て場生成済み）と共有層（村成立）の両方を参照するため、層を跨ぐ整合の試験が不可欠。
- **今後の制約**：
  - **Phase 1 スパイクへの合格条件**：H-15＝個別層が他者に漏れず・共有層が全員に一致・セーブ/再ログイン・死亡・次元移動で全項目が永続化（57 §4 H-15 合格ライン——docs/40 §5.2.2 T-4/T-5 に接続）。「あなたが捨てたもの」は実データ駆動の端到端（現実側ゴミ箱投入→章アフィニティ→配置→由来札表示）で証明する——テスト注入では証明にならない（40-Q19）。
  - **着手順序**：H-12/H-15 は区分上 S1 並行だが、先行ゲート H-04/H-06 が個別層基盤を前提とするため先行ゲートと一体で着手する（57 §1.2）。
  - **条件付き発動項（57-U2-Q11）**：H-06 の可視性モデルで案C（初接触消滅）または生成側案A退避（全共有＋初接触消滅）が採用された場合のみ、16-U1-Q14「使用後も残存・再入可能」→「初接触で消滅」への改訂＋H-02 合格ライン・H-12 T-U2-04d の個別層前提条件化＋「消え方が曖昧の演出形」の仕様確定が発動する。書き戻し先4箇所（docs/16 §3.7・docs/32 §4.1・docs/11 §4・docs/00 §3.1①）は**一括反映のみ許可**（部分反映は docs/42 §5.1 R-17 の発火）。案A/B（発見者のみ視認）採用時は発動しない（条件付き項として記録——確定扱いしない）。
  - **エスカレーション経路**：個別層のデータ分離自体が不能と判明した場合、本 ADR と ADR-0004 の前提を揺らす正典改訂となるため、検証計画内の代替では処理せず要承認へ上げる（57 §4 H-15・docs/42 §5.1 R-08 行）。発生時は新 ADR で記録する。
  - **スキーマ拡張規則**：章量産時は新章＝レジストリ項目・データの追加のみとし、既存セーブを破壊するスキーマ変更は行わない運用を前提とする（P-VS-04）。後方互換の具体的運用規則は正典未規定——open_questions（12-U2-Q1）。
  - **暫定値の着地**：転移持ち込みの減損率絶対値は暫定——PoC スパイク計測後に Issue #15 へ着地（57-U2-Q2・57 §8）。
  - **ADR 間の接続**：本 ADR は ADR-0004（上位の状態モデル）の技術実装側であり、ADR-0006（次元生成方式——個別層生成物の配置・生成トリガの前提）と ADR-0008（マルチプレイ——個別層の非漏洩・共有層一致を配信側で担保する記録）と接続する。個別層生成物の負荷基準は ADR-0009（パフォーマンス方針）に従う。
