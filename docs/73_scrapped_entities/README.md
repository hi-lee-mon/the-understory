## 2. 本シリーズの位置づけ

- **docs/72 → docs/73**：72 が「採否判定」（どの没案を拾うか）、73 が「個別設計」（拾った没をどう世界に置くか）。判定は 72、設計は 73——二書が対になる（docs/66→67 と同型の research→design 構造）。
- **権利の枠組み**：全案が docs/72 §2 の L1（アイデア・来歴のみ参照可）に基づく。名称・造形・アセット・コードは全て独自（L2/L3・35-U1-Q2）。原案参照は `MJ-nn` ID で行い、**ゲーム内表記に原案名は出さない**。
- **工程の記録**：本設計はセッション内工程で実施した——マルチエージェントワークフローでなく、設計者による自己レビュー2周（L1〜L5 遵守・正典突合・被覆確認）で品質を確保した（**逸脱記録**：SWE-2 枠飽和により独立検証を自己レビューで代替——Issue #34・#35 と同じ運用。詳細は Issue #39 完了報告へ）。

## 3. 共通規則（全ユニットに効く）

1. **「没の理由」が形になる**——各案は没の理由（似すぎ・描かれたまま・譲った・言及のみ消滅・有毒・選ぶ場自体の廃止等）を来歴として持ち、造形・振る舞い・語りにそれが滲む設計とする。
2. **独自化の徹底**——仮称は全て docs/16 §2.5 文法（「〜なかった〜」「没になった〜」）と docs/44 語彙で作る。命名確定は docs/44 経路② の別工程。
3. **既存体系への割付**——mob は 38/04 §1.4/§1.5（遷移表・統一規範）準拠、構造は docs/16 §2.1 型体系、情景は気配〜示唆段階の導線、拾得物は docs/14・38/01 へ手渡し。**新規の生成方式・機構・命名権威は作らない**。
4. **数値は手渡し**——HP・実効・出現率・収容物構成は全て `SE_*` 変数または型として列挙し、絶対値は Issue #15（docs/38 系）へ。**N-系 ID・SE-ID の採番は本書では行わない**。
5. **「迎えに来た者」規則**（L5）——公式で同型要素が復活したら「別の世界が迎えに来た」語りとして接続し、復活済みの案は語り材料のみとする（meta_motifs.md §3.4 が正本）。
