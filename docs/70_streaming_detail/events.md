## §0. 目的

配信者到達の主経路（Issue #22 D-7 承認＝**サーバーイベント運用**）の**形態設計**と、docs/17 §6「期間限定の没の素材・異物を入れられるよう設計」の**設計枠**を定める。docs/43 §5 が「いつ・誰へ・何を渡すか」（到達の運用設計）を担うのに対し、本書は**イベントという場そのものの形**（どんな鯖で・何が見せ場になるか・期間限定要素をどう収めるか）を設計する。

- **対象**：サーバーイベントの形態分類と採否・共同進行/群像劇蓄積の見せ方・期間限定要素の収録/非収録ルール・解禁/復刻規格・コラボ規格・保守コスト判定
- **除外**：到達運用（送付・応答・導入——docs/43 §5 が正本）・配信者網の選定/交渉（Issue #17 網整備側の所掌——43-U3-Q3(a)）・L3 検証運用（docs/41 が正本）
- **前提（G-SD-02・覆さない）**：配信モード画面なし（U4-11）・観戦/俯瞰視点新設なし（18-U4-Q13）・予告頁＝ノミ語り＋挿絵・ARG接点＝現実側ガラのみ（U4-9）・切り抜き瞬間自体は素材化しない（43-U3-Q6）

## §1. サーバーイベント運用の設計

### 1.1 形態分類（実績形式→本作での形）

docs/08 §1-1 の実績4形式に、正典の機構が実際に対応できる形を対応付ける（採否は全採用前提にしない——P-SD-05）：

| 形式 | 実績（docs/08・46 §6.1） | 本作での形 | 採否の判定 |
|---|---|---|---|
| **期間限定テーマ鯖** | マイクラ肝試し2025「Book of Märchen」（物語テーマ・4人チーム・13日間・配信自由） | **主形態**。章＝配信回の構造（docs/17 §2）と「没の国」という物語テーマが、肝試し型「誰もが知る物語だが誰も知らない物語」の企画意図と同型。期間限定「没素材」の余地（docs/17 §6）はテーマ鯖の企画材料そのもの | **採る**——正典機構が全てそのまま効く（§1.2） |
| **MOD入りカスタムサーバー** | ぶいきゃすドラゴンサバイバル（35名・レンタル鯖提供） | D-7 の実績形式そのもの。提供パッケージ＋サーバー既定値テンプレ同梱（43-U3-Q2(b)）で運営体が立てる形 | **採る**（主経路の実現形——43 §5.1.2 経路2） |
| **短期集中イベント鯖** | VCR 型（開催密度最大） | 開催コストは運営体側。本作が提供側に回る乗合対象として有効 | **採る**（乗合対象として——自前開催はしない＝43-U3-Q1 案C） |
| **常設共有鯖** | にじさんじ鯖・ホロ鯖（多年の街＝群像劇） | 群像劇蓄積（§1.3）には最強の形だが、単独開発で常時サーバーを維持する保守コストが最大 | **要承認**（17-U2-Q3——推奨＝自前常設は持たない） |

### 1.2 共同進行の見せ方（正典の実在機構のみ）

期間限定テーマ鯖・カスタム鯖で「みんなで進める」が映える構造——全て正典の確定機構であり、イベント用に新設する機構はない：

| 見せ方 | 正典機構 | 配信面での効果 | 出典 |
|---|---|---|---|
| 全員が同じ環礁で各々の物を見る | 「あなたが捨てたもの」個別層（自分＝「あんたの物」/他者＝「◯◯の物」） | N視点視聴の天然資産——イベント参加者ごとの切り抜きが別内容になる | docs/32 §6・docs/17 §5 |
| 結末を「誰が」綴じたか | 結末決裁＝先着＋「◯◯が綴じた結末」共有層表示＋頁所持者は気配のみ | 「書き換える派？見届ける派？」コメント議論→誰が綴じるかの駆け引きがイベントの見せ場 | docs/32 §6（18-U4-Q11）・docs/17 §6 |
| 村への届きもの着弾 | 共同箱着弾（mailboat.creak→bin.arrive）＋近傍住人の定型反応連鎖＋着弾 Toast | 「村に届く」を全員が同時に目撃する共有イベント——マルチの見せ場として確定済み | docs/51 village BD-VL-081・51-U3-Q5・docs/23 §7 |
| 仲間をクレーンで捨てる儀式 | L3 処理場クレーン掴み（予備動作→掴み→吊り上げ→投入口落下）＋「◯◯に捨てられた」記録 | 処理場構造コスト＝合意の閾値。落とされた側だけが灼熱の埋立て地へ届く視点差——イベントのハイライト儀式 | docs/23 §8.5・docs/16 §6.4.2・docs/17 §3 |
| 後発加入の追いつき | 「◯◯の手記の写し」（先に進んだ者の手記複写頁・死亡ロスト対象外） | 期間中の途中参加が「先達の物語を読む」形で成立——イベント鯖の継続流入を阻まない | docs/32 §6（U2-N4・18-U2-Q6） |
| 同時性の担保 | 共有共有層イベントのサーバー権威発火 ±100ms | 複数配信者が同じ瞬間をほぼ同時に見せられる（N視点の同時クリップが成立） | 19-U1-Q3・19-U4-Q4 |

### 1.3 群像劇蓄積の見せ方

常設/期間鯖で「世界がプレイヤーの物語を記憶する」蓄積がコンテンツになる構造（docs/08 §2-2——群像劇の土台）：

| 蓄積層 | 正典機構 | 見せ方 |
|---|---|---|
| 村の発展 | 救出連動の jigsaw 発展区画（手紙屋・農園・祭り場・鍛錬名人・原案の座区画）＋村報発行所 | 「誰が救った住人か」が村の姿として残る——イベント期間の進行史が地形になる | docs/16 §2/§3.4・docs/34/06 §6.3 |
| 名前の記録 | 「◯◯が綴じた結末」・ボス再戦記録（共有層「◯◯の記録」）・「◯◯のごみ処理場」所有者表示 | 参加者の名が世界に残る——常設鯖の「歴史」になる | docs/32 §6・18-U2-Q4・docs/23 §8.6 |
| 捨てられた記録 | 「◯◯に捨てられた」（個別層＋処理場記憶＋共有層——67-U4-Q6 承認待ち）・住人の記憶セリフ「あんたが捨てたあれ…」 | 「お前に捨てられたんだが！？」の弁明・笑い——イベント後のコミュニティ話題 | docs/23 §8.5・§11・67-U4-Q6 |

## §2. 期間限定要素の設計枠

docs/17 §6 の「イベント向けに期間限定の没の素材・異物を入れられるよう設計」を、何が・どこへ・どう収めるかの枠に降ろす。

### 2.1 拡張余地の構造（正典に実在する挿入口）

P-06「構造物設計は拡張余地を最初に固める」（docs/16）により、期間限定要素の挿入口は既にプール構造として存在する：

| 挿入口 | 正典の構造 | 期間限定での使い方 | 出典 |
|---|---|---|---|
| 異物チャンクの型プール | 複数型の異質パーツプール（Far Lands的崩れ・存在しない柱・文字化け看板・色の剥がれた村等——内部ダンジョン化なし） | 期間限定型の追加（「◯◯の季節に棄てられた物」の異物型） | docs/16・32 §4.1（16-U1-Q13） |
| 補助環礁 | 本線環礁の間の S 級寄り道（3〜5島——報酬・ロア部品） | 期間限定の寄り道島（小さな場として置ける最小単位） | docs/16 §3.1・38/04 N-ECO-608 |
| 村の発展区画 | 救出連動 jigsaw プール | 期間限定の出店・施設（祭りの出し物等——村の祭り場との親和） | docs/16 §3.4・docs/34/03 §7 |
| ポスト機構 | 届きもの着弾・誤配便5%・「あんた宛」返信 | 期間限定の届き物（イベント宛の手紙——誤配体系への追加行） | docs/23 §7・docs/52 §9 |
| L3 処理場パーツ | 構成パーツが文法を決める（投入口・クレーン・マグマ槽・圧縮機・選別ライン） | 期間限定部品（処理方法の季節変種——ただし部品追加は文法の拡張になるため高コスト・最小限に） | docs/16 §6.4.2・docs/23 §8.3 |
| 漂着物・拾得物 | 没素材・拾得装備・フレーバー物の体系 | 期間限定の拾得物（「没の被り物」「没の飾り」——最も低コストな収録面） | docs/38/01・docs/14 |

### 2.2 収録ルール（期間限定に適するもの——判定可能な基準）

| # | ルール | 判定基準 |
|---|---|---|
| R1 | **「没」語彙と整合する物のみ** | 棄てられたもの・没になったもの・異物として世界観内に説明が立つ物。説明が立たない外来物は没の国の文法で吸収できず採らない（世界観の吸収力＝本作の期間限定が他作と違う点——「なんでも没にすれば入る」構造がテーマを壊さない） |
| R2 | **本編の伏線系統に混入しない** | 伏線台帳（F-系・docs/36）・TX-ID 断片系統（docs/52）・章アフィニティ配達（docs/23 §6）に食い込まない。期間限定物は本編の弧（短/中/長距離）の構成要素にならない |
| R3 | **個別層の由来語義を壊さない** | 「あんたの物」/「◯◯の物」はプレイヤー由来の語（18-U4-Q4）。期間限定物を「◯◯の物」に偽装して個別層に混ぜない——誰が捨てたかが読めない物は共有層の環境物として置く |
| R4 | **核心4項目に触れない** | 由来物の正体・没腐・結末構造・切り抜き瞬間（docs/43 §6.3）——期間限定素材も同じ除外規則が効く（43-U3-Q6 どおり瞬間そのものは素材化しない） |
| R5 | **期間終了後に文法内で消せる** | 撤去時に「二度棄てられたもの」として語彙内で消せる構造（残滓・遺留状態のまま残さない）。常設化するなら最初から常設として設計する |
| R6 | **性能予算・収録条件を侵さない** | 追加物は modpack 収録条件（性能コスト予算・依存最小——docs/43 §4.5 運用列挙）の内側に収まる |

### 2.3 非収録ルール（本編に混ぜない——同じく判定可能に）

| # | ルール | 根拠 |
|---|---|---|
| N1 | **章演出の正典（幕切れ・見得・予告頁・幕構造）をイベント仕様に転用しない** | 演出の正本は docs/51・34・48（G-SD-06）。期間限定の盛り上げに幕構造を引っ張ると本編の劇的資産を薄める |
| N2 | **ARG 接点・幻想文字系統は期間限定に使わない** | 現実側はガラのみ・真相言明禁止（U4-9・docs/48/04 §6）。期間限定の刻印は考察班の分母を汚染する |
| N3 | **正典の数値・確率・発火条件を変える期間限定はしない** | 正典値は引用のみ（G-SD-01）——「期間中だけドロップ倍増」型は数値の分岐を生み検証不能になる |
| N4 | **没腐・喪失境界・結末の系統に接続する期間限定はしない** | 個人没腐度・二度棄ての行き先は本編の状態系（docs/32 §2.3・23 §10）。期間限定物が二度棄て先（座の棚）に食い込むと本編の記録系統が汚れる |
| N5 | **視聴者にだけ別の景色を出さない** | 同席者方針（G-SD-03）——イベント限定の観戦向け追加表示は作らない |

### 2.4 解禁・復刻の規格

- **解禁判定の帰属**：期間限定要素の公開も追加単位の公開判定と同じ流れに乗せる——正式後は docs/43 §2.7 G-7「完成塊・情報粒度・版数・変更履歴」の同型適用、β期は G-5 に従属（17-U2-Q4——推奨）。
- **復刻の文法的正当化**：没の国は「棄てられたものが集まる場所」——一度出た物が「もう一度棄てられたものとして戻る」は物語的に破綻しない。**復刻はそのまま再録してよい**（「復刻イベント」という外部枠は要らず、世界内の語彙で説明が立つ）。
- **期間切替の運用単位**：収録・撤去は「追加単位」単位（1完成塊ずつ——P-RL-01・43-U4-Q1）で行い、部分解禁・部分撤去はしない。

## §3. コラボ・イベント規格

### 3.1 コラボ要素の世界観整合形

コラボ先の要素は**「相手の世界から棄てられたもの」として没素材の形で収録する**——コラボ物がコラボ世界のまま来るのでなく、没の国の文法（棄てられた→届く→拾い直される）に一度通す。これは本作の世界観が「没」でほぼ任意の物を吸収できる構造だからこそ成り立つ（docs/11 §4・docs/23 §5）。

- 由来表示：コラボ由来物は「◯◯（由来名）の物」の由来札で読める形——R3 どおりプレイヤー個別由来に偽装しない
- 名付け可否：没素材として入る以上、名付けの文法の通常対象（docs/23 §3.3）——ただし収録基準自体は 17-U2-Q2 の要承認に含める

### 3.2 イベント運用の規格行

| 項目 | 規格 | 出典・接続 |
|---|---|---|
| 提供形態 | パック＋サーバーデフォルト値テンプレ同梱（「入れるだけ」＋運営既定値） | 43-U3-Q2(b)・docs/46 §6.2 必須4点 |
| サーバー前提 | 専用サーバー動作＝modpack 収録条件の必須項・マルチ機構全実装（40-Q2）・共有層 ±100ms | docs/46 §4.2・docs/32 §6 |
| 解禁の連動 | サーバーイベント第1波の契機＝**8-K 正式リリース化**（43-U4-Q7 案A）。アルファ期のイベント素材送付は経路2 の送付物として先行可（公開掲載とは別物） | docs/43 §8.2 8-L・§5.1.2 |
| 情報粒度 | イベント告知・運営向け素材も核心4項目除外（由来物の正体・没腐・結末構造・切り抜き瞬間）＋切り抜き瞬間は「幕切れ→予告頁」型の存在示唆まで | docs/43 §6.3・43-U3-Q6 |

## §3.3 観客参加枠の受け皿（17-U3-Q5 の着地先）

非プレイヤー視聴者の「自分の物が届く」体験は、docs/23 §10 の名札・村宛届きもの定型・共同ゴミ箱の機構をそのまま使い、**期間限定イベントの運用枠で「観客の捨てた物が村宛に届く」形で受ける**——新規のゲーム内機構は追加しない（17-U3-Q5 推奨案(a) の具体的枠）。形態は §1 のサーバーイベント形態分類に従属し、採否・期間の詳細は audience.md §5（17-U3-Q5）のユーザー決裁に従う。

## §4. 保守コストと運用負荷（G-SD-08）

### 4.1 負荷の帰属構造

| 負荷 | 誰が持つか | 根拠 |
|---|---|---|
| サーバー実費・常時運用 | **運営体側**（ぶいきゃす実績＝レンタルサーバー提供——乗合モデルでは本作側にサーバー費用は乗らない） | docs/46 §6.1 |
| 提供パッケージ整備・導入検証 | 制作者（本作側）——パック・サーバー既定値・素材5点・導入手順 | docs/43 §5.2-5.3 |
| 交渉・採用交渉の工数 | 最長不確定要素として R-34 で監視——イベント運営交渉は Phase 5 以降の実施 | docs/42 R-34・docs/43 §8.5 |
| 期間切替・復刻の運用 | 追加単位ごとの判定＋掲載＋告知の反復工数 | docs/43 §2.7/§3.8 |
| ネタバレ統制 | 週次手動巡回の常設コスト（期間限定で露出面積が増える分だけ悪化しうる） | docs/42 R-38 |
| ホットフィックス | 掲載後に常設・緊急度2級制 | 43-U4-Q6 |

### 4.2 判定（採る/採らない）

- **自前の大規模運営＝採らない**（確定済み——43-U3-Q1 案C：自前開催は交渉・運営工数が本線を食い R-34 を増幅）。本書はこの決定の上に立つ。
- **期間限定要素の総量**：収録ルール R1〜R6 を通る物なら入れられるが、**単位あたりの運用工数（判定・掲載・告知・ネタバレ確認）に対し得られる話題性が小さい物は採らない**——「没の被り物」級の低コスト拾得物を主軸にし、補助環礁・処理場部品級の大物は年1〜2回の山場に絞る運用を推奨（17-U2-Q1/Q2 と併せて判定）。
- **常設共有鯖**：群像劇蓄積（§1.3）は常設で最大化されるが、単独開発で常時鯖の保守は現実的でない——自前常設は持たず、期間中テーマ鯖に蓄積の見せ場を集約する（17-U2-Q3——推奨案B）。
- **EULA 前提**：イベント参加・コラボに金銭授受が絡む形は R-22 赤信号（収益化検討＝即時エスカレーション）——コラボ・イベントの形態は無償公開の枠内に限定する。
