# 69_調査基準：配信詳細（Issue #17）

Issue #17「配信詳細：イベント・観客参加・クリップ瞬間」（完了条件＝docs/17 更新または追補ドキュメント）の制作物差し。**追補ドキュメントとして `docs/70_streaming_detail/` を新設**し、docs/17（v0.2・方針書）の確定方針を詳細仕様へ降ろす。

## §1. 対象と除外

- **対象**：(a) 各章・各拠点のクリップ瞬間台帳（「配信を知らない人にも30秒で状況が分かる」劇的瞬間を章単位で言語化）(b) イベント・期間限定要素の設計（期間限定の没素材/異物・サーバーイベント運用の形態・実装余地の構造）(c) 観客参加・同席感の詳細設計（考察班素材の供給形態・コメント誘発点・視聴者参加要素の要否判定）
- **除外**：配信の基礎方針（docs/17 確定済みを再検討しない）・実装コード・外部サービス連携の技術仕様・収益化設計（docs/43/46 の確定範囲を覆さない）

## §2. 正典制約（G-SD-01〜10——違反は不可）

- **G-SD-01**：正典値は引用のみ・再定義禁止（docs/17 の確定方針・「同席者」方針・44-U3-Q5 の用語棲み分け＝設計概念「切り抜き」/検証項目「クリップ瞬間」/口語「見せ場」）
- **G-SD-02**：承認済み決定を覆さない——配信者到達＝サーバーイベント運用が主経路（Issue #22 D-7）・専用「配信モード」画面なし＝コンフィグ対応（18-U4-Q13・U4-11）・観戦/俯瞰視点は新設しない（18-U4-Q13）・予告頁＝ノミ語り＋挿絵（U2-D/U4-#2）・ARG接点規則（現実側＝ガラのみ・U4-9）
- **G-SD-03**：「視聴者＝同席者」方針（docs/08 §2・docs/17 v0.2）を全設計の前提とする——視聴者にだけ別の景色/情報を出す機構は創作しない
- **G-SD-04**：Phase 0＝設計のみ。実装コード・JSON・確定的なクラス/イベント名は書かない——仕様・構造・責務・判定可能な言語化まで
- **G-SD-05**：面白さの根幹（観客参加・イベント要素の要否）は選択肢＋推奨案つきの要承認 `17-U{n}-Q{m}` で起票——Devin は推奨まで作り、決定権はユーザー
- **G-SD-06**：各章のボード（docs/51）・プロット（docs/34）・数値（docs/38）・幕構造（docs/48）が演出の正典——クリップ瞬間はそれらの引用・言語化であり、新規の演出仕様を創作しない
- **G-SD-07**：「30秒ルール」判定基準は docs/17 §3 の言語（配信を知らない人にも30秒で状況が分かる）に従う
- **G-SD-08**：保守コスト・サーバー運用負荷は配慮として明記（単独開発——docs/42 の保守リスク系に接続）
- **G-SD-09**：未着地・暫定値は「暫定＋着地先」を明記
- **G-SD-10**：日本語・既存 docs の文体/書式に従う

## §3. 設計原則（P-SD-01〜08）

- **P-SD-01 出典明記**：各クリップ瞬間・イベント要素・参加機構は正典出典 ID（docs/NN §X・NN-U{n}-Q{m}）付き
- **P-SD-02 判定可能な言語化**：「クリップになる」とは何を指すかを判定可能に（例：前提知識なしで見た視聴者が30秒以内に状況を言語化できる・切り抜きのタイトルが立つ）
- **P-SD-03 配信者反応の設計**：「プレイヤー本人が驚く/語る瞬間」を各クリップ瞬間で言語化——視聴者の反応だけでなく配信者本人の反応が発生する構造を見る
- **P-SD-04 層の分離**：ゲーム内機構（実在の仕様）と配信運用（宣伝・素材・イベント運営）を分離して記述
- **P-SD-05 参加の要否を判定**：観客参加・期間限定要素は全て採用ではなく「採る/採らない」の判定を論点化——採る場合の保守コストと得られる価値を並べる
- **P-SD-06 シリーズ化との一致**：章＝配信回の構造（docs/17 §2）と矛盾しない——クリップ瞬間は章の見せ場位置に寄せる
- **P-SD-07 要承認採番**：`17-U{n}-Q{m}`（U1=クリップ台帳・U2=イベント・U3=観客参加・U4=README/横断）——書き戻し先必須
- **P-SD-08 README/手渡しは成果物**：索引・要承認集約・手渡し表を必ず含める
