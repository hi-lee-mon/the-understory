## 1. デザイントークン完全定義

> docs/20 §8 残件「デザインシステムのトークン（色・形・動き）の完全定義」の着地節。docs/20 §2 の方針行を、実装が引ける値・規格へ翻訳する。実数値は推奨案——承認で正典化（要承認 ID＝`18-U1-Q{n}`・§2.7 に集約）。

### 1.1 色トークン

**原則**：色は「語りの深度」を運ぶ。基調パレットは器の骨格（全器共通）、アクセントの朱・琥珀は意味を持つため予約（docs/20 §2 色予約）、かすれは淀みの語彙（彩度↓＋灰化）。**色のみに依存する表示は禁止**（G-UI-06——必ず形・位置・動き・音と併記する）。

#### 1.1.1 基調トークン（器の骨格——全 UI 共通）

| トークン | 用途 | 推奨値（hex） | 根拠 |
|---|---|---|---|
| `ui_ink`（墨） | 本文・罫線・枠線・確定した記述 | #2B2E33 | docs/20 §2 基調「墨」。読む層の主文字色 |
| `ui_paper`（月白） | 頁の地・主面・ハイライト背景 | #E6E1D3 | 基調「月白」。温かみのある白（国の紙） |
| `ui_ground`（灰青） | 背景地・器の外縁・暗い下地 | #3E4A52 | 基調「灰青」。頁を囲む世界の色 |
| `ui_gilt`（古金） | 見出し・装飾線・綴じ糸・重要項目の強調枠 | #8F7B4F | 基調「古金」。意味を帯びた飾り（使いすぎない） |

#### 1.1.2 アクセントトークン（予約色——使い途を限定）

| トークン | 許される用途 | 禁止用途 | 推奨値 | 根拠 |
|---|---|---|---|---|
| `ui_vermilion`（拾得の朱） | 拾える物の標識・拾得系動作の選択表示（綴じ画面の「拾う」項等——**拾得に帰属する選択に限定**）・新規拾得の通知差し・「届いた」の一点 | 装飾全般・章差し色・危険表示・**拾得に帰属しない汎用カーソル/選択色** | #B5442C | docs/20 §2・45/01 §4.4「拾得の朱一本」（器内適用の裁定は下行注記） |
| `ui_amber`（灯りの琥珀） | **「読める物を兼ねる拾得物」のみ**（届いた手紙・読める物を兼ねる由来物）・灯火の UI 反映 | 上記以外の全て（**読めない由来物・汎用の気配表示には使わない**） | #B98A44 | docs/20 §2 琥珀例外・45/01 §4.4 |

> **予約色の器内適用の裁定（本書の明記）**：朱の選択表示への適用は「拾う」等の**拾得に帰属する動作の選択に限定**し、汎用のカーソル色・選択色には用いない。琥珀の由来物への適用は**「読める物」を兼ねる由来物**（届いた手紙等）に限定し、読めない由来物の気配には用いない。いずれも 45/01 §4.4 の予約域（拾得標識＝朱一本／琥珀＝読める物・静止した手紙・灯りの安全・静止系）の内側に収める器内適用として明記する——予約色の乱用禁止（45/01 §5.1 K-10「アクセント予約色の乱用」）に触れない範囲の限定である。

#### 1.1.3 かすれ階調（淀み・読めない項・未確定の語彙）

| トークン | 用途 | 推奨値・規則 | 根拠 |
|---|---|---|---|
| `ui_faded`（かすれ） | 「かすれた項」・封印済み・まだ読めない頁の表示 | 基調色を彩度 −60%・輝度 ±10% へ灰化（頁上では墨 #6A6E70 相当・輪郭だけ残す）。**存在の可視は枠・位置・形が担い、文字の可読は奪う**（コントラスト規則 C-4 の対象外＝正典設計） | 45/04 §4 C-4・docs/20 §5 彩度規則・K3 |
| `ui_blank`（余白） | 「まだ綴じられていない頁」・欠頁の余白・詩の行間 | `ui_paper` より一段明るい #EFE9DC。余白は情報の欠如でなく「これから綴じられる場所」の語彙 | docs/20 §5 余白・48/02 §4.1 |

#### 1.1.4 章パレットの UI 適用

- **器は共通・断片頁の皮だけが変わる**：UI の基調色・器クローム（拾得図鑑・手記・綴じ画面等の枠・綴じ目——1.1.1・1.2.1）は章・形式で変えない——「拾得図鑑は形式に関わらず同じ器に収まる・共通の装丁に住み分け」（48/04 §5.2 綴じの皮）が確定済みの線引き。章・形式ごとに変わるのは**断片頁の装丁の皮**（枠意匠・綴じ糸色・頁面モチーフ・挿絵比率——48/04 §5.1 装丁マトリクスの「装丁の皮／頁の構え／乱れの演出」列の範囲）のみ（P-UI-01・法典の結び）。
- 章サブパレット（褪せた祭り色・錆・鉱石の輝き等）は**断片頁の装丁と頁面挿絵の内部**に閉じる。HUD・通知・字幕・器クロームには章色を流用しない（色が情報を担う系譜を乱さない——G-UI-06 予防）。

#### 1.1.5 コントラスト規則（45/04 C-4 の UI 側履行）

- 読む層の本文は「`ui_ink` × `ui_paper`」の高対比を既定。装飾背景の上に本文を直置きしない（挿絵頁の文字は余白面または下地紙の上に置く）。
- かすれた項・封印項は読めない設計（K3）ゆえ対象外——**「ある」ことを枠・折れ目・綴じ目の空きで示す**（色の灰化は補助）。
- 字幕・由来札・照準ヒントは背景不透明度の確保で担保（バニラ字幕の表示規則に倣う）。

### 1.2 形トークン

**原則**：全 UI は「書物・頁・綴じ目」のモチーフで造る（P-UI-01）。「かすれた・欠けた・継がれた」の審美は形の言語で表す（docs/20 §2 形状言語）——**形の差は色に依存しない識別系**としても機能する（G-UI-06 の裏取り）。

#### 1.2.1 器の部品語彙

| 部品 | 意味 | 形の規格 |
|---|---|---|
| 表紙 | 器の入口・所蔵状態の顔 | 外縁に継ぎ目（異素材の接ぎ）・角の欠け。「新頁あり」の気配は表紙の微細な隆起＋薄い光の滲みで表す（U2-N2——拾得の朱の予約域に触れない、気配級の形＋光の差で示す） |
| 頁 | 内容の最小単位 | 右/左頁で綴じ目側の影が逆。端のかすれ（水濡れ系）は装丁差の一部 |
| 綴じ目（糸綴じ） | 頁の帰属・欠頁の可視 | 綴じ糸は古金。欠頁は糸の残る空き孔＋余白頁で「ここにあった/来る」ことを示す（枚数のみ可視・内容は示さない——U2-N2） |
| 折れ目（頁端折り） | 未読の印 | 頁の外角を折る。読了で消える（状態遷移＝読了フラグ） |
| 栞・帯 | 再開地点 | 綴じ画面・手記で「前回ここまで読んだ」を帯で示す（再開可能原則の視覚化） |

#### 1.2.2 枠意匠（境界の装飾）

| 意匠 | 用法 |
|---|---|
| 欠けた矩形 | 基本フレーム。角の1〜2箇所を欠かす——完全な矩形は「現実側・新品」の語彙として温存 |
| 破れた頁縁 | 断片・欠片由来の頁（拾得した断片の綴じ頁は縁が破れている） |
| 継ぎ目 | 異形式・異出典の境界（書簡と設計書が同じ器に綴じられる境、等） |
| 不完全な円 | 選択肢・未確定の項の囲み（綴じ画面の三択枠——完成しない円＝結末の未確定） |
| 「没」の印 | 設計書・棄却項の捺印型意匠（朱肉の掠れ印——48/02 §4.1） |

#### 1.2.3 アイコン体系

| 規格 | 値 |
|---|---|
| 基準グリッド | 16×16（バニラ GUI 基準）。内側 1px 余白 |
| 統一線幅 | 外郭 1px・主形 1px（アイコン内の太さ差は 2 段まで） |
| 欠け表現 | 全アイコンに「欠け変種」を用意——角の欠け・輪郭の断ち・内部の抜けを形で入れる（完全な形は使わない） |
| 色規則 | アイコンは墨＋古金で描き、意味の差し色は朱（拾得）・琥珀（読める物兼ねる）の予約に限る |
| 一覧 | 拾得（欠けた菱形＋糸屑）・没腐（歪んだ輪郭）・結末（不完全な円＋綴じ目）・図鑑（綴じ目付き冊子）・未読（折れ目）・由来（名札形）・頁追加（頁＋折れ目）・幕（開いた幕形）——各器での使用は §3〜§5 が明記 |
| 配信要件 | 16px 基準でも部品が識別できる形（輪郭の内切りを広めに——P-UI-08・30 秒基準） |

#### 1.2.4 「読めない形」の語彙（幻想文字・かすれ文字の形側）

- 幻想文字：58 字形・「骨格（子音行）×継ぎ目（母音列）」の行列構造（48/04 §2.2〜2.3 確定）。**ガラ（読めない字）の識別基準＝行列構造に収まらない形**——UI 側はこの形状規則を崩さない字形でレンダリングする。
- かすれ文字：日本語のまま形が崩れる書体——「読めるが乱れた」状態はフォントが担い（§1.4）、読めない状態（幻想文字）と峻別する（48/04 §5.2：読めなくするために幻想文字は使わない）。
- 祭囃子没腐姿（Issue #2 手渡し分——H23）の**形側メモ**：半融合三段構成（下半身＝指揮台機構接合・両腕＝操り糸機構・頭部上半身＝人の姿——16-U3-Q1 承認値）において、UI/観る層で「機構が演目を演じる」ことが読める部位の見え方（拍子歯車の露出・糸巻きの回転・鈴と扇の腕のみが拍子を刻む動き）は §6 演出要件の入力とする——デザイン側造形詳細（衣装・表情）は本節のトークン範囲外、§6.5 の造形メモへ集約する。

### 1.3 動きトークン

**原則**：モーションは「時間の経過」を語る——速い・弾む動きは使わない（世界は止まっている）。動きは全て「かすれて現れる・綴じられる・めくれる・幕が降りる」の語彙に閉じる（docs/20 §2 モーション）。数値は UI 時間値として本書が確定する（P-UI-10——承認で確定：18-U1-Q3/Q2）。

#### 1.3.1 モーションプリミティブ（推奨確定値）

| モーション | 用法 | 時間・緩急（推奨値） |
|---|---|---|
| かすれて現れる | テキスト・項・頁の出現。低彩度・低輪郭から知覚できる形へ | 0.45s・ease-out（彩度 0→規定値・不透明度 0→100% を同時変調） |
| 欠片が綴じられる | 拾得片・頁・欠片が器に収まる | 0.9s：対象が収束点（綴じ目）へ吸い込み＋綴じ音で締まる |
| 頁めくり | 書物器の頁送り/戻り | 0.30s/頁・ホールドによる連続めくり時は最短 0.18s/頁（**同一操作部位の長押し＝同一入力の反復**——§1.3.2 の裁定・採否は 18-U1-Q2 の確定対象）——§2.6 と連動 |
| 幕遷移 | 大幕/中幕/小幕の暗転 | **時間規格は docs/38 03 §4.3 が権威**（暗転約10秒・応答窓±0.40秒・キュー3.0秒——引用のみ・G-UI-18）。画面側のフェード形状＝暗転の立ち上がり 0.8s・保持・降り 1.2s（演出時間の内側に収まる形状のみ定義） |
| 巻き戻る | キャンセル・戻る操作のフィードバック | 0.25s 逆方向フェード＋巻き戻る音 |
| 沈む/淀む | 通知の消去（Toast が視界から沈む） | 0.4s 下方へ 4px 移動しながらフェード |

#### 1.3.2 モーション規則

- **イージングは ease-out のみ**（現れ→静まる）。bounce・elastic・over-shoot は使わない（「かすれた・古い」の審美と矛盾）。
- **明滅は一拍限定**——連続閃光・速いパルスは禁止（45/04 §4.3 規則 C-6＝点滅は注意喚起の一拍限定・幕の暗転等の演出は対象外。抑制強度のコンフィグ化は 45/04 §6 #3）。
- **UI 上の動きは情報の一次チャネルを担わず増幅側に留める**——**これは本書の UI モーショントークンに限定した規則**。世界側の動き（C4）は一次チャネルを担う（規則 A-2「動くものは敵・止まったものは読める」の運動 2 値判別・ボス攻撃の見得テレグラフ——45/04 §2.2（規則 A-2）・§5.1（規則 H-2））。UI のモーションは、形・位置・文字が担う一次情報の差分の可視性を上げる補助として設計する（G-UI-06・45/01 §1.4 と同じ発想）。
- **頁送り連続入力の裁定**：頁めくり部位の長押しによる連続めくり（§1.3.1・最短 0.18s/頁）は**同一操作部位への同一入力の反復**であり新規操作体系の追加ではない——法典 §4.2 可表「書物 UI 装丁：頁めくりの操作はバニラどおり」「頁めくり演出：速度・入力は不変」（48/04 §4.2）の内側と裁定する。ただしバニラ書物に長押し連続めくりは存在せず「速度・入力は不変」との解釈余地が残るため、**採否を 18-U1-Q2 の確定対象として明示**する——不採用なら連続めくりはクリック反復のみとし、0.18s/頁の値は破棄する。

### 1.4 フォントトークン

**原則**：フォント差は「読めるか」でなく「どの時代・誰の手の字か」を運ぶ（48/04 §5.2）。3 系統は font プロバイダで実装（U4-8 承認済み・G-UI-12）。

#### 1.4.1 系統表

| 系統 | font id（仮） | 役割 | 実装方式 | 使用箇所 |
|---|---|---|---|---|

#### 1.4.2 実装規則

- **プロバイダ構成**：`font/understory.json` に `ttf`（本文）・`bitmap`/`ttf`（かすれ・幻想）を登録し、テキストコンポーネントの `font` フィールドで切替（53 §2.1）。本文・かすれ系のプロバイダ種別（`ttf`/`bitmap`）の確定は 18-U1-Q5 の対象。**幻想文字の実装方式細目（プロバイダ種別の確定・換字対象の専用コードポイント割当・登録構成）は U4 担当節が確定する**（H17 棲み分け——§0.4・docs/53 §1 U4「幻想文字フォント実装方式」）。幻想文字はゲーム内に翻訳 UI を置かない方針は不変（48/04 §2.4「ゲーム機構は翻訳しない」・§4.3 不可表）。
- **和文要件**：本文・かすれ文字はゲーム内日本語全量をカバーするグリフ数が前提——約 2,000〜7,000 字形級の和文対応書体を選定する（docs/20 §3/§8 の留意条件）。サイズは描画スケールで 9〜12px 可読（読む層の可読性はコンフィグ拡大段階と併用——45/04 §6 #2）。
- **手書き三系統との境界**：案内人筆・先達筆・王筆の「字癖」は実文（Issue #10）と装丁側が担い、フォント器は時代・書き手の差を運ぶ器に留める（48/04 §2.6）。
- **ライセンス**：同梱書体は SIL OFL 相当の再配布許可を必須条件とする。**本文・かすれ系の書体選定確定は要承認（18-U1-Q5・docs/20 §8 残件）**——幻想文字書体の実装・ライセンス細目は U4 担当節の確定事項（§0.4）。

### 1.5 UI音トークン

**原則**：UI 音も「かすれた・古い」質感で全編統一（docs/20 §7）。音は通知の一チャネルであり、字幕名は「〈主体〉：〈動作〉」二項型で登録する（G-UI-15）。

#### 1.5.1 UI 音パレット（docs/20 §7 の UI 範囲）

| 音素材 | 質感 | 用途 |
|---|---|---|
| 紙 | 擦れ・めくれ・閉じる | 頁めくり・書物の開閉・断片の綴じ込み・予告頁の提示 |
| 木の軋み | 箱・台・器の軋み | 名付けの台・掲示板・コンテナの開閉 |
| かすれた鐘 | 遠くて掠れた鳴り | 通知・解放・章の印（音量小・残響短め） |
| 綴じ音（糸を締める音） | 締まる・縛る | ノミ綴じ・結末確定・頁追加の締め |
| 巻き戻る音 | 逆巻きの軋み | 戻る・取り消し・綴じ画面からの離脱 |
| 封切り | 封蝋の剥がれ | 届いた手紙・密書の開封 |
| 静けさ/紙音のみ | 音の不在 | 設計書・05 章区間（無音区間は字幕も出さない——H-4） |

#### 1.5.2 字幕名登録規則（H15 の登録面）

- **命名型**：`〈主体〉：〈動作〉` の二項型——例「紙：擦れる」「頁：めくれる」「封：切れる」「頁：綴じる」「箱：軋む」「鐘：遠くで鳴る」「幕：落ちる」。
- **方向・距離語は許容**（「遠くで」「足下で」）、**内容言明は禁止**（正体を名付けない——「打鍵：遠くで響く」型。45/04 §5.2）。
- **無音区間は字幕も出さない**——05 章の「音がないこと」は演出であり字幕で埋めない（45/04 §5.2 聞き手規則との関係・48/02 §6 無音区間行・48/04 §5.1 詩行）。
- **登録範囲**：導線上意味を持つ SE に限定を既定（45/04 §6 #1）——言語ファイルの字幕キーに登録し、UI 音は `understory.ui.*` 命名系で管理。

## 2. 共通規格

### 2.1 画面階層

**原則**：UI の所在層を固定し、層の秩序を乱さない（P-UI-05・P-UI-06）。層は「演出層＞画面層＞世界層＞HUD 補助層＞通知層」の序列で管理する——**この序列は抑止優先度であり描画の上下関係ではない**（通知は描画上は画面の上に出るが、演出中は抑止される。描画上のオーバーラップ可否は §2.1.3-2 が規定する）。同時に開く画面は常に 1 つ（バニラと同型）。

#### 2.1.3 層の優先度と抑止

1. **演出層が最上位**——幕・綴じ画面・エンドロールの表示中は通知層の一過性通知（Title・Toast・HUD 小通知）を抑制し、キューイングして演出後に出す（幕の中に Toast は出さない——幕自体が通知であるため）。**字幕は抑止・キューの対象外**——字幕は一過性通知ではなく SE の同時表示名（45/04 §5.2 H-4：導線上意味を持つ SE は全て字幕表示名を持つ）であり、演出中に発生した音（柝・綴じ音・頁送り音等）の表示名を遅延・欠落させると、聴覚特性のプレイヤーの「音がある」検知チャネルが演出中だけ消失する（H-1）。演出内の SE は発生と同時に字幕が出る。
2. **画面層は 1 画面**——書物器を開いている最中に別器は開かない（バニラの画面排他と同型）。通知層（Toast・字幕）は描画上は画面層の上に重なってよいが（序列は抑止優先度であり描画順ではない——§2.1.1）、読み物を隠さない位置に置く（右下・上部端）。
3. **世界層は視線依存**——対象が視野外・照準外になれば消える（常時表示は由来札のコンフィグのみが例外＝U4-#9）。没腐コンパスの指しは同行者（ノミ）の身体動作として実現されるため、ノミが視界にいる間に機能する世界側の表現である（45/01 §2.2-9）。
4. **HUD 補助層は最小化**——常時の HUD 追加は行わない（没腐コンパスの指しは世界層のノミ動作が担い、HUD の針・マーカーは新設しない——45/01 §2.2-9・48/04 §4.3 不可表「HUD 矢印・浮遊マーカー」）。拍子キュー・照準ヒントは局面限定の二次補助（G-UI-22・G-UI-23）。

### 2.2 国スキン適用境界

**原則**：国スキンは「国にいる間だけ」適用、現実側の UI はバニラのまま（G-UI-02）。実装は次元判定によるリソースパック GUI 差替（48/04 §6）。

#### 2.2.1 適用判定規則

| 対象 | 判定 | 適用内容 |
|---|---|---|
| 世界クローム（コンテナ枠・HUD 枠・ボスバー枠等の GUI 装飾） | **所在次元**で判定 | 国次元にいる間＝国スキン（欠けた矩形・継ぎ目・基調パレット）。現実次元＝バニラのまま |
| 書物器の装丁（手記・図鑑・村報・予告頁・綴じ画面） | **器固有**——所在次元に依らない | これらは「物の見た目」でありアイテム固有の装丁を持つ（バニラの記入済み書物が現実でも本の見た目を保つのと同型）。現実で手記を開いても国の装丁——器は次元スキンではなく物の顔 |
| フォント（系統の登録） | 系統ごと固定・**登録は全次元で有効** | 「フォント系統は所在次元に依らない」＝**フォント ID（`understory:*`）の登録が全次元で有効**の意——登録の有効範囲の話であり、各表示がどのフォントを**選ぶ**かは下行（情報チャネル）の次元判定に従う。幻想文字は国の物にのみ出る（器側の選択——48/04 §2） |
| 字幕・由来札・照準ヒント（情報チャネル） | 機能は次元非依存・**スキンは次元判定に追従** | 表示機能はどの次元でも働く。**フォント選択も次元判定に従う——現実側＝バニラ既定フォント・国側＝本文フォント `understory:body`**（G-UI-02「現実側はバニラのまま」との整合）。枠・背景のスキンも所在次元に追従。書物器内部（手記・図鑑等の頁面）の表示は器固有の装丁として次元に依らず各系統フォントを適用する（上行「書物器の装丁」） |
| 通知音 | 質感は全編統一 | 「かすれた・古い」質感は現実側でも変えない（国の物が届く時の音は国の音——20 §7） |

#### 2.2.2 境界の白黒

- **可**：国次元での全 UI 装丁・フォント・遷移・色味の変更（法典 §4.2）。
- **不可**：現実側への国スキン漏出（クローム類——法典 §4.3「現実側での国 UI スキン適用」）。
- **裁定の明記**：書物器の装丁は器固有として次元非依存と裁定——世界クロームの次元判定とは分離して扱う（本節 2.2.1 表の二分法。要承認＝18-U1-Q4 へ記録）。
- 死亡・帰還・転移の瞬間は次元切替に追従——クロームスキンは次元変化イベントで切り替わる。

### 2.3 遷移言語

**原則**：開く・閉じる・戻るは全器で同一（P-UI-02・P-UI-06）。閉じる操作は常に有効——読み損ねを構造で潰す。

#### 2.3.1 基本遷移（全器共通）

| 操作 | 入力 | 挙動 |
|---|---|---|
| 開く | 右クリック（使用）／対象ブロックへ照準＋使用キー | 書物アイテム＝手に持って使用。掲示板・台・箱＝ブロック操作。バニラ書物・容器と同型 |
| 閉じる | ESC／インベントリキー | **全器で常時有効・例外なし**。アニメーション中（頁めくり・かすれて現れる途中）でも即座に閉じる |
| 戻る | 頁戻しボタン／右クリック領域 | 書物器内の階層戻り。最深は一覧（目次）まで——戻る操作のスタックは器の階層と一致 |

#### 2.3.2 閉じて再開可能原則（K3 の拡張——P-UI-02）

- **全ての読み物・演出画面は閉じて再開可能**：結末綴じ画面（K3 確定）・予告頁（U1-#1）・エンドロール（48/01「いつでも閉じられる・再演可」）・手記・図鑑・村報——閉じても内容は失われず、同じ状態から再開する。
- **再開時の状態保存**：綴じ画面＝選択途中の状態を保持し再度開ける（頁の帰還＝座の境へ——K3）。書物器＝前回の頁で開く（栞・帯が再開点を示す——§1.2.1）。
- **強制表示・自動進行の禁止**：プレイヤー操作なく内容が消える読み物を置かない。表示時間が問題になるのは一過性通知のみであり、その数値は §2.6 が確定する。
- **頁めくり中・語り再生中の閉じる**：アニメーションを中断して閉じる。再生済み部分は記録され、再開時は同じ頁から。
- **マルチ**：綴じ画面の開閉は個人単位——他者の画面を開閉しない（32 §6）。

#### 2.3.3 遷移の例外（幕・暗転）

幕転換（暗転＋間）は**UI の開閉操作の対象外**——演出時間規格（38/03 §4.3）に従って自動で進行し、閉じる・スキップの UI 操作を受け付けない。**ただし身体入力（移動・回避）は奪わない**——幕は演出層でありプレイヤーの身体は制限しない（§4.3.2-2 と同規定。攻撃等の動詞が進行に寄与しない局面は正典規範どおり）。ただしエンドロール/PC は「いつでも閉じられる」（48/01）——演出画面でも閉じる権利は残る。幕の暗転とエンドロールの違い：暗転は世界側の転換（全員に同期）であり、エンドロールは個人の画面再生（閉じてよい）として分ける。

### 2.4 入力規則

**原則**：前提操作は七つの身体動詞＋既存バニラ入力のみ（45/04 A-0・P-UI-09）。新規キー・新規操作体系の追加は不可（G-UI-01）。

#### 2.4.1 動詞 → 入力写像（確定）

| 身体動詞 | バニラ入力 | UI 側の受け口 |
|---|---|---|
| 近づく | 移動（WASD） | 接近時の由来札・気配表示の発火条件 |
| 拾う | 接触／使用 | 拾得物の獲得・拾得通知の発火 |
| 置く | 設置／ドロップ | 台座・箱・ゴミ箱への投入（容器操作） |
| 撞く（鳴らす） | 使用／攻撃 | 鐘・音符ブロック（A-0 の正典写像——45/04 §2.1。名付けの台は含まない） |
| 乗る | 使用 | 座れる構造物 |
| 坐る | 使用（照準時ヒントが補助） | 「観客になる」等の局面動詞——環境誘導一次・照準時最小表示は二次フォールバック（G-UI-23・H12） |
| 開ける | 使用 | 書物・箱・扉・蓋・**名付けの台**——全器の開操作。名付けの台は「命名器を開く→名を書き込む→確定」の書き込み系手続（48/04 §4.2・23 §3.3・38/02 §3.6.4②・34/06 §3.2——台は平時の手続。戦闘中のその場命名は台を用いない別手続③として §4.2.1 が扱う） |

※「名付けの台の起動＝撞く」は正典に存在しない写像（A-0 の撞く＝鐘・音符ブロックのみ——45/04 §2.1）のため確定表から除外する。「撞く」で儀式を開始する案は身体動詞語彙の拡張（正典変更）にあたるため、確定表には置かず 18-U1-Q6 として記録（推奨＝不採用・現行の「開ける/使用」写像で確定）。名付けの台の器規格（アンビル型命名器の国スキン器）は H19＝U3 §4.2 が担当。

#### 2.4.2 UI 内操作

- 書物器内の操作は**「読み・選び」の範囲**：クリックによる頁送り/戻り・選択肢のクリック——バニラ書物の操作体系を超えない（法典 §4.1-1）。頁送り部位の長押しによる連続めくりは同一入力の反復として扱う（§1.3.2 裁定——採否は 18-U1-Q2 の確定対象）。
- 名付け入力はバニラ命名器（看板/アンビル型）の入力——台への起動は「開ける（使用）」、器内はキーボード文字入力のみで、操作は不変（48/04 §4.2・23 §3.3・38/02 §3.6.4）。器の規格表自体は U3 §4.2（H19）が定義する。
- マルチで他者の画面操作・画面強制は行わない。

#### 2.4.3 ヒントの位置づけ

操作ヒント（「坐る」等）は**環境誘導が成立しない場合の二次フォールバック**としてのみ設計する——照準を合わせた時だけ出る最小表示。常時ヒント・チュートリアル画面・操作説明テキストは置かない（P-UI-09・45/04 P-1・U4-#1）。

#### 2.5.2 通知の優先度とキュー

1. **幕（演出層）＞綴じ画面＞Title＞Toast＞HUD 小通知**。演出中のこれら一過性通知は演出後にキューから出す（§2.1.3-1）。**字幕は本キューの対象外**——SE の同時表示名として発生と同時に表示し、演出中・画面閉じ中を問わず遅延・欠落させない（§2.1.3-1・45/04 §5.2 H-4/H-1）。ただし 05 章の無音区間は「音がないこと」自体が演出であり字幕も出さない確定規則（§1.5.2）が上位に立つ。
2. **同型通知は集約**——連続拾得は 1 件に集約（「○○ ×3」）して表示を溢れさせない。
3. **持続型気配は時間で消えない**——「新頁あり」「折れ目」は読了まで残る（状態表示であり通知ではない——時間切れを起こさない）。

### 2.6 テキスト表示規則（読み上げの間の確定値——H11 着地）

**原則**：全年齢で読み切れる時間を担保する（P-UI-02・53 §2.4）。数値の委譲を受けて本書が確定値を持つ（P-UI-10——以下は推奨案、承認で確定＝18-U1-Q1・Q2）。

#### 2.6.1 適用範囲の二分

- **読み手が速度を制御する器**（書物器・図鑑・村報・綴じ画面の本文）：**最低表示時間は設けない**——閉じて再開可能（§2.3.2）が構造の担保であり、読み上げの間は「頁が開いている間ずっと読める」形で実現される。
- **一過性・自動で消える表示**（字幕・Toast・Title・HUD 小通知・語り再生・自動フェード）：**式で最低表示時間を強制する**。これらは消えたら読み損ねになるため、時間で担保する。

#### 2.6.2 読み上げの間の式（一過性表示——推奨確定値）

**`T_min = T_base + N × τ`**（N＝表示文字数、上限 T_max あり）。全年齢向けに遅めの係数を取る：

| 係数 | 推奨値 | 意味・根拠 |
|---|---|---|
| `T_base`（基本時間） | 1.2 秒 | 出現を認知する最低時間 |
| `τ`（1 文字あたり） | **0.12 秒/字** | ≒8.3 字/秒——全年齢の余裕側（大人の快適読了 10〜20 字/秒の 8 割程度・BBC/Netflix 系の子供基準の系譜——53 §2.4） |
| `T_max`（上限） | 10 秒 | それを超える文は頁区切りで分割する設計側の義務（U2-R-6「朗読に耐える分量」と両立） |

#### 2.6.3 媒体別の適用値（推奨確定値）

| 媒体 | 保持時間 | 備考 |
|---|---|---|
| 字幕（独自 SE 行） | バニラ準拠（各行 ≒3 秒）。長い表示名は `T_min` 式に適合させる | 45/04 §6 #2——サイズ拡大はコンフィグ。**抑止・キューの対象外——演出中も常時表示（§2.1.3-1）** |
| Toast（拾得・解放・頁追加・気配着弾・綴じ片入手） | `3.0 秒 + 0.12 秒×文字数`、上限 6 秒 | FromSoft 型の短い通知側 |
| Actionbar/HUD 小通知（死亡遺留物・最小 1 行通知） | 2.5〜3.0 秒固定（短文のみ） | 連続拾得は集約（§2.5.2-2） |
| Title（章名・重要告知） | フェードイン 0.5s＋保持 `1.2s + 0.12s×文字数`＋フェードアウト 0.5s | 配信視点の視認要件（P-UI-08）に適合する大きさ |
| 照準時表示の消滅フェード | 約 0.3 秒 | 照準を外した時の消え方（§5.3 の器に適用） |
| 語り再生（ノミ語り・予告頁の語り） | 読み上げ音声の長さに同期＋終了後頁は残る | 音声なし時は `T_min` 式を頁単位で適用後、自動では送らない（手でめくる） |
| エンドロール「残した者たちの頁」 | 1 頁あたり **5〜6 秒**（10〜15 頁 × 5〜6 秒＝60〜90 秒——48/01 U1-#3 の確定値を確認値として引用） | いつでも閉じられる・再演可・**自動頁送りは演出画面の器規格どおり（§2.6.4 参照——読み物器の自動送り禁止とは別系統）** |
| 頁めくりアニメーション | 0.30 秒/頁・連続 0.18 秒/頁 | §1.3.1 と同値。連続めくりは同一入力の反復（§1.3.2 裁定——採否は 18-U1-Q2 の確定対象） |

#### 2.6.4 自動送り・特殊ケース

- **読み物に自動送り・強制送りのテキストは置かない**——書物・手記・語り頁等の読み物器は読み手がめくる（「読み損ね」を構造で潰す原則の裏面＝強制もしない）。**演出画面の自動頁送りは本項の適用外**——エンドロール「残した者たちの頁」の自動頁送り（頁10〜15枚×約5〜6秒＝48/01 §4.4 U1-R-5・§7-#3 承認済みの確定値）等は演出画面群の器規格（§4.4＝U3 担当節）に従い、停止・送り/戻し・閉じるは常時有効（48/01 §4.3 U1-R-4・本書 §2.3.2）。両者の分岐基準：読み物器は「頁が開いている間ずっと読める」器、演出画面は「記録の再生」器——いずれも閉じて再開可能であり、読み損ねは構造的に潰れる（P-UI-02）。
- **かすれた項・封印項は常時表示**——時間で消えない（存在の可視が仕様——K3・45/04 P-2）。
- **マルチの個別層**：表示時間は各プレイヤーの端末で独立に計算（他者の読み速度に引っ張られない）。
- **読み上げの間の最低保証**：一過性表示を読み損ねても、全ての内容は書物器・図鑑・記録頁へ着地する（読み返せる＝P-UI-02）——通知は「あることを知らせる」までの役割であり、本文の唯一の置き場にしない（G-UI-04 とも整合）。

## 3. 書物器 UI 群

> 本節は本作の「読む層」の器を定義する。P-UI-01（器は語りである）に従い、書物 UI の皮そのものが語りの一部であり、P-UI-03（バニラの器への翻訳）に従い全ての器は「書物・頁・綴じ目」の言語で装丁される（docs/48_fusion_elements/04 §5）。P-UI-05 に従い各器は実装形を明記し、P-UI-06 に従い頁面構成は形式ごとの法則で記述する（場当たり的な個別装丁をしない）。器割当は正典どおり：**目録系書物（拾得図鑑・村報）＝ Patchouli（soft dep・D-2）／拾い人の手記＝自前書物器**（docs/48/04 §6・U4-7・docs/48/02 U2-N6）。
>
> 器内の時間値（読み上げの間＝最低表示時間・頁めくり速度・自動送りの有無）は §2.6 の確定値を全器に一律適用する（26 §8・48/02 U2-R-5 の委譲どおり）。通知型（Toast/Title/書物音の使い分け）は §2.5 の統一言語に従い、本節では各器の**発火点**のみを定める（H24）。新規画面は docs/20 §6 一覧の器のみで、本節の全器は一覧内に収まる（G-UI-03）。
>
> 多重化の採番は docs/45/04 §3.2 の C1〜C8 に従う。書物器が運ぶ情報は「読む層＝深読み層」の報酬であり、一次導線・必読情報を書物 UI 単独に運ばせない（G-UI-04/G-UI-05）——よって各器の必須チャネルは「器の開閉・新頁の気配」といった器自身の状態変化を対象に置き、本文内容の読了は強制しない。

| 結末節 | 結末の記録の個人写し＋「あんたは拾い続けることにした」等の史記調 | 結末確定の都度追記 | 図鑑の結末記録と同文面（§3.5） | 34/06 §6.6 |

#### 器としての挙動

- **頁単位増殖**：拾った断片がそのまま「頁」になる（断片アイテム→手記内の頁への写像は 1 断片＝1 葉）。断片は拾うと手記に綴じられ、**綴じ済み断片は死んでも失われない**（B-2 不滅）——死亡で失うのは未登録拾得物のみ（32 §2.1）。
- **「◯◯の手記の写し」＝追体験書物**（U2-N4・32 §6）：他人のプレイ済み物語を追体験する書物アイテム。表題に「◯◯の手記より」の由来を付し、**発見演出は再生しない**（書物で読む再読型）。死亡ロスト対象外（B-11）。
- **読み返し規則の着地**：B-1（断片再読可）・B-2（綴じ済み不滅）・B-3（未収集＝欠頁）・B-4（未読表示）・B-6（閉じて再開可）・B-10（見届け後の読み返し）を本器が担う（48/02 §5）。B-7（結末の欠片は宝箱に入れない＝集積の間票付き棚）は器外の配置規則。
- **「見届ける」の後**：畳まれた世界でも手記は手元に残り読み返せる（B-10——「読み終えた本を開き直す」読み返し層として存続）。綴じ機能は図鑑と村報へ移管済みのため、手記への新規頁追加は「見届ける」以後停止する（記録が自ら続くのは図鑑側）。

### 3.3 欠頁・未読表示（綴じ目の空き・折れ目・綴じ糸色・「新頁あり」の気配）

> 三形統一文法：**白紙＝頁は開くが文字なし／欠頁＝綴じ目だけがある／かすれた項＝項はあるが読めない**。共通則は「**存在は見せる・内容は読めない**」（48/02 §6・34/06 §6.1）。本節はその器内実現形を固定する。結末綴じ画面の第三項（かすれた項）は U3 §4.1 管轄、本節は書物器側の表示を担う（H3・U2-N2）。本節の各要素は §3.1/§3.2 の器内表示であり、実装形・起動条件・状態遷移・a11y は親器の規格表を継承する。

#### 欠頁（未収集頁の存在表示）

| 要素 | 仕様 | 根拠 |
|---|---|---|
| 表示形 | 綴じ目に「頁が抜けた空き」を表示する——綴じ糸が通るべき位置に紙が無い状態。手記＝章節内の綴じ目連続に空き差し込み、図鑑＝未開放項を綴じ目の空きのエントリ殻として一覧に残す | U2-N2・48/02 §6 |
| 示すもの | **枚数のみ**（「あと何頁あるか」の数）。欠けた頁の内容・所在・拾い方は一切示さない | U2-N2（枚数のみ・内容場所は示さない） |
| 実装形 | 手記＝自前器の綴じ目装飾差分。図鑑＝Patchouli 未開放エントリを「空き項」表示（本文非表示・項名は伏字または空白）——Patchouli の locked entry を「殻」として残す運用 | 46 §3・48/02 §4.4 |
| 白紙頁との区別 | 白紙＝頁は存在し開ける（文字なし）。欠頁＝頁自体が無い（綴じ目のみ）。01 の白紙頁（絵が乱れた頁の対）は欠頁でなく白紙として配置 | 48/02 §3.1・§6 |

#### 未読表示（読んでいない頁の標識）

| 要素 | 役割 | 仕様 | チャネル | 根拠 |
|---|---|---|---|---|
| **頁端折れ目** | 未読頁の一次標識 | 未読の頁の頁端が折れている（形差分）。読了で折れ目が消える | **C2 形（主）** | U2-N2・48/02 §4.2 |
| **綴じ糸色** | 未読の補助標識 | 未読頁を通る綴じ糸の色が既読と違う | C3 色彩（**補強のみ——単独算入不可**。折れ目と併用必須：G-UI-06・45/04 §3.1） | U2-N2・45/04 C-1 |
| **表紙「新頁あり」の気配** | 閉じた状態からの通知 | 未読頁を含む書物の表紙に微かな気配（表紙の隆起＋薄い光の滲み——§1.2.1 の統一形。拾得の朱の予約域に触れない） | C2 形＋C1 光 | U2-N2 |
| 通知との連動 | 新頁追加の告知 | 頁追加は §2.5 の通知型（Toast＋書物音）で発火し、その後は表紙気配が残る——「通知＝一過」「気配＝残る」の二層 | H24・§2.5 | 48/02 |

#### 「かすれた項」（読めない項の存在表示）

- 書物器側での適用：項（エントリ）は存在するが本文が読めない状態——適用例＝**失われた物語節の項**（項は残るが素材化で消えた物語の本文は読めない——名残の記録行のみ可読）／**結末綴じ画面の「拾う」項**（頁所持者のみ本文が読める——K3 型は U3 §4.1 の画面規格、書物器側は同じ表現文法を参照）。**選ばなかった側の結末項は対象外**——選ばなかった側は「あったこと」として読める併記であり、かすれた項にしない（§3.5・34/06 §6.6。結末未確定の項は項自体を立てない §3.5 規則とも整合）。**項の存在を隠さない**（「読めない答え」のフェアプレイ——K3 の精神を書物側にも適用）。
- 表示：**項の輪郭・位置（存在）は全員に見せ、項の内容は滲み／塗り潰しで読めない**を統一形とする。項名の可読は局面で分岐——結末綴じ画面の第三項（§5.5 統一形）は項名と本文ともかすれて読めない（「三つ目がある」ことのみが届く）／失われた物語節の項は項名と名残の記録行は読め、欠落した本文のみが読めない。実現はフォントではなく**表示状態**（頁面の空白・塗り潰し・字形の滲み——48/02 §6「かすれた項＝項はあるが読めない」・§3.6「本文を持たない白紙の項」K3）とする。かすれ文字フォントは「読めるが崩れた字形」の用途（深部の乱れた筆致・古い文書の表記）に限定し、「読めない」の実現には使わない（48/04 §5.2 フォント割当どおり）。
- **選択不可・読了不能は内容ではなく存在を示す**——かすれた項は読めないことが正典のためコントラスト規則の対象外（45/04 §4.3 C-4 と同型の扱い）。

### 3.4 予告頁（交付・表示・挿絵頁・語り再生・閉じて再開——U1-#1/#2 確定値の UI 化）

> U1-#1（交付規格）・U1-#2（挿絵器）の確定値を器に落とす節。語り内容の設計（声・色・一場面・禁止事項）は 48/01 §2 が権威——本節は**表示と遷移**を定義する。

#### 器の規格表

| 名称 | 実装形 | 起動条件 | 構成要素 | 入力操作 | 表示内容 | 状態遷移・閉じ方 | 多重化 | 共有/個別層 | a11y・コンフィグ | 根拠 |
|---|---|---|---|---|---|---|---|---|---|---|
| 予告頁 | **図鑑内の頁**（Patchouli image+text 頁。不採用時＝自前書物器の画像頁）＋交付時の語り演出（ノミ綴じ→語り→頁提示） | 各章クリア（01〜05 各 1 頁・計 5 頁・序章なし）。結末綴じ→章の幕切れ→幕開け（救出・色の回帰）の後、交付はノミ綴じイベントとして発火 | 交付演出（ノミ綴じ動作→図鑑挿入→語り再生→頁提示→環境残響）・頁本体（挿絵 1 枚＋引用行 1 行＋かすれ軸の色） | 交付中は視聴のみ（既存入力でスキップ可＝閉じる操作）。頁提示後は通常の書物操作。閉じて再開可 | 声＝引用行 1 行（案内人筆・主名不言明）／色＝次章パレット（かすれ軸）／一場面＝挿絵 1 枚（正方形・写実でも実シーンでもない・文字禁止 Y-2） | 交付：自動進行（ノミ綴じ→挿入→語り 1〜2 行→頁提示）。**いつでも閉じて再開可**（K3 構造保証の拡張——交付を中断しても頁は図鑑に残り、図鑑を開けば同じ頁が読める） | 交付＝ノミ綴じ動作（C4）＋語り（C6 音声＋C7 字幕）＋頁の光（C1）。環境側二重化＝朧な光の気配が同じ方角へ残る（Y-5・45/02 U2-D） | **各自の図鑑に綴じ・対象は共有**（U1-#1）。未読の予告頁を持つ者同士で内容共有は自由（読む層） | 語りは字幕名「ノミ：語る」で字幕化。挿絵に文字を入れない（Y-2）。方角のみ語り距離は濁す（Y-4）。実シーン予告禁止（45/01 §5） | 48/01 §2/Y-1〜Y-13・28 §6/U1-#1・45/02 U2-D・17 §3 |

#### 交付シーケンス（Y-12 の UI 化）

```
結末確定 → 章の幕切れ（大幕・幕切れ：暗転約10秒＋綴じ音のみ残るツナギ——38/03 §4.3・48/01 I-1〜I-2）
  → 幕開け＝救出・色の回帰（彩度回帰＋動き復帰＋音復帰の三点——48/01 I-3④・45/04 A-4/C-2）
  → ノミ綴じ動作（頁を図鑑へ）
  → 図鑑に頁が挿入される（頁追加演出＝器内の頁めくり＋光）
  → 語り再生（声＝引用行 1 行をノミが語る：音声＋字幕）
  → 頁提示（挿絵頁が開かれた図鑑の見開きとして提示）
  → 環境残響（同じ方角へ朧な光の気配が残る＝環境二重化 Y-5）
```

- **中断・再開**：交付のどの段階でも閉じられる（閉じる＝バニラ書物閉操作または既存入力）。閉じても頁は図鑑に綴じ済みで残り、図鑑を開けば同じ頁が読める（K3 の閉じて再開可構造を交付に拡張——U1-#1「閉じて再開可」明記どおり）。
- **読み上げの間**：語り行の提示時間・頁めくり速度は §2.6 の確定値（26 §8 の規範に基づく数値）。
- **環境側二重化**：ノミが「淀んでいる方角」を語る際、環境側も同じ方角へ朧な光の気配を残す（45/02 U2-D・Y-5）——語りと世界の一致。朧な光は気配級（補助〜主要境界）で、追う義務はない。
- **05 クリア後の幕開け＝総集編演出（I-4）**：第5章クリア後の幕開けは通常の救出・色の回帰でなく「**座への道が開く**」総集編演出——結末の一音だけが国の果てに届き、鐘の残響が全環礁を渡る見せ場で章が閉じる（48/01 I-4・34/05 §7）。その直後に終章の予告頁が交付される。
- **条件付き滲み（Y-6）**：落慮王断片を拾得済みなら座の気配が滲む、05 クリア後は「いつもと違う綴じ」（ノミの仕草の差分）——本文に入れず綴じ方の演出に留める。

#### 挿絵頁（U1-#2）

- **器**：書物スキンの画像頁を基本とし、Patchouli 採用時は Patchouli `image` 頁、フォールバックは地図アート（マップ画像）。挿絵は**正方形 1 枚**・章基調色・写実でも実シーンでもない絵・文字を含めない（Y-2）。
- **選択対象**：N-ECO-901 の淀み指標（未攻略章の未消化断片数＋素材見込み数・同値は昇順・05 解禁後は 05 固定）——表示層は指標値を見せず、方角の語りのみで表す（Y-4）。
- **手記側**：手記には予告頁の綴じ先はなく、**再読用の索引のみ**（U1-#1）——「次章の予告頁がある」という見出し行のみで頁本体は複写しない。

### 3.5 結末の記録（各章選択と世界変化の記録形式）

> 結末綴じ画面（選択を行う画面）は U3 §4.1 管轄。本節は**選択の結果が図鑑に残る記録形式**を定義する（H4）。器は拾得図鑑「結末の記録」節＋手記「結末節」の二箇所。同文面を両器に写す。本節の記録形式は §3.1 図鑑・§3.2 手記の器内表示であり、実装形・起動条件・状態遷移・a11y は親器の規格表を継承する。

#### 記録形式

| 項目 | 仕様 | 根拠 |
|---|---|---|
| 文体 | **史記調続体形**——「あんたは書き換えた」「あんたは見届けた」「あんたは拾い続けることにした」。章別の世界変化は「あんたは月を満ちさせた」型の結末固有行 | 34/06 §6.6・26 §3.7 |
| 選ばなかった側 | **両方残る**——選んだ側を主文・選ばなかった側を「あったこと」として併記（「あんたは書き換えた。もう一つの答えも、あった」） | 34/06 §6.6・45/02 §7-1 |
| 書き換え後の記録 | 書き換えても各章の記録は「**綴じ直された**」として保存——旧記録は消えず、新記録が綴じ直しとして追記される | 34/06 §6.2・22 §2 |
| 共有/個別 | **共有層＝「◯◯が綴じた結末」**（世界の記録——誰が結末を綴じたか）／**個別層＝「私が関わった」**（個人図鑑の記録——自分が選択した・関わった視点） | 32 §6・45/02 §7-3 |
| エンドロール再演 | 図鑑の結末記録からエンドロールを再演できる（U1-R-4——再演画面自体は U3 §4.4、本節は起動点＝結末記録項に「再演」導線を置く） | 34/06 §7.3・48/01 U1-R-4 |

#### 各章の記録項目（章 × 記録内容）

- 01〜05 各章＝二択のうち選んだ側＋選ばなかった側＋章固有の世界変化行（「あんたは月を満ちさせた」等）。終章＝三択。
- 記録は**結末確定の都度**図鑑に追記され、未完成の章は項自体が未生成（欠頁でもかすれた項でもない——結末未確定の項は「まだ記録がない」状態として項を立てない。項が立つのは確定後）。
- 「見届ける」の後は畳まれた世界でも図鑑の結末記録は残り（村報最終号と同じく「読み終えられた記録」として存続）、村の殻でも再読・再演可能。
- **没腐漂着物「未完の頁」の記録文分岐**：序章小選択①（終わらせる／残す）の結果で図鑑の記録文が分岐する——終わらせた場合は「終わらせた」旨の記録行、残した場合は「まだ読まれていない」旨の記録行（34/00 §109）。「未完の頁」の語はこの序章の記録対象（没腐漂着物）に限定して使い、終章の拾得必須物＝前任の白紙の頁とは別語とする（§5.10——用語の使い分け）。

|---|---|---|---|---|---|---|---|---|---|---|

#### 発行規則（U2-N5）

- **発行トリガ＝定期＋臨時の二系統**：
  - **定期号**＝①章クリア毎 ②救出住人加入毎 ③施設解放毎（48/02 §4.3・U2-N5）
  - **臨時号**＝名付け・結末確定・ポストクレジット級の特別号外（U2-N5 の臨時枠）
- **文体**：朗らかな村内新聞（26 §3.7）——「記録」でなく「村の新聞」として書く。内容は発展/住人/解放の三要素（H5）。
- **「見届ける」の最終号**＝畳まれた村の殻に残る読み物（K11・34/06 §7.3）——村報発行所が残り、最終号が殻に貼られたまま機能する。図鑑の村報節にも同号が綴じ込まれる。
- **綴じ役の帰着**：「見届ける」以後はノミが畳まれるため、村報の発行は「記録が自ら続く」演出で村報発行所→図鑑へ移管（K1・34/06 §7.3）。
- **Patchouli 採用時**：村報は図鑑の村報節エントリとして収録可能（U4-7 器割当＝図鑑系は Patchouli 統一）。

#### 装丁運用の器内則

- **読み上げ演出の割当**：形式列の「読み上げ演出」は聞く層の音設計（BGM 形式差・紙音・環境音）で、頁を開いた際の形式別の演出音を定める。無音区間（05）では字幕も出さない（45/04 §5.2 H-4・規則——「無音」は聴覚系統として扱い視覚に全翻訳）。
- **字幕**：書物器の音（頁めくり・綴じ・封切り）は「〈主体〉：〈動作〉」二項型の字幕名を持つ——「紙：擦れる」「封：切れる」「頁：めくれる」「頁：綴じる」（U2-R-7・45/04 §5.2・U4-#3）。内容の言明は禁止。
- **幻想文字**：幻想文字の刻印・書き入れは「読めない文字」の字形のまま表示し、翻訳 UI・対訳辞書 UI は作らない（H25・48/04 §3・G14——対訳は余白の書き入れ考察層の楽しみとして残す）。

#### 4.1.3 起動条件

- **撃破→静まり→結末選択**（通常章）：ボス撃破の直後、痕跡密度の最大地点が静まる一拍を置く（45/02 §7.3「待っていた場所」の静まり）。その後、白紙の最終頁が開き結末綴じ画面へ（34/01 §6.1・48/01 §3.4-1）。
- **終章の綴じ画面**は三択が常時表示される点で通常章と別格（§4.1.5 終章型参照）——起動＝玉座の間の対峙（迎え→呈示→空の椅子→問いの二連）の直後に開く（34/06 §5.2・45/02 §7.3）。頁を全て拾い集めた者は「書き換える権利」を得て綴じ画面に戻り、改めて三択から選べる（K8）。
- **殴る＝綴じ画面を割り込んで「書き換える」経路の戦闘に入る早期入力**（終章固有）：問いを飛ばして王へ攻撃入力した者は畳み込み戦へ突入するが、**これは結末の確定ではない**（K7＝「殴る＝書き換える」ではない——結末を確定するのは綴じ動作の先着のみ。殴った者は記録上「書き換えようとした者」として並記・34/06 §5.3・32 §6）。通常章の綴じ画面には攻撃対象がなく、本入力は発生しない。

#### 4.1.5 終章型：三択と白紙の項（T4・K3/K7/K8）

- **三択が常時表示**されるが、「拾う」項は**白紙の項**（本文を持たない空白の項）として現れる——非所持者には**かすれた項**（項名と本文ともかすれて読めない・輪郭と位置のみ可視＝§5.5 の統一形）として「ある」ことだけが全員に常時表示（K3・45/04 P-2・U3-D 承認・45/02 §7.3：「あるが読めない第三の項」として隠さない）。
- **読めるのは頁所持者のみ・選択も所持者のみ**（前任の白紙の頁＝選択前提・K3・48/02 §3.6「拾う」の形式条件）。非所持者には項の存在と「読めない」状態のみが届く。読めないまま選ぶ盲目選択はさせない——選択可否と可読性を一致させる（34/06 §6.1）。
- **頁の回収経路は五重保証**（K3——(a) 通路の拾得必須物→(b) 見落とし時ノミが入口で手渡す→(c) 綴じ画面は閉じて再開可→(d) かすれた項の常時表示→(e) 手放された頁は元の場所に還る・45/04 X-2 雛形・32 §6）。
- **確定系は三系統**：書き換える（戦闘あり）／見届ける（畳む・戦闘なし）／拾う（頁所持者のみ・続体形）——選択制ボス N-BOS-06 の発生条件もこの三系統に連動（34/06 §5.3・16 §6.3.6）。
- **戦闘経路からの戻り**：項選択または殴る早期入力で N-BOS-06 戦に入り頁を全て拾い集めた者は「書き換える権利」を得て綴じ画面に戻る——改めて三択から選べる（K8・34/06 §5.4）。権利を持つ者が「書き換える」を選んだ場合は再戦闘せず直接最終頁を書く局面に進む（34/06 §5.3）。戦闘中に空の椅子に坐る／頁を拾い切る＝その者の戦闘離脱であって結末確定ではない（32 §6）。
- 頁収集の進行は**ノミの頁数え動作**で非言語可視（拾い上げられた頁をそっと数える仕草——数字表示なし・45/04 §2.5 M-3・48/03 §5.7・34/06 §5.4）。

#### 4.1.6 多重化（必須チャネル適合——45/04 §3.2）

- **第三項の存在の可視**：かすれ表示（C7＝「読めないが形がある」）＋頁の位置（C5＝頁所持者の画面でのみ本文が現れる位置の確保）＋ノミの手渡し・検分動作（C8＝二次装置）＝3系統（45/04 §3.2 の正典例どおり・P-2）。
- **綴じ画面への誘導（主要⑤）**：見開きの開き方＋項の形（C4+C2）＝2系統。

#### 4.1.7 a11y・コンフィグ

- 綴じ画面・項のテキストはコントラスト規則の対象（45/04 C-4）。**かすれた項は読めない設計が正典**（K3）のためコントラスト規則の対象外——「項の存在の可視」は枠・位置の形で担保。
- 読み上げの間＝最低表示時間（docs/26 §8・Issue #3/#18 確定値を引用——実数値は持たない。着地の担保は §7 18-U3-Q11）。項ボタンの大きさ・文字サイズはコンフィグ対象（Issue #34）。
- 確定の取り消し不可＝**警告表示のみ**（確認ダイアログを増やさない。「選ぶ＝捨てる」の不可逆性を器の性質として教える型——G-UI-01）。→ §7 18-U3-Q4

#### 4.1.8 誘導・静まり・配信

- **結末地点への誘導**：アリーナの淀みが最深部へ収束し、撃破後は静まり＋月一拍（時間の再開の合図）が綴じ画面の開きを告げる（45/02 §7.3・34/01 §6.1）。結末地点は明示級の一点のみを一視界に置く（45/02 §7.3・45/01 §3.1 強度三段）。
- 静まりの「間」は情報を置かない（45/04 C-6——幕の間は演出であり、暗転中に操作要求・情報を挟まない）。
- **配信**：「書き換える派？見届ける派？」の議論（docs/17 §6）と「あるが読めない第三項」の発見が視聴者にも同じ情報として届く（docs/17 §6）。項のかすれ・欠片の器・先着記録は配信視点でも読める強度（P-11・45/04 X-4）。

2. **幕間中は攻撃・キュー・進行変化が発生しない**（48/03 §3.4 幕間中規則——幕間は舞台枠組みの切替＝全要素のリセット）。一方で**移動・回避の入力は奪われない**——幕は演出層であり入力は生きる（ただし攻撃が進行に寄与しない章固有規則＝34/03 §5 第三幕「観客になる」等の例外は正典の規範どおり・U2-C）。
3. **アリーナ離脱＝幕間の中断**として扱う——再進入で同じ幕が上がり直す（幕の巻き戻し・48/03 §4.4・docs/15 §5・U3-N5）。幕の内部状態（フェーズ・展開）はアリーナ帰属で保存し、離脱→再進入で「まだ終わらない」が演出として読める。
4. **柝一拍**＝転換の合図（柝系の短い一拍＝全幕共通の効果音・音色は章固有——38/03 §4.3・U3-N2。字幕表示名登録候補——「拍子：幕間を繋ぐ」等・48/03 §3.3）。視覚代替＝舞台装置の動き・幕の開閉の形（45/04 §5.3・H-1）。
5. **フェーズ転換時の一拍の静まり**——45/02 §7.3「待っていた場所」の静まりを転換の型として流用（転換前に一拍、戦闘音が引く間）。幕間の「間」は演出であって操作要求を挟まない（C-6）。
6. **段間転換（N-BOS-06 固有の別規格）**：終章選択制ボスの段間は**短い「一拍の間」（暗転＋柝一拍・各約5〜8秒）＋頁排出演出**（各段 1/3・2/3・完遂で1枚ずつ計18枚・全て拾得物——38/03 §4.6）。**フル幕間（暗転約10秒）は段3→4の中点に1度だけ**置く（270〜300秒戦闘の呼吸点——U3-N7 承認）。「段間転換」は 06 の6段構造固有の語——他章ボスのフェーズ転換とは混同しない（同じ区別を §4.3.1・§4.3.5 にも適用）。

#### 4.3.3 幕切れの三要素（48/01 §3.2-3.4——U1-#4 承認済み）

1. **暗転**——約10秒（38/03 §4.3 権威・引用のみ）。暗転の最深部に**一点光を残す**（漆黒を避ける・48/03 §6——幕切れは喪失でなく転換の読み）。
2. **間**——綴じ音のみが残る静けさ（頁を閉じる・綴じる作業音＋字幕表示名候補——「頁：閉じる」等）。間の間に情報を置かない（C-6——「音だけの内容」は許容・48/03 §3.4）。
3. **幕開け**——転換先の初景（「別の場面になった」が読める）：救出・色の回帰の光景＝**彩度回帰＋動き復帰＋音復帰の三点**（彩度だけに依存しない——点灯個数の増加・揺れの再開・環境音の復帰を必ず重ねる C-2/G7・45/04 §2.2 A-4）。**幕開けの初景は設計対象**——幕が上がった直後の数秒はその場面の読みを一画面で渡す構図（45/02 §7.2 幕開けの初景・48/01 §3.2-3.4 幕切れ三要素——U1-#4「幕開け＝救出・色の回帰」。なお 45/02 §7.2 本文の「U3-N9 承認」タグと「48/03 §3.6」節参照は正典側の誤記——U3-N9 は 48/03 §5.5「音だけの劇」特例であり 48/03 に §3.6 は存在しない——§7 18-U3-Q10 に記録）。
4. **幕開け後の接続**——救出の初景（色・動き・音の回帰）から**予告頁交付**（§3.4 U2 領域——ノミ綴じ→図鑑挿入→語り再生→頁提示の交付シーケンス・U1-#1）へ滑らかに繋ぐ。幕開けの感動が予告の「次の気配」へ流れる構成（48/01 §3.4）。

#### 4.3.4 特殊幕・オプション幕（台詞なしの型）

- **観客化の幕（03章）**：客席に坐る＝劇の開始合図——幕が上がるのは座った瞬間（環境一次誘導：舞台の光が落ち客席だけが明るく残る視線誘導＋人形が客席を指し示す＋坐るべき空き席が光る——U2-C・U4-#1・16-U3-Q6 承認。操作ヒント＝対象へ照準時の「坐る」アクション表示を二次フォールバック・P-1）。
- **合唱の幕（05章）**：響界の共感覚を幕として使う——音が見える世界で幕の転換を光の波紋で演じる（34/05 §3.2・45/04 M-4）。**幕間自体が最大の転換演出**——第一連→第二連の幕間＝大鐘が初めて鳴く（「音だけの劇」特例・U3-N9・48/03 §5.5）。柝が出せない章では全予告を身体＋光で担う視覚一本立ち（U3-N9・45/02 §7.1）。
- **座の幕（終章）**：玉座の間の対峙＝幕の機構の最終使用——呈示（頁を繍るたび幻の風景が座の上に展開）を幕開け、空の椅子への坐る（個人離脱＝その者の戦闘のみ止まり綴じ画面へ）を幕切れとする対の型（34/06 §5.2/§5.4・32 §6・16 §6.3.6）。段転換の幕間は §4.3.2-6（U3-N7）の別規格どおり。

#### 4.3.5 a11y・コンフィグ

- **一点光を残す暗転**（漆黒回避）・幕の暗転はシェーダー非依存の演出で構成（C-5——暗転そのものは演出層・必須情報は載せない）。
- 幕の暗転長・「間」の長さの規格は **38/03 §4.3 が権威**（引用のみ——G-UI-18）。幕間・章幕切れの暗転＝各約10秒はいずれも §4.3 の権威値。**段間転換（各約5〜8秒＋段3→4中点にフル幕間1度）・応答窓 ±0.40秒・キュー間隔 3.0秒**は 06 固有の別規格・確定値として引用（38/03 §4.6・§4.3・U3-N7）——本書に実数値を持たない。
- **配信モード**（演出抑制のコンフィグ）：暗転の長さを削る程度に限定し、幕切れ三要素（暗転→間→幕開け）の構造と多重化は削らない（45/04 §6 #7・**docs/17 §8・U4-11 確定**——専用の「配信モード」画面は作らずグローバルコンフィグで演出強度・スキップ可否を調整。Issue #34 コンフィグ設計へ引継ぎ——G-UI-19）。

- **宛名のない届け物**（拾う結末）：村の共同ゴミ箱に誰が捨てたかも誰宛かも分からない包みが着弾——中に**読まれたことのない頁**（N-ITEM-076）が一枚＝「まだ拾われていない物語」の物理的な姿（34/06 §7.3・48/01 §5.2 PC-1・N-ITEM-082）。
- **新しい捨て場の影**（書き換える結末）：書かれた世界の端に選ばれなかった側が生まれ始める遠景の差分（気配級の遠望——C3 差分級）＋図鑑の結末記録に循環の記述（34/06 §7.3・48/01 §5.2 PC-1・T3）。
- **村報最終号**（見届ける結末）：畳まれた村の殻に残る最終号——「読み終えられた世界では記録が自ら続く」型の最後の配達（34/06 §7.3・48/02 §5 U2-B-10・U2-N5 承認）。図鑑の村報節には同号が綴じ込まれる（§3.6 発行規則どおり）。拾い人の手記は「見届ける」以後の新規頁追加が停止するため（§3.2・U2-B-10）、最終号の写しは図鑑側にのみ綴じ込まれる。
- **最後の手紙**（見届ける結末）：村の画面でなく**現実のプレイヤーのゴミ箱へ届く一通**——灯台守が初めて自分の手紙を書き世界の終わり際に投函し、終わりの後に届く（K9「届いたものは終わりの後にも届く」＋K10 別の一通——宛先＝**現実のプレイヤーのゴミ箱**のみ。座の届きもの棚への「拾い人宛」フォールバックは座に流れ着いた返信＝没配便側の物流規則に限定され、本通には適用しない——34/06 §6.3/§7.3・48/01 §5.3 PC-3。docs/28 §10.6 の括弧書き（「没配便として座に流れ着いた返信」）との齟齬は §7 18-U3-Q10 に記録）。
- **新異物報せ**（**見届ける結末限定**）：現実のどこかに新しい異物が生まれる報せ——器は既存機構の自然発動（新異物生成＝棄てが極まった場所に追加生成・docs/32 §4.1＋縁の羅針盤が新方角を指し始める・Issue #31 U1-Q4。村報最終号の一文が報せを含めてもよい）。「拾う」＝宛名のない届け物、「書き換える」＝新しい捨て場の影がそれぞれの結末のリプレイ導線——全結末共通への拡張は行わない（48/01 PC-3・34/06 §7.3・36a §7）。
- 通知の型は**着弾時1回＋物は常設**（U1-#6）——着弾通知＝ゴミ箱の蓋の動き＋光＋字幕（45/04 §5.3 届きものトークンの型）。通知の保持時間・再通知の扱いは §7 18-U3-Q3（U1-#6 の「着弾時1回」を通知の消え方まで含むか未規定のため）。見届けるの後、新たな投函への返信は来ない（K14・PC-4——返信機構は結末と共に閉じること自体が演出）。

#### 4.4.5 a11y・コンフィグ

- ERの頁送りは自動だが**いつでも閉じれる**＋頁送り速度はコンフィグ（45/04 §6 #10・Issue #34）。自動送りを止めて手動頁送りにする設定を持つ（読み上げの間の確保・docs/26 §8 基準——着地は §7 18-U3-Q11）。
- 名の一覧は書物頁（C7）＋頁送りの動き（C4）＋送り音と字幕（C6+C7）で多重化——読み物として成立する器（45/04 C-4 コントラスト適用）。

### 5.6 字幕表示名

バニラ字幕システムへの独自 SE 表示名の登録規則（XAG 106・G-UI-15）。命名規則は「〈主体〉：〈動作〉」二項型＋方向語許容・内容言明禁止（U4-#3 承認済み）。

| 名称 | 実装形 | 起動条件 | 構成要素 | 入力操作 | 表示内容 | 状態遷移・閉じ方 | 多重化（必須チャネル適合） | 共有/個別層 | a11y・コンフィグ | 根拠（出典節） |
|---|---|---|---|---|---|---|---|---|---|---|
| 字幕表示名 | バニラ字幕システム（言語ファイル `subtitles.*` キー登録） | 独自 SE の発音時（表示対象はコンフィグ粒度に従う） | 右下字幕領域に「〈主体〉：〈動作〉」の 1 行。方向語は括弧でなく直付（「遠くで」「足下で」「頭上で」） | なし | 音の聞こえ方の名（音源の正体でなく、聞こえる音の種類）。内容のネタバレ・正体言明は禁止 | SE 終了と同時に消える（バニラ字幕の表示時間に準拠） | 聴覚 C6 のペア（C6 は C7 とのペアでのみ算入） | 個別層（字幕は個人のクライアント表示。環境共有情報は別に環境が担う） | §6.1 #1（粒度：意味を持つ SE 限定/全 SE/OFF）・#2（サイズ・表示時間） | Issue #31 U4-#3・45/04 §5.2 H-4・48/04 §4.2 |

**登録規則**
- **二項型**：「〈主体〉：〈動作〉」——例：「鐘：鳴る」「郵便船：軋む」「紙：擦れる」「拍子：鳴り続ける」「打鍵：遠くで響く」「ゴミ箱：鳴る」「小さな鐘：微かに鳴る」「人形：踊る」「頁：めくれる」「淀み：響く」。
- **方向語**：「遠くで」「足下で」「後ろで」「頭上で」を許容。距離の精密化はしない（方角はバニラ字幕の矢印に任せ、語彙は曖昧のまま）。
- **禁則**：音の正体・内容の言明をしない（「打鍵」の正体は最深部で環境が明かす——F-U4-R11）。主体名は「聞こえる音の種類」に限る。
- **無音の扱い**：第5章の無音区間では字幕も出さない——「音がないこと」自体が演出（45/04 §5.2）。
- **登録対象の基準**：導線上意味を持つ SE（遠い汽笛・打鍵音・紙擦れ・拍子・鐘・没腐の歪み音・異物の気配音・頁をめくる音・ゴミ箱の投入音等）＝45/04 §5.2 の列挙を既定対象。全登録 SE の語彙表は Issue #4（音）との共同管理とする。

### 6.3 配信対応

- **専用画面は作らない**（U4-11 承認・G-UI-19）——演出抑制・強度調整は全て §6.1 のコンフィグで対応。
- **視認強度（30 秒基準）**：最重要・主要の情報は視聴者が配信解像度の画面から読める強度とする（45/04 X-4・17 §3）。具体的な下限——字幕名・由来札・照準表示はバニラ字幕準拠サイズを下限に拡大段階を持つ（#2）、拍子印・頁形通知は画面下端〜右下の認識域で 1 回の視線移動内に収める大きさ。迷子・詰まりは配信の事故になるため、多重化（§6.2 表）はそのまま配信品質の担保になる。
- **短縮の境界**：#7 の短縮は**暗転の長さを削る程度**に限定し、幕間の「間」に置く情報の多重化・三重信号は削らない。
- **綴じ画面＝配信の山場**：結末綴じ画面（§4.1）は三択の視認性とかすれた項の存在（§5.5）が「コメントが沸く形」の要件——視聴者が「三つ目がある」と画面だけで読める強度が必須。マルチ視点差分（由来札・頁所持者のみの項）は同席者が別視点を観に行く理由として機能（17 §5）。
- **配信者向け提供素材**：シェーダー推奨設定・導入手順は docs/17 §7・46 D-7 の成果物側（Issue #8 手渡し）——本書は UI 側の視認要件のみを担う。

### 6.4 シェーダー共存の UI 要件

- **描画非依存の成立**：本書の UI 要素（HUD 層・ツールチップ・字幕・Screen・Toast/Title）は全てバニラの GUI/字幕パイプライン上にあり、シェーダーの色彩・ポストプロセス処理に乗らない——**UI レイヤはシェーダー ON/OFF で変わらないこと**が合格条件（G-UI-11・45/04 C-5）。
- **環境側演出の代替**：幕の暗転・朧な光・彩度勾配・霧滞留といった環境側演出はシェーダーで外見が変わり得るため、必須チャネルは C1 光（明度）・C2 形（輪郭）・C4 動き・C5 位置で構成し、バイオーム着色・粒子色・空の色は補強に留める（C-5）。シェーダー OFF 時の一次代替は 45/02 各章表の OFF 時併記どおり（灯台残火型＝霧が濃くなる側の光源とのペア）。
- **対象シェーダーの確定**：docs/20 §8 の残件「主要対応シェーダーの決定」は本書の確定対象——推奨3系統（Complementary Shaders - Reimagined・BSL Shaders・Sildur's Vibrant Shaders＋Iris/Oculus 実行環境——占有率の高い代表系統をカバー）を §7 18-U4-Q14 として登録。
- **検証項目（Issue #34/#6 への手渡し）**：確定した対象シェーダー×（異物演出・次元空・ボス演出・UI）の表示確認に加え、本書の各表示（字幕名・由来札・拍子印・かすれた項・没腐コンパスの指し）が OFF で一次チャネルとして機能することをプレイテスト検証項目に登録（20 §4・U2-K）。「色を取り戻す」完了表示の配色シミュレーション（protan/deutan/tritan）は環境側と併せて検証（U4-#7）。

### 6.5 祭囃子没腐姿の造形メモ（docs/16 §5.3.4・16-U3-Q1 への注記）

> 正典の三段構成（16-U3-Q1 承認）は以下の通り：(a) 下半身＝指揮台機構への接合（装束に糸巻きと拍子歯車が食い込む）(b) 両腕＝操り糸状機構に接続・鈴と扇を持つ腕のみが拍子を刻む (c) 頭部・上半身＝人の姿を保つ。デザイン側の造形詳細（衣装・表情・部位の見え方）は Issue #3 領域と正典指定されているため、本書はその概略メモを置き、docs/16 §5.3.4（16-U3-Q1）への注記とする。モデル実装側の手渡しは Issue #15（ボス/モブ数値・全表）または新 Issue 起票へ——Issue #2（構造物・ダンジョン）は完了済みのため受け皿にしない。

- **全体の読み取り設計**：遠望では劇場の暗がりに隠れ「機構だけが動いて見える」（34/03 §3#7——人形の列だけが遠目に踊る）。客席に着いた時に初めて**人の顔が見える**＝悲劇の開示（「演目そのものが彼女だった」と分かる瞬間）。
- **衣装**：祭りの囃子装束——褪せた祭り色（03 章パレット：褪せた祭り色・提灯の残光）。審美の「継がれた」面を担う：装束は**直され続けた祭り装束**（継ぎ・折れ目・重ね仕立ての痕——機構に食い込まれた裾の裂けは「巻き込まれた」でなく「長い時間そこにいた」形）。
- **下半身（接合部）**：指揮台の祭具時計台への接合——糸巻きと拍子歯車が装束に食い込む。布と機構の境目は「埋まった」のでなく「絡まった」形（継ぎ目の審美——欠けた接合）。
- **両腕（機構接続）**：操り糸状の機構に繋がれ、鈴と扇を持つ腕のみが拍子を刻む——**拍子の刻みは機構由来であり、彼女自身の手は止まっている**（刻ませられている、が読める形）。腕の動きは機構のリズム（キューと同期＝彼女はキューの一部として読める）。
- **頭部・上半身（人の姿）**：表情＝**待ちの静けさ**——涙や苦しみの顔でなく「祭りが来るのを待ち続けた者」の目。髪飾り＝祭りの簪（彼女が祭りの演者であった名残）。顔は舞台面の照度内にあり、見得視認（人形側）の妨害にならない配置（指揮台は舞台中央奥）。
- **復帰演出（撃破後）**：機構が一拍ずつ緩む逆巻き→糸が緩み装束が下ろされる→彼女が舞台中央に降りる＝**劇場で初めて舞台中央に立つ者**→結末選択へ（16 §5.3.4）。救出後の指揮台は空の祭具として殻に残る。
- **キューとの整合**：画面内拍子 UI（§5.2）は二次補助——一次合図は人形の構え＋提灯・幕の動きであり、祭囃子の腕の刻みはその環境合図の一部（彼女の動きが拍子を読ませる——彼女の姿自体が「読み合いの器」）。
