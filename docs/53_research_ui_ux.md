## 2. 先行研究

### 2.1 NeoForge / MC 1.21.1 の UI 実装実態

- **画面の型**：カスタム画面＝`Screen`（GUI を持つ全画面 UI——書物・綴じ画面・設定）／コンテナ画面＝`AbstractContainerScreen`（スロットを持つ器——台座・ラック・箱系）／HUD＝`GuiLayerManager` の overlay 層（ホットバー・ボスバー・字幕・照準テキストの層管理。カスタムレイヤー追加可）／テキスト通知＝ Title/Actionbar/Toast のバニラ器
- **フォント実装**：`font` プロバイダ（`ttf`/`bitmap`/`reference`/`space`/`unihex`）で書体を登録——**幻想文字は新規 `ttf` または `bitmap` プロバイダ＋架空書体1系統**で実装（48/04 U4-8 承認済み方針）。本文・かすれ文字は別書体または同書体のスタイル差分。リソースパック差し替えと共存可
- **Patchouli**：`book.json`＋カテゴリ/エントリ/頁（text・image・crafting・entity・relations 等の標準頁型）。外見カスタムは概略：表紙テクスチャ・頁背景・進行アイコン程度。**ファクシミリ表現（挿絵が頁面を占める・形式別装丁・かすれ演出）には表現幅不足**→ 拾い人の手記は自前書物器で確定済み（48/02 §4.4・D-2）
- **自前書物器**：バニラの「記入済み書物画面」を置き換える独自 Screen——頁めくり・見開き・装丁スキン・折れ目・読了マークを自前実装。マルチでは読了状態をプレイヤー NBT/能力データに持つ
- **JEI 連携**：カテゴリ実装（`IRecipeCategory`）＋レシピ表示制御——隠すレシピ（招待状等）は `IRecipeManager` 制御で非表示（46 D-1・14 §末）
- **ツールチップ/由来表示**：`ItemTooltipEvent` で由来札を挿入（ホバー時のみ・既定）。照準時アクション表示は `RenderGuiOverlay`/字幕相当の最小テキスト
- **字幕**：バニラ字幕システムへの独自 SE 名登録（表示名は言語ファイル）——「〈主体〉：〈動作〉」二項型（U4-#3 承認済み）
- **マルチ同期**：綴じ画面の開閉・頁所持・読了は個別層（プレイヤー単位）。画面内の他者表示は共有層

### 2.2 読み系ゲームの UI 作法（器＝語りの一部の先例）

- **Tunic**：ゲーム内説明書＝物理的冊子のファクシミリ（頁は拾って増える・挿絵主体・読めない文字でも「構成」が読める）。本作の拾い人の手記・欠頁表示の直接の系譜
- **Pentiment**：書体そのものが人物・時代を語る（書体差＝語り形式差のデザイン言語化——48/02 §4.1「観る層」の系譜）
- **Heaven's Vault**：古代文字の部分解読 UI（推測語の差し込み）——本作はゲーム内に解読器を置かない（48/04：翻訳 UI 禁止）が、「対訳断片の照合」発見 UI の系譜
- **Outer Wilds**：ログは船のログで再読可能（拾った情報が集約器でいつでも読み返せる——読み返し規則の系譜）
- **Elden Ring / FromSoft**：アイテム説明＝短い頁＋フレーバーテキスト末尾配置（説明→物語の順序構造——26 §3.2「行為と物で語る」と同型）
- **Book of Travels / 文書回収型 RPG**：断片＝紙・封・便箋の器差分で「誰が書いたか」が先に伝わる（48/02 の形式別装丁と同系譜）

### 2.3 リズム・拍子キューの UI 作法（03 劇場の二次補助）

- **Hi-Fi RUSH**：全世界が拍で動く（UI なしでも拍が読める——一次＝世界の動き、本作の見得・提灯・幕と同型）
- **Cadence of Hyrule / Crypt of the NecroDancer**：画面下の拍バー＝拍の到来を可視化する**二次表示**（世界側が一次）。本作の拍子 UI はこの「二次補助」ポジション（U4-#8 承認済み）——キュー間隔 3.0 秒・窓 ±0.35〜±0.40 秒（38/03 §4.3 確定値を引用）
- **対象照準時の操作表示**：Tunic/Zelda 式の「照準を合わせた時だけ出る最小表示」——「坐る」ヒントの形（U4-#1/U2-C 承認済み：環境誘導一次・UI 二次フォールバック）

### 2.4 テキスト表示時間・読み上げの間の標準

- **字幕ガイドライン**：映像系の読み速度基準——大人向けで概ね 20 字/秒（英字 cps）、子供・全年齢向けは更に遅く（BBC/Netflix 系基準の系譜）。ゲーム本文の最低表示時間は「基本時間＋字数×係数」の式が一般的
- **ビジュアルノベル/ADV**：日本語の快適読了速度は概ね 10〜20 字/秒。強制送りでない器（自分で頁をめくる型）では最低表示時間は「頁が開いてから閉じ操作が効くまでの時間」として設計し、**閉じて再開可能（K3）を構造の担保**とする
- **FromSoft 系の拾得表示**：短い説明文＋数秒の保持——「読み上げの間」はストーリー文書に対しては長め、UI 通知には短めの二段階が実務
- **本作への設計指針**：読み上げの間の**確定値は本書が持つ**（26 §8・48/02 U2-R-5 の委譲どおり）——式の形「基本時間＋1文字あたり時間＋上限」を提案し、全年齢で読み切れる遅めの値を推奨案とする（要承認へ）

### 2.5 ダイエジェティック・最小 HUD 哲学

- **Dead Space / Metroid Prime**：HUD を世界内に溶かす（本作では「装置は二次」の原則と一致——没腐コンパスはノミ連動の器、HUD 矢印・クエストマーカーは禁止＝48/04 §4 不可表）
- **Ghost of Tsushima の風 / Zelda の最小 HUD**：一次は世界、UI は最小。本作の導線体系と同型（45/01）
- **Journey の操作開示**：説明テキストなしで操作を教える（全年齢基準——45/04 §2.1 七つの身体動詞と同型。「坐る」ヒントもこの系譜の最小表示）

### 2.6 アクセシビリティ基準（UI 側が満たすもの）

- **XAG（docs/39 §2 集約済み）**：XAG 103（重要情報の複数感覚化）・106（独自音響の字幕名）・テキスト可読性・色のみ依存禁止——45/04 §3.2 必須チャネル表が正典側の運用形
- **バニラ a11y 機能**：テキスト読み上げ・字幕・テキスト不透明度/背景・オートジャンプ等——MOD 側の独自設定は**コンフィグで追加**する方針（U4-11：専用配信モード画面は作らない）
- **45/04 の確定規則（UI 側の直接義務）**：M-2 個別層＝由来札のみ・P-2 かすれた項の存在常時表示・C-1 色のみ依存禁止・A-2 敵資源判別＝運動 2 値・H-1 音に依存しない可視化
- **Issue #34 との境界**：演出強度・スキップ・各種表示の ON/OFF の項目表は本書で**定義**し、画面構成・実装優先度は #34 へ手渡し

### 2.7 配信視点の UI 要件

- **30 秒基準**（docs/17 §3）：視聴者が画面だけで状況を読める強度——重要表示は配信解像度で読める大きさ・コントラスト
- **演出抑制＝コンフィグ**（U4-11 承認済み）：演出強度・スキップ可否はグローバルコンフィグ——専用画面は作らない
- **綴じ画面＝配信の山場**：結末綴じ画面は「最大の演出面」（20 §6）——コメントが沸く形（三択の視認性・かすれた項の存在）を設計要件に入れる

## 4. 設計原則（P-UI——制作の共通原則）

| # | 原則 | 意味 |
|---|---|---|
| P-UI-01 | **器は語りの一部** | 全 UI は「書物・頁・綴じ目」モチーフの統一言語で造る（docs/20 §2）。例外は docs/48/04 法典の裁定表どおり |
| P-UI-02 | **読み返せる** | 読み損ねを構造で潰す——全ての読み物は再開・再読可能（K3 の拡張原則） |
| P-UI-03 | **バニラの器への翻訳** | 新規画面・新規操作を増やさない。全演出は書物 UI・アイテム・暗転・パーティクル・音・フォントの器に翻訳する |
| P-UI-04 | **三層の読み** | 観る層（装丁・挿絵）／読む層（本文）／聞く層（読み音・間）——形式差は三層それぞれに仕様を持つ（48/02 §4.1） |
| P-UI-05 | **実装形を明記** | 全画面・全表示に「Patchouli 標準頁／自前 Screen／バニラ器（HUD 層・字幕・ツールチップ・Title 等）」の実装形を必ず付ける |
| P-UI-06 | **「場合による」は置かない** | 項目別に可/不可・一次/二次・共有/個別を白黒明記する |
| P-UI-07 | **多重化は設計要件** | 重要情報の必須チャネル数（45/04 §3.2）を各表示仕様の欄に明記し、不足なら作り直す |
| P-UI-08 | **配信の画面** | 視聴者が画面だけで読める強度（大きさ・コントラスト・保持時間）を要件に入れる（docs/17 §3 30 秒基準） |
| P-UI-09 | **操作は増やさない・教えない** | 前提操作は七つの身体動詞＋既存入力のみ。ヒント UI は照準時フォールバック |
| P-UI-10 | **数値の権威は本書** | 読み上げの間・頁めくり速度・通知保持時間等の UI 時間値は本書が確定値を持ち、他書（26 §8・48/02）は引用する形へ揃える（委譲どおり） |
| P-UI-11 | **没腐の UI 語彙** | 欠け・かすれ・継ぎ目・折れ目を UI の形状言語として使う（審美の浸透——docs/20 §1） |
| P-UI-12 | **主題と UI の一致** | 「あるが読めない」（かすれた項・白紙の頁）は主題そのもの——UI が「拾う＝可読化」を体現する形を守る |
