# 61. 用語集 調査・設計基準（Issue #9 → docs/44_glossary.md）

> 本書は docs/44（用語集）を作るための**共通基準**——先行調査・絶対制約（G-GL）・設計原則（P-GL）・棚卸し必須項目（H）・組版テンプレを集約する。執筆・レビュー・検証の全エージェントは本書を物差しとする。

## 0. 目的と完了条件との対応

- **Issue #9 の完了条件**：`docs/44_glossary.md` の作成（The Understory 関連用語の日英統一——棄てられたものの国、没腐、拾得鍛錬、落慮王、ノミ等）
- **本書の役割**：用語集が「正典の再定義の書」にならないよう、収録基準・欄構成・引用規則・登録運用を先に固定する
- **用語集の位置づけ（設計判断の骨格）**：用語集＝**名前（用語・読み・英語名・識別子）の唯一の台帳**。概念の定義・数値・仕様の正本は各正典書に残し、用語集は「どの正典節が権威か」の索引に徹する（TBX の termEntry 型——概念ごとに preferredTerm/admittedTerm/定義出典を束ねる構造を採用）

## 1. 先行調査

### 1.1 用語台帳（termbase）の標準構造

TBX（ISO 30042:2019／TermBase eXchange）・CAT ツールの用語集テンプレートの共通構造：

- **概念（concept）単位のエントリ**——1エントリ＝1概念。同じ概念を指す複数の表記は別エントリにせず、1エントリ内に preferred/admitted/deprecated の**格付け**で束ねる
- **必須欄**：用語（term）・定義（definition）・出典（source）・状態（status：preferred/admitted/deprecated）
- **言語層（langSet）**：言語ごとに term＋定義を持つ——日本語原語＋英語対訳の2層
- **運用**：「新規語の登録手順」と「改名・廃止の手順」を台帳自身が持つ（登録なしの表現が増殖するのを防ぐ）

本プロジェクトへの適用：用語集エントリは「用語｜読み｜英語名/識別子｜定義の正本（doc節参照）｜状態｜異表記・備考」を標準形とする。定義本文は正典節の引用または要旨＋節参照とし、数値・仕様は再掲しない。

### 1.2 ゲーム内テキスト・翻訳キーの作法（Minecraft MOD の文脈）

- **lang キー規則**：Minecraft の翻訳キーは `category.modid.name` の snake_case（例 `item.understory.xxx`・`subtitles.understory.<領域>.<主体>.<動作>`——docs/18 §5.6・docs/19 §3.1 で確立済み）。翻訳キーの命名根拠＝英語名の台帳が必要
- **音名 ID**：SoundEvent は `understory.<領域>.<主体>.<動作>` のドット区切り（docs/19 §3.1 が唯一の台帳）
- **内部識別子**：N-ITEM/N-DEV/N-GEAR/N-ECO 等の正典採番体系（docs/38 系）——名前の正本は数値表側、用語集は索引として突合する
- **読み仮名**：固有名詞の読みは配信素材（実況・読み上げ速度カード）で必須情報——非自明な読み（没腐＝ぼっぷ等）は全件明示

### 1.3 本リポジトリの用語状況（前提観測）

- 正典は約60ファイル——世界観語・システム語・工程語・識別子が混在し、定義は各書に分散
- 独立検証で「表記ゆれ」が毎回検出される現状がある（例：月の中継点/月中継点、名前の揺れ、数値の転記ずれ）
- 英語名の明示は限定的（The Understory・anomaly 等）——Phase 4 英語版（42-U2-Q1・43-U3-Q7 承認済み）の対訳種表が未整備
- 工程語は設計書群の中で自生している（垂直スライス・検証3層・スライス外台帳・段・要承認等）——docs/40 §9 から新語登録の手渡し済み

## 2. 絶対制約（G-GL-01〜12）

| ID | 制約 |
|---|---|
| G-GL-01 | **引用のみ**：用語集は定義・数値・仕様を**再定義しない**。定義欄は正典節への参照（`docs/NN §x.y`）＋必要最小限の要旨のみ。値が要るものは「正本節」を指す |
| G-GL-02 | **命名の権威は正典側**：正典で確定した名・ID・キーを用語集側で変更しない。改名・統一・英語名の新規付与は全て**要承認**（本書 §4 H-07 の衝突検出も同扱い） |
| G-GL-03 | **日本語が原語**：見出し・語句・備考は日本語。英語名列は「Phase 4 対訳の登録欄」として、正典に既存の英語名のみ収録——**未定の英語名を執筆時に新造しない**（新造候補は要承認として挙げる） |
| G-GL-04 | **層別**：世界観語・システム語・工程語・識別子は別節に分け、混在させない（読者層と消費先が違う） |
| G-GL-05 | **識別子は索引化のみ**：N-XXX 番号・`understory.*` 音名・翻訳キー・advancement 名・config キー・セーブキーは、採番・命名規則の正本（docs/38・19・18・34 系）を指す索引に留める。個別 ID の全列挙はしない（台帳の二重管理を防ぐ） |
| G-GL-06 | **収録基準**：正典で命名・定義済みの語に限る。修辞上の一度きりの言い回し・汎用語は収録しない（線引きは P-GL-04） |
| G-GL-07 | **状態欄**：`確定`（承認済み）/`暫定`（正典で暫定表記）/`未命名`（英語名等が未定）/`異表記あり`（衝突検出済み）の4値 |
| G-GL-08 | **Phase 0 制約**：lang ファイル・実装コードは生成しない。命名規則・登録運用の設計のみ |
| G-GL-09 | **読み仮名**：非自明な読みを持つ語は全件に読みを付す（配信素材の源泉——D-7 系）。自明な語は省略可だが、漢字複合語・造語は原則付ける |
| G-GL-10 | **要承認の集約**：衝突・改名候補・新規英語名・未命名語の扱いは `44-U{n}-Q{m}` の ID で集約し、推奨案＋書き戻し先を必須とする |
| G-GL-11 | **権威侵害の禁止**：docs/42 リスク台帳・docs/43 リリース計画等他書の管理物を用語集側で再管理しない。関係は「参照」で示す |
| G-GL-12 | **登録運用を書に含める**：用語集は静的リストでなく「今後の新語登録・改名・廃止の手順」を内蔵する（Issue 手渡し→登録の流れを § 登録運用で定義） |

## 3. 設計原則（P-GL-01〜10）

| ID | 原則 |
|---|---|
| P-GL-01 | **1概念1エントリ**：同一概念の別表記は主エントリの「異表記」欄に束ね、別行にしない（TBX termEntry 型） |
| P-GL-02 | **二経路の索引**：分類別（世界観/システム/工程/識別子）の本文表＋五十音順の総索引を併設。読者が「カテゴリから探す」「音から探す」両経路を持つ |
| P-GL-03 | **正本ポインタの必須化**：全エントリに定義の正本節（`docs/NN §x.y`）を付ける——正本のない語は収録しない（＝用語集が勝手に権威にならない） |
| P-GL-04 | **収録線引き**：「正典で用語として定義または固有名称として確立した語」を収録。判定基準：①見出し・太字・「〜とは」で名付けられている、②複数の正典節から参照されている、③実装・素材・配信で名指しが要る。どれも満たさない修辞句は除外 |
| P-GL-05 | **状態の格付け**：正典の承認状態を用語集の状態欄へ機械的に写す（承認済み＝確定、暫定表記＝暫定、英語名なし＝未命名） |
| P-GL-06 | **英語名は登録制**：未定の英語名は「未命名」として穴を可視化する。勝手な新造を防ぎ、Phase 4 の翻訳工程への入力リストにする |
| P-GL-07 | **異表記は消さず束ねる**：正典に実在する異表記（用字ゆれ・旧称・別称）は異表記欄に記録し、検索時に主語へ誘導する。統一そのものはユーザーの承認事項 |
| P-GL-08 | **配信者視点**：読み仮名・呼称の略称は実況で言いやすさに資する情報として保持（D-7 の配信素材源泉） |
| P-GL-09 | **衝突の可視化**：同名異物・一概念複数名・正典間の定義ずれは、黙って修正せず「衝突」として検出し要承認に挙げる——用語集は発見した矛盾の消去装置ではなく報告装置 |
| P-GL-10 | **工程語は内部層**：工程語（垂直スライス・要承認・段・ゲート等）はプレイヤー/配信者に見えない開発内部語として分離する——公開用語と混ぜない |

## 5. 組版テンプレート（docs/44_glossary.md の必須節構成）

```
# 44_glossary.md — The Understory 用語集

§0 位置づけ
  0.1 本書の役割（名前の唯一台帳——定義の正本は各正典。引用のみ）
  0.2 収録基準と除外基準（P-GL-04）
  0.3 状態欄の読み方（確定/暫定/未命名/異表記あり——P-GL-05）
  0.4 使い方（設計書執筆時・実装命名時・翻訳時・配信素材作成時）

§1 世界観語（原語＋読み＋英語名＋正本節＋状態＋異表記）
  ――棄てられたものの国・没腐・拾得鍛錬・落慮王・ノミ・拾い人の村・縁の地・異物・ゴミ箱・返礼・没の由来品・残影・写し・響界・物語の終わり 等

§2 システム語（同上の欄構成）
  ――器スロット・段位・個人没腐度・没腐遺留物・拾い直し制・環礁・疑似ループ・イベント台帳・解禁チャネル・迷子・配信モード 等

§3 工程語（内部語として分離）
  ――垂直スライス・検証3層・スライス外台帳・完成品質・量産可否・先行ゲート・段間ゲート・解禁判定・巻き戻し・段 A〜F・工程 8-A〜N・要承認 等

§4 識別子・命名規則の索引
  4.1 ID 接頭辞体系（N-ITEM/N-DEV/N-GEAR/N-ECO——正本＝docs/38 系）
  4.2 音名・字幕キー（`understory.<領域>.<主体>.<動作>`・`subtitles.*`——正本＝docs/19 §3.1・docs/18 §5.6）
  4.3 advancement・config・セーブキー・lang キー規則（正本節への索引）
  4.4 命名の新規採番ルール（命名が必要になったときの手続き）

§5 英語名台帳（Phase 4 対訳の種表）
  ――確定済み英語名／未命名リスト（未命名は要承認候補として明示）

§6 五十音順総索引
  ――全収録語を五十音順に（主語・異表記・別称の誘導込み）

§7 登録運用
  ――新語の登録手順（Issue 手渡し→用語集登録→正本節指定）・改名/廃止の手順（要承認必須）・衝突検出時の流れ

§8 未決・要承認集約（44-U{n}-Q{m}——唯一の台帳・推奨案・書き戻し先・統合元）

§9 他 Issue への手渡し一覧
```
