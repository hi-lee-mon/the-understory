# docs/29：Phase 0 整合性レビュー R2（全設計書の横断監査）

> docs/06（第1ラウンド）に続く第2ラウンド。観点：①一般的ベストプラクティス ②最初に決めた方針への整合 ③考慮漏れ ④ゲーム業界の開発設計基準 ⑤矛盾の有無。
> 分類：docs/00 §4 に従い blocker / major / minor。
> 2026-09-25 実施。**発見した矛盾の多くは本レビュー内で修正済み**（各項目に「→修正済み」を付記）。

---

## 1. 総評

全体の構造は健全：**設計→レビュー→Issue管理**の流れは AGENTS.md 通りに運用されており、ADR・章構造・垂直スライス方針・層構造（表層/深読み）・分量予算（docs/26 §6）といった業界標準の武器は揃っている。大きな構造的破綻はなく、戻り作業リスクは小さい。

**主な問題は「横の繋がり」**——後から加わった設計（ゴミ箱機構・招待状ゲート・人物設計）が先に書かれた文書に一部未反映で、古い参照・用語揺れ・機構の齟齬が残っていた。本レビューで全て修正した。

## 3. 考慮漏れ（未設計・要Issue化の候補）

現行Issue（#2-#33）で追えていない領域：

| # | 領域 | 内容 | 推奨の置き場 |
|---|---|---|---|
| G1 | **アクセシビリティ・コンフィグ設計** | 色覚対応（色を取り戻す演出の識別性）、文字量・フォント可読性、難度オプション、演出の抑制（点滅/ノイズ）、「読む」層の文字サイズ——業界標準では設計段階で検討対象 | **新Issue提案**（またはIssue #16へ追加） |
| G2 | **招待状ゲートの厳密仕様** | 発火条件・タイミング・異物経由で先に来た場合の分岐（招待状は来るか/来ないか）、マルチでの誰宛か | Issue #16（システム厳密仕様）に追加済み想定 |
| G3 | **没腐の定量化仕様** | 定義（docs/24 §4.3）は固まったが、「どれくらいで没腐するか・どう回復するか・放置で増えるか（docs/15 §4）」の数値・条件が未設計 | Issue #16 へ |
| G4 | **結末選択の結果差異** | 「書き換える/見届ける」の報酬差・世界変化の具体（docs/12 §4 未決のまま） | Issue #14（章詳細）で扱う |
| G5 | **新規プレイヤーのオンボーディング再確認** | 「ゴミ箱を作る」までの導線（レシピの見つけ方）は暗黙——最初の1歩の導線仕様が欲しい | Issue #31（非言語導線）または #16 |
| G6 | **英訳・ローカライズの文体ポリシー** | 「かすれた・欠けた・継がれた」（docs/26 §4）の英語等価規範は未定 | Issue #9（用語集）へ |
| G7 | **マルチの結末決裁細則** | ADR-0004 で方針は決定済みだが「先着か多数決か・誰が綴じたかの表示範囲」の細目 | Issue #16（既に記載済み） |

これらは全て既存Issueの範囲に収まるか新Issue1件で足りる粒度であり、**構造的な欠落ではない**。
