## 0. 位置づけ

### 0.1 目的

「誰が・どんな状態でも遊べるか」の**到達側の最終仕様**を確定する。本作の核心演出——「色を取り戻す」転調・かすれた文体・没腐の歪み・読み合い戦闘・音を一次に据える章——は視覚・聴覚・読解・反応の特性に深く依存しており、a11y はオプションでなく**表現の届け先そのものの設計**である（docs/29 §3-G1）。

### 0.2 三層構造（本書の骨格）

| 層 | 内容 | 正本 |
|---|---|---|
| **設計担保層** | コンフィグの有無に依らず既定で成立する多重化・代替・配色規則 | docs/45/04 §2〜§5（本書は再定義しない・引用のみ） |
| **コンフィグ層** | 強度を変えられる上乗せ項目——本書 §2 が仕様化の正本 | 項目の権威＝docs/18 §6.1・45/04 §6（項目の新設・削除・既定値変更は全て要承認） |
| **検証層** | 「既定でも不利にならない」の監査・実機確認 | docs/40 §5.2.3・Issue #6（本書 §6 で手渡し） |

### 0.3 適用範囲

- **扱うもの**：a11y 方針（特性別の担保）・コンフィグ項目の仕様（キー・型・スコープ・同期・既定値・範囲）・設定画面の置き場・字幕名台帳の登録運用・未着地数値の着地
- **扱わないもの**：導線の多重化規則そのもの（45/04 §3）、UI の実装細部（docs/18）、字幕名の個別名付け（docs/19 §3.6 が台帳の権威）
- **正典を変更しない**：矛盾・未定義は §5 の要承認に集約

## 1. アクセシビリティ方針

### 1.1 特性別の担保表（設計担保層＋コンフィグ層の対応マップ）

| 特性 | 設計担保層（既定で成立——45/04 規則） | コンフィグ層（§2 の上乗せ） |
|---|---|---|
| **色覚特性**（protan/deutan/tritan） | 色のみ依存の全面禁止（C-1）・完了表示＝点灯個数＋動き＋音の三重信号（C-2）・パレットは明度/彩度差＋点灯/非点灯で設計（C-3）・シェーダー非依存の必須チャネル（C-5） | #4 コントラスト強化（明度差・輪郭補強の上乗せ）。**配色3型シミュレーション実機確認は検証層へ**（45/04 §7-#7→Issue #6/#34→§6 手渡し済み） |
| **聴覚特性** | 音だけに依存しない（H-1）・テレグラフは視覚常設（H-2）・拍子は視覚合図（H-3）・独自 SE 全件に字幕名（H-4） | #1 字幕粒度・#6 聴覚補助強度（響界波紋・字幕・粒子の強化） |
| **視認特性**（小文字・低視力） | 読み物は背景との明度差を担保（C-4）・視認強度の下限（配信視聴者が読める強度——X-4） | #2 文字サイズ段階（§4.1）・#4 コントラスト強化。字幕背景不透明度＝**バニラ項目へ委譲**（§1.2 表） |
| **読解特性**（読み速度） | 進行必須情報を文字に置かない層構造（45/04 §1.2——読まなくても遊べる）・綴じ画面は閉じて再開可（K3）・読み上げの間＝18 §2.6 確定式 | #10 テキスト速度3段（τ 倍率）・#2 表示時間連動 |
| **運動・反応特性** | テレグラフの予備床（単発≥1.5s・AoE≥2.0s——38/03 §2.3）・即死級は 3 系統の完全予告（05 切ない高音） | #5 読み合い支援（応答窓拡大——§4.2 の分割設計）・SERVER 難度係数（§4.6 新規——要承認） |
| **光過敏特性** | 明滅は注意喚起の一拍限定・連続閃光禁止（C-6——WCAG 2.3.1「3回/秒」閾値に設計側で適合） | #3 点滅・ノイズ抑制。稲妻フラッシュ・暗闇脈動は**バニラ項目へ委譲** |
| **認知特性**（迷子・複雑性） | 一次導線は環境（B-1）・迷子判定の定量閾値 90 秒（docs/13 §1）・リカバリ段階（環境→装置→ノミ→最終段） | 迷子補助感度（§4.3——最終段の早発化・要承認）。難易度自体は「外側の難しさ」でなく説明なし完走の担保として扱う |
| **操作特性**（文字入力） | 名付け・手紙は進行必須でない（補助層の行為） | 文字入力の代替経路——候補選択 UI（§4.7——要承認） |
| **配信者・視聴者** | 視聴者が読める強度（X-4・30 秒基準）・幕間に情報を置かない | #7 配信モード/演出抑制（暗転のみ短縮・多重化は削らない） |

### 1.2 バニラ項目への委譲（二重実装の禁止——G-AC-05）

| バニラの Accessibility Settings | 本作の扱い |
|---|---|
| 字幕 ON/OFF（Closed Captions） | 本作の字幕は全てバニラ字幕パイプライン上に置く——OFF 時は独自 SE 字幕も出ない（字幕名粒度 #1 は「登録対象の範囲」であり、バニラ OFF を上書きしない） |
| テキスト背景・背景不透明度 | 委譲——独自項目を設けない |
| 通知時間（Notification Time） | 委譲——拾得・進行通知の保持はバニラ通知時間に従属（18-U3-Q3：通知は着弾時1回・物は常設の設計と整合） |
| 稲妻フラッシュ非表示・Darkness Pulsing | 委譲——MOD 独自演出の点滅のみ #3 が対象 |
| ナレーター | 対象外（ゲーム内書物はナレーターの読み上げ対象外——読み上げの間・文字サイズ・閉じて再開可で担保） |
| オートジャンプ・キー割当 | 本作は新規キー入力を持たない（45/04 A-0——七つの身体動詞はバニラ操作の写像） |

### 1.3 合格条件

**既定値（全コンフィグ OFF/標準）で、全プレイヤーが情報面で不利にならないこと**（45/04 §6 の合格条件を継承）。コンフィグは上乗せであり、既定が不十分な項目は本書に置かず設計側（45/04）で閉じる——この逆方向の発見（既定で不十分な箇所）は設計側の blocker として docs/42 リスク台帳に記録する。

## 3. コンフィグ画面の置き場（§3＝H-11 の着地）

### 3.1 方針

- **ファイルが正本**：`understory-*.toml` が値の権威（modpack 収録条件③の充足形——外部編集可能なテキスト設定）。
- **a11y 項目はゲーム内で変えられる**：CLIENT 項目は**独自設定画面**を設け、.toml 編集を必須にしない（P-AC-6——a11y はファイルを編集できないプレイヤーこそが必要とする）。NeoForge 1.21.1 には標準の MOD コンフィグ GUI がないため、**独自 Screen（書物器スキン族——docs/18 の器言語に従う）**を設ける。
- **到達導線**：Mods 一覧 → The Understory → Config ボタン（NeoForge の `IConfigScreenFactory` 拡張点）＋ゲーム内オプション画面には注入しない（バニラ画面を改変しない原則——45/04 G3 と同線）。
- **SERVER 項目は .toml のみ**：難度・迷子補助等は管理側の値——設定画面には表示しない（一般プレイヤーの変更対象でない）。

### 3.2 タブ構成（独自設定画面）

| タブ | 収録項目 | 書物器の装丁イメージ |
|---|---|---|
| **見え方** | #1 字幕粒度・#2 サイズ・#10 読み上げの間・#4 コントラスト・#9 由来表示 | 「読む層」の頁——装丁＝便箋罫線 |
| **演出・音** | #3 点滅抑制・#6 聴覚補助・#7 配信モード | 「演出」の頁——装丁＝演目表 |
| **あそびやすさ** | #5a 応答窓・#8 段階名表示 | 「補助」の頁——装丁＝栞 |

各項目の表示は**項目名＋一行説明＋選択肢**——説明文は日本語正典（「何が変わるか・既定はどれか」を平易に書く。内部キー名・係数値は画面に出さない）。

## 4. 未着地項目の着地（H-02〜H-10 の確定）

### 4.1 #10 テキスト速度の倍率（権威＝18 §2.6.2 従属——正典は段階名のみ指定で倍率値は未定義）

- 確定式：`T = T_base(1.2s) + 字数 × τ(0.12s)`・上限 10 秒・頁めくり 0.30s/頁・連続 0.18s/頁（18-U1-Q1/Q2 承認済み——式は不変）
- **段階＝τ の倍率**（式を変えない——18 §6.1 #10 の範囲指定どおり）：**`slow`=×1.5・`standard`=×1.0・`fast`=×0.7** を推奨値とする（**要承認 63-U1-Q1**）。頁めくり速度も同倍率で連動（slow 時 0.45s/頁——18 §2.6.3 の「緩」値と一致させる）

### 4.2 #5 読み合い支援の分割設計（H-02——#5 の拡大係数実数値）

**分割の理由**：応答窓（プレイヤーの入力受付の広さ）は個人の特性で個別に効かせたい補助。テレグラフの予告時間（ボスの見得の長さ）は**世界側の共有事象**——個別に延ばすと「同じボスが人によって違う速さで見える」となり、共有層の一貫性とマルチの読み合いが割れる。

- **CLIENT 側 `assist.response_window_scale`**（既定 `off`）：ON 時、**応答窓を ×1.5**（±0.35〜0.40s → 概算 ±0.52〜0.60s）に拡大する（**推奨値＝要承認 63-U1-Q2**）。効く範囲＝入力受付のみ——世界の時間は変えない。**マルチでの扱い**：per-player の補助（応答窓は自分の入力受付にのみ効く）であり他者の世界・難度を変えないため、バニラのアクセシビリティ設定と同じく個人の選択として許容する。サーバー側で一律に揃えたい運営は S-1（テレグラフ延長）で世界側を調整する設計とする
- **SERVER 側 `assist.telegraph_scale`**（既定 `1.0`）：テレグラフ予告時間を 1.0〜1.5 倍に延長する**世界側の別項目**として新設（**要承認 63-U1-Q4**——新規項目のため）。サーバー全体・ワールド単位で全員に同じ延長が効く（運営・modpack 向けの難度運用手段としても兼ねる）
- **係数の根拠**：×1.5 は予備床（単発 1.5s→2.25s・AoE 2.0s→3.0s）が読み取り負荷を下げつつ演出の体裁を保つ範囲。±0.52s の応答窓は拍子キュー間隔 3.0s の約 1/6 で、リズムの崩壊を起こさない上限の読み

### 4.3 迷子最終段の発火時間閾値（H-03——45/04 §7-#5・41-U4-Q6 承認の着地先）

- **迷子判定**（既確定——docs/13 §1）：一次導線の勾配圏外で 90 秒滞留、または未消化の淀み地点が残る状態での同一地点周回
- **リカバリ段階**（既確定）：環境再提示 → 装置（没腐コンパス） → 最小語り（ノミ） → **最終段の明示増強**
- **最終段の発火閾値（推奨値——要承認 63-U2-Q1）**：**迷子判定の継続状態が累計 270 秒を超過、または同一区画 ID で迷子判定が 2 回発火**した時点で最終段（ノミ示唆の段階的強化＋コンパス指しの一時明示化）へ移行する
  - 根拠：各段階を概ね 90 秒刻みで積むと 270 秒＝3 段×90 秒の整理値に一致し、「同一地点の二度目の迷子＝導線不合格」（docs/40 §5.2.1 E-5）のテレメトリ判定と同一の区画基準を共有できる
  - `navigation.lost_assist_level=enhanced`（SERVER・S-5）時は最終段閾値を **180 秒**に早める（迷子補助を早く効かせたい運営向け）
- **telemetry との接続**：docs/41 §5 の `navigation.lost.recover` の `via` 値に `final_stage` が既にあり、本閾値はその発火条件の確定値——docs/41 は「確定値を参照」記述のまま変更なし（41-U4-Q6 どおり）

### 4.4 #7 配信モードの短縮係数（H-04——確定済みの仕様化）

- **係数＝0.6（確定——57-U2-Q10 承認済み）**：`stream.effect_compression=shortened` 時、暗転・フェーズ転換の表示時間を ×0.6（0.8s/1.2s→概算 0.5s/0.7s——18 §6.1 #7 の概算値をそのまま規格値とする）。**多重化は削らない**（40-Q20・45/04 §6-#7）
- 適用範囲は「幕の暗転・フェーズ転換の『間』・長いシーン」に限定（45/04 §6-#7）——演出の短縮は暗転の長さのみ

### 4.5 ダッキング量・復帰窓（H-05——係留の継承）

- **暫定・係留継続**：docs/57 H-21 の合格ラインは「機構成立＋発火条件の一致」で値を問わない（57-U4-Q7——PoC 実測後に確定値を提案する運用）。本書はクライアント側キー `audio.ducking_amount_db`（暫定推奨 -8dB）・`audio.ducking_release_ms`（暫定推奨 1500ms）を**暫定登録**として記録し、確定値は PoC 後の別承認に委ねる（**63-U2-Q2**——係留継承の記録確認）
- 対象＝楽曲バスの一時的な音量低下（docs/19 §6.1——幕切れ・結末・救出等の重要イベント時）

### 4.6 難度オプションの着地（H-09——Issue #34 本文「ボス難度・没腐ペナルティの調整可否」）

- **方針**：個別技の弱体化はしない（45/04 §7-#6——即死級技は予告多重化で担保済み）。難度の調整は**係数の系**として提供——§2.2 の S-2/S-3/S-4（ボス HP・与ダメ・没腐度上昇率の 3 係数）を新設
- 個人特性による救済は S 系ではなく #5a（応答窓）が担う（個別の反応特性は個人単位で効かせる——§4.2 の分割理由どおり）
- **要承認 63-U2-Q3**（S-2/S-3/S-4 の新規項目追加・範囲値）

### 4.7 文字入力の代替経路（H-10——Issue #34 本文「操作の代替」）

- **対象**：名付けの台（没素材への命名）・戦闘中命名（2 秒チャネル）・名札命名（K4 ノミへの最後の名付け——バニラ名札 UI）・（該当あれば）手紙記入
- **設計案（推奨——要承認 63-U2-Q4）**：全ての自由入力点に**「候補から選ぶ」経路を併設**する——
  - 名付けの台・名札命名：由来に即した定型名の候補 3〜5 件を提示＋「自分で書く」選択肢（自由記述は残す）
  - 戦闘中命名：候補の巡回選択（2 秒チャネル内で選択肢を切り替える操作形——実装細部は Issue #3 領域として手渡し）
  - 手紙・書き込み系がプレイヤー自由入力を持つ場合は同型の定型文選択を適用
- **進行保証**：名付け・手紙は進行必須でない補助層の行為——代替経路は「書かなくても進める」保証を壊さない範囲に限定（45/04 §1.2 の層構造と整合）

### 4.8 予告頁の環境側二重化の確認（H-07——docs/16 §7.5 手渡しへの回答）

- **確認済み**：docs/16 §3.6 の「朧な光の気配」は C1（光）＋C5（方角・淀み濃度勾配）の環境一次導線として設計済みであり、45/04 規則 P-3（予告頁が語る方角と環境側の一致）・多重化表の要件を満たす。a11y・演出規格側との整合に齟齬なし——本節をもって docs/16 §7.5 の確認依頼への回答とする
