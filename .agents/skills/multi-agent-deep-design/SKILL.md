# マルチエージェント深設計（multi-agent deep design）

複数の成果物（章・機能・文書）を持つ大きな設計タスクを、**単独作業では埋もれる矛盾まで掬い上げる**ための反復型フレームワーク。核心は「制作とレビューを別エージェントに分ける」「レビューは必ず深い思考」「横断レビューと独立検証の二段構え」「指摘が尽きるまで止まらない」。

## いつ使うか

- 成果物が複数のユニット（章・モジュール・ページ等）に分かれ、**相互整合**が品質を左右する
- ユーザーが「深い思考」「指摘がなくなるまで繰り返し」を要求している
- 机上設計・長文仕様・物語/世界観設計など、テストで検証できない成果物

小さい単一ドキュメントや、即時のバグ修正には使わない（過剰）。

## 工程

### 1. 調査フェーズ（先行・必須）
制作の前に、対象領域の**ベストプラクティス・成功作の統計・学術研究**を調査し、1本の「基準ドキュメント」に集約する。
- 目的：全エージェントが同じ物差しで制作・判定するための**共通基準**を作る
- 必ず**組版テンプレート**（成果物の必須節構成）まで落とす——例：docs/33 §7 の10節テンプレ
- web 検索だけでなく、自分たちの正典（既存 docs/ADR）も基準に含める

### 2. ユニット別制作→レビュー→改訂ループ
成果物ごとに独立したエージェントを立て、以下を**受理（accepted=true）まで繰り返す**：
1. **制作エージェント**：基準ドキュメント＋正典を読ませ、テンプレに従って執筆
2. **レビューエージェント**（深い思考）：別セッションでレビュー。指摘は **blocker / major / minor** の3段分類、各指摘に「根拠箇所の引用」と「修正案」を必須化
3. **改訂エージェント**：指摘の全件処理（棄却する指摘にも理由を要求）

ループは `workflows/` の Python スクリプトでオーケストレートし、各エージェントの成果は structured_output（`plot_md` / `findings` / `accepted` 等）で機械可読に受け渡す。

### 3. 横断レビュー（ユニットを跨ぐ整合）
全ユニット受理後に、**観点別の横断レビューエージェント**を立てる：
- 例：物語整合系＋システム整合系の2系統（用語統一・章間の設定矛盾・伏線の受け渡し・共有リソースの配分）
- ユニット内レビューでは見えない「間」の問題だけを狙わせる

### 4. 全指摘の反映
検出された指摘を成果物へ全件反映する。正典（別ドキュメント）に触れる変更は**直接書き換えず「要ユーザー承認」として一覧化**する（面白さの根幹の決定権はユーザー）。

### 5. 独立検証パス（必須・反復の終了条件）
修正後、**新しいエージェント**に指摘一覧を渡し「各指摘が本当に解消されたか＋修正が新たな矛盾を生んでいないか」を検証させる。
- 証拠は引用ベースで要求（grep の実記述を根拠に ok/fail）
- **半修正**（変更履歴は修正済みを謳うが本文に旧表現が残存）はよくある失敗 —— 検証側に「履歴の宣言ではなく実記述を見ろ」と指示する
- accepted=true が出るまで 4→5 を繰り返す（Issue #14 では2巡目で受理）

### 6. 統合・引き継ぎ
- 索引ドキュメント（README）を作り、横断レビューで確定した**共通規則**と要承認事項を集約
- STATE.md / todo.md / 該当 Issue に進捗と**要承認リスト（推奨案つき・書き戻し先明記）**を残す
- コミット前に機密情報スキャン

## 運用ノウハウ（Issue #14 で実証）

- **セッション上限**：SWE-2 無料枠は同時8セッション（親含む）。完了済み子セッションは枠を占有し続ける → `devin_session_interact(action="terminate")` で都度終了（結果はジャーナルに記録済みで再実行されない）
- **429 が出たら**：バッチを小さく分けてリトライ（7ユニット → 4+3分割が安定）
- **停滞したエージェント**：`message_workflow_agent` で生存確認のポークを送ると再開することがある
- **成果の回収**：ワークフロー最終ログが途切れても、各セッションの `devin_session_interact(get)` から structured_output を個別回収できる（生テキストをファイルに退避してからパース）
- **検証エージェントは修正後のリモートを読む**：修正を push してから再検証を依頼する。差分だけ再検証させると安い

## レビュー品質のコツ

- レビューアには「正典の該当節を必ず開いて突き合わせろ」と明記する（記憶で判定させない）
- 分類基準を固定する：blocker＝正典と直接矛盾／major＝章間不整合・未回収の伏線・規則未定義／minor＝表記揺れ・参照ずれ
- 「指摘0件で受理」も正当な結果として許容する（無理に指摘をでっち上げさせない）
- 全員が同じ正典セットを読むこと——判断の分散を抑える最大の効果
